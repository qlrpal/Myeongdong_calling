## P1 — Rust WASAPI 프로브

목표: 장치별 실제 지원 주기·모드표, 캡처 전달과 출력 경로를 새 코드로 측정.

- [ ] 장치 열거와 `DeviceInfo` 수집 (공유 주기 4값, 독점 주기, RAW 지원, 드라이버)
  - 기본 형식 추가(2026-11-12, 읽기 전용 열거 1회): `devices` 표·CSV와 `loopback` 메타에 Windows 기본 형식을 기록한다. 측정에 쓰는 장치(수신 PC fifine·Realtek, 노트북 Realtek)는 기본·믹스 형식 모두 48kHz였다. 상세는 `DISCUSSION-LOG.md`.
- [ ] 캡처: 공유 / 공유+RAW / 독점, 이벤트 구동, `CaptureRecord` 기록
  - P1-b(2026-11-11, 내부 기록, 구성당 30초 1회, 지연 판정 아님): fifine 마이크는 공유 10ms/480프레임, 독점 3.00ms/144프레임으로 전달됐다. Realtek 마이크는 공유 최소 2.90ms, 독점 3.33ms/160프레임(최소 주기는 정렬 오류로 재시도). 노트북 마이크 배열은 공유 최소(64프레임)에서 프레임의 약 18.6%를 잃었고, 독점 최소(64프레임)에서는 그 손실이 없었다(3회, 1회에서 9프레임 위치 건너뜀 1건). 상세는 `DISCUSSION-LOG.md` "구현 중 확인한 사실과 검토 항목".
  - 공유+RAW(같은 조건): fifine 마이크는 RAW에서도 10ms/480프레임만 조회됐다. Realtek 마이크는 RAW에서 44.1kHz 믹스 형식, 기본 448 / 최소 128프레임(2.90ms). 노트북 마이크 배열은 공유 최소+RAW에서 위 손실이 거의 없었다(3회).
  - 정정: Realtek 마이크의 2.90ms·3.33ms·44.1kHz는 기본 형식이 44.1kHz로 설정돼 있던 때의 값이다. 48kHz로 바꾼 뒤에는 공유·RAW 최소 2.67ms/128프레임, 독점 2.67ms/128프레임(재시도 없음)이었다.
  - 위치/프레임 비율(2026-11-12, 내부 기록, 구성당 10초 1회): 캡처 요약에 누적 장치 위치 증가량 / 누적 패킷 프레임 수 비율과 Windows 기본 형식 레이트를 기록한다. 세 마이크 × 다섯 모드 중 비율이 1이 아닌 것은 노트북 마이크 배열의 공유 최소(1.20, 손실)와 공유 최소+RAW(0.998)였고, 기본 형식 레이트는 모두 48kHz였다. `DESIGN.md` 4.2 판정 단위는 P2에서 결정한다. 모드표는 `DISCUSSION-LOG.md`.
- [ ] 렌더: 공유 / 공유+RAW / 독점(기준용), `RenderRecord` 기록
  - P1-b(같은 조건, 무음 렌더): Realtek 헤드폰 공유 기본 10.00ms/480프레임, 공유 최소 2.67ms/128프레임, 독점 2.67ms/128프레임. 공유+RAW도 같은 주기였다(기본 480, 최소 128프레임).
- [ ] MMCSS 없음 / Audio / Pro Audio
  - 프로브 옵션 `--mmcss none|audio|pro-audio` 추가(2026-11-12, 내부 기록, 지연 판정 아님): 수신 PC 헤드폰 공유 최소 무음 렌더 30초(Pro Audio 2회, Audio 1회, 없음 1회)에서 깨어남 간격 P50 2.67ms / P99 2.69ms로 구분되지 않았다. 등록 직후 스레드 우선순위 값은 없음 0, Audio 13, Pro Audio 15였다. 부하 없는 조건의 1회씩이며, E6 판정(외부 합계, 마감 초과)은 리그가 필요하다. 상세는 `DISCUSSION-LOG.md`.
  - CPU 부하·노트북·독점 조건(2026-11-12, 내부 기록, E6 판정 아님, 무음 렌더 30초 구성당 1회): 모든 논리 CPU를 보통 우선순위로 100% 점유한 부하(`mdc-rig-load`)에서도 공유 구성의 세 값은 깨어남 간격으로 구분되지 않았다(수신 PC 공유 최소 P99 2.68~2.69ms, 노트북 공유 P99 10.30~10.31ms). 노트북 스피커 독점은 MMCSS 값과 무관하게 깨어남이 묶여서 왔다(부하 없음 P99 약 20ms, 부하 P99 약 75ms). 같은 노트북의 마이크 배열 독점 캡처에서는 그 몰림이 없었다(최대 2.8ms, 손실·불연속 플래그 0). 원인은 미확인 검토 항목으로 남긴다. 수신 PC 헤드폰 독점 최소(2026-11-13)는 부하에서 Audio·Pro Audio가 P99 2.68ms로 같았고, MMCSS 없음만 깨어남을 놓쳤다(P99 약 31ms, 깨어남 수 32~40%, 2회 재현). E6 판정은 외부 리그 뒤에 한다. 상세는 `DISCUSSION-LOG.md`.
- [ ] 로컬 캡처→렌더 직결 (PCM, 코덱 없음)
  - 1단계(2026-11-11, 공유·공유+RAW, 내부 기록, 조합당 30초 1회, 지연 판정 아님): Realtek 마이크→헤드폰은 링 수위 128프레임 고정, fifine→헤드폰은 128~576프레임, 모두 모자람·넘침 0. 렌더 깨어남마다 장치 버퍼 padding이 0이었다(끊김 여부 미확인). 독점 조합(2단계)과 외부 리그 지연 측정은 남았다.
  - 2단계(2026-11-11, 독점, 내부 기록, 30초 3회, 지연 판정 아님): fifine 독점(144프레임) → 헤드폰 독점(128프레임), 16비트. 링 수위 112~304프레임(P50 224), 넘침 0, 모자람은 3회 중 1회에서 16프레임 1건. 프라이밍 임계값 144와 288의 차이는 이 실행들로 가리지 못했다. 외부 리그 지연 측정은 남았다. 상세는 `DISCUSSION-LOG.md`.
- [x] 출력 장치 endpoint 효과(EFX) 등록 감지
  - 확인(2026-11-12, 읽기 전용 열거 1회): 노트북 Realtek 스피커에서 경고가 나왔고, 등록된 endpoint 효과는 DTS EFX APO와 Realtek EFX 두 개였다. 수신 PC 장치에는 경고가 없었다. 감지는 등록 여부만 본다. 활성 여부·지연 영향은 E2(외부 리그)에서 판정한다. 상세는 `DISCUSSION-LOG.md`.
- [ ] 같은 장치의 Realtek 드라이버 vs Microsoft HD Audio 드라이버 주기 비교 (사용자 확인 후)

## 실험 설계 합의 (R2로 닫힌 측정 쟁점)

판정은 모두 **외부 리그 합계 지연(재시작 단위) + 보존율**이 1차다. 실험을 시작하기 전에 `docs/experiments/`에 파일을 만들고 판정 기준을 먼저 적는다.

| # | 쟁점 | 방법 | 판정 기준 | 단계 |
|---|---|---|---|---|
| E1 | 공유 vs 독점 캡처 | 같은 장치, 재시작 반복. 내부 기록은 원인 분해용 | 외부 합계 차이. 내부 타임스탬프는 모드 간 비교에 쓰지 않음 | P1 |
| E2 | 출력 주기·RAW·향상 기능 | 입력 경로 고정, 출력 변수만 변경. 입력 주기·캡처 불연속 유지 확인 | 외부 합계 차이 = 출력 쪽 차이. 출력 단독 절대 지연은 분리하지 않음 | P1 |
| E3 | 코덱 4종 | 코덱 단독 임펄스 + 정렬 모델(`DESIGN.md` 8) + 외부 합계 | 외부 차이 ≈ 코덱 차이 + 정렬 차이면 분리 성공. 구현 복잡도·표준 호환성 손실도 기록 | P2 |
| E4 | 렌더 5스트림 마감 | P2 첫 항목 참조 | 마감 초과·연속 초과. 실패 시 pull 구조 재검토 | P2 |
| E5 | 인라인 vs 송신 작업자 | 실행 전 고정 모드. 1명·5명, CPU 부하 | 외부 P50/P95/P99, 캡처 처리 P99.9, 캡처 불연속, 송신 API 반환 지연 | P3 |
| E6 | MMCSS Audio vs Pro Audio | 한 번만 비교 | 외부 합계, 마감 초과 | P1 |
| E7 | 드리프트 추정 | 오프라인 주입: ±50/100/200ppm, 일정 지연, 순간 지터, 최소 지연 계단 변화, 송신 스케줄링 변화, 묶음 도착 | 추정 편향, 수렴 시간, 오판, 잘못된 보정으로 생긴 불연속, 장시간 큐 이동 | P2 |
| E8 | 드리프트 보정 방식 | 삽입·삭제 / 선형 보간 / 짧은 다상 리샘플러 | 실제 추가 지연(임펄스), 파형 왜곡, 불연속, CPU, 장기 정확도, 청취 | P3 |
| E9 | 최소 수신 여유 | 여유 스윕, 값마다 재시작 반복 | 지연–보존율 Pareto frontier | P3 |
| E10 | 수신 스레드 스핀 폴링 | 선택 실험 | 외부 합계 vs CPU 비용. 기본 설계로 채택하지 않음 | P4 |
| E11 | Windows RIO 송신 | 선택 실험 (sendto 꼬리가 문제일 때) | 송신 API 반환 꼬리, 외부 P99 | P4 |
