# 003 — 렌더 5스트림 마감 시험

- 단계: P2 / 관련 쟁점: E4 (`ROADMAP.md`), `DESIGN.md` 15장 위험 1
- 상태: 계획 (**미동결**. 정의와 판정 기준은 "측정기 확인"을 통과하고 사용자가 확인한 뒤 동결한다)

이 실험은 입→귀 지연 판정이 아니다. 렌더 스레드가 주기 안에 일을 끝내고 장치에 낼 데이터를 제때 넘기는지를 보는 마감 시험이라, 내부 계측을 판정 근거로 쓴다. 아래의 "빈 큐 관측", "마감 초과", "출력 예정 시점 초과"는 모두 내부 계측이다. **실제 DAC 출력 누락으로 표현하지 않는다. 실제 누락은 외부 리그로만 확인한다.**

## 가설

[가설] 상대 5명의 프레임 이동·디코딩·믹스를 pull 구조로 128프레임(2.67ms) 주기 안에 처리할 수 있고, 게임 수준 CPU 부하에서도 마감 초과가 생기지 않는다.

## 렌더 쓰기 정책 (먼저 고정)

주기 P = 스트림을 연 뒤 실제로 받은 주기 프레임 수(공유 최소에서 128 예상). 초 단위 주기 Pt = P / 48000.

- **정책 A (판정 대상, 최소 지연).** 선채움 = 무음 한 주기(F0 = P). 깨어남마다 정확히 한 주기를 쓴다. 목표 수위 = 0.
- **정책 B (참고, 여유 한 주기).** 선채움 = 무음 두 주기(F0 = 2P). 깨어남마다 한 주기를 쓴다. 목표 수위 = P. 지연이 한 주기(2.67ms) 늘어난다.
- 두 정책 모두 밀린 만큼 몰아서 쓰지 않는다. 결손 뒤에는 "회복 규칙"을 따른다.
- **최종 결론은 정책 A 조건으로만 낸다.** 정책 B는 계측 특성을 비교하는 참고다.

근거: P1 로컬 직결 기록(`DISCUSSION-LOG.md`, 2026-11-11, 수신 PC, 공유 최소 128, 깨어남당 한 주기 쓰기, 선채움 무음 한 주기)에서 렌더가 깨어날 때마다 `GetCurrentPadding`이 0이었다(11,251회 전부). 정책 A에서는 padding 0이 정상 상태이므로 "버퍼 − padding"으로 놓친 주기를 세는 식은 성립하지 않는다. 그 식은 쓰지 않는다.

## 원시 측정값 (깨어남마다 기록, 계측 켬/끔 공통)

아래 값을 가공하지 않고 깨어남마다 고정 크기 기록 하나로 진단 링에 넘겨 파일로 남긴다. 뒤의 모든 파생값은 이 원시값으로 사후에 다시 계산할 수 있어야 한다.

| 기호 | 내용 |
|---|---|
| `t_k` | 이벤트 대기 반환 직후 QPC |
| `p_k` | 쓰기 전 `GetCurrentPadding` (공유 모드) |
| `w_k` | 이번에 쓴 프레임 수 |
| `e_k` | `ReleaseBuffer` 반환 직후 QPC (쓰기 완료 시점) |
| `pos_k`, `q_k` | 쓰기 완료 뒤 `IAudioClock::GetPosition`이 준 장치 위치(원값)와 **그 위치에 대응하는 QPC 값(같은 호출이 준 값)** |
| `W_k` | 스트림 시작부터 이번 쓰기까지 쓴 프레임 누계. 선채움 F0 포함 |
| `s_k` | 이번에 쓴 블록의 첫 원본 샘플 번호(상대 공통 재생 커서) |
| `skip_k` | 이번 쓰기 직전에 건너뛴 원본 샘플 범위 `[시작, 끝)` (없으면 빈 범위) |
| `dec_k` | 이번 주기의 디코드 호출 수(전 상대 합) |
| 상대별 | 이번 주기의 `missing_samples`, `played_samples` 증가량 |

실행마다 한 번 기록: `GetFrequency` 값, QPC 주파수, P, 버퍼 크기, F0, 정책, `Start` 직후 첫 `GetPosition` 쌍(`pos_0`, `q_0`).

## 파생값의 정의

### 기본

- 장치 진행량 `D_k = (pos_k − pos_0) × 48000 / GetFrequency값` (프레임). `W`와 `D`는 둘 다 "스트림에 처음 넣은 프레임 = 0"에서 센다.
- 깨어남 간격 초과 `a_k = (t_k − t_(k−1)) − Pt` (부호 있음).
- 처리 시간 `c_k = e_k − t_k`. 주기 대비 비율 = `c_k / Pt`.
- 쓰기 완료 지연 `L_k = (e_k − e_(k−1)) − Pt`. 항등식 `L_k = a_k + (c_k − c_(k−1))`가 성립한다.
- 남은 출력 여유 `R_k = W_k − D_k` (쓰기 완료 시점에 넣었지만 아직 장치가 소비하지 않은 프레임).

### 장치 위치의 갱신 간격과 QPC 시차

- 시간은 호출 시각이 아니라 `GetPosition`이 위치와 함께 준 `q_k`로 잰다. 위치와 `q_k`는 한 쌍이므로, 위치가 늦게 갱신되거나 계단식으로 갱신돼도 쌍끼리 비교하면 시차가 상쇄된다.
- `q_k = q_(k−1)`(새 표본이 없음)인 깨어남은 구간 길이가 0이므로 결손 계산에서 빼고 다음 깨어남의 구간에 합친다. 이런 깨어남의 수와 `e_k − q_k`(쌍이 얼마나 오래된 값인지)의 분포를 적는다.

### 결손 (주기별 증가량으로 정의)

큐가 비었을 때 장치 위치가 멈추는지 계속 가는지는 확인한 적이 없으므로([가설]) 두 항을 모두 정의한다. 어느 항이 반응하는지는 측정기 확인에서 본다.

- 구간 경과량 `τ_k = (q_k − q_(k−1)) × 48000 / QPC단위` (프레임).
- **멈춤 항(증가량)** `δ_k = τ_k − (D_k − D_(k−1))`. 그 구간에서 시간은 흘렀는데 장치가 우리 프레임을 소비하지 못한 양이다. 각 구간은 정확히 한 깨어남에만 속하므로, **한 번의 정지는 위치가 못 따라간 그 구간에서만 잡히고 이후 구간에서 다시 집계되지 않는다.**
- **지나침 항(증가량)** `O_k = max(0, D_k − W_(k−1))`는 누적 수준이므로 그대로 쓰면 같은 정지가 이후에도 계속 잡힌다. 증가량 `ω_k = max(0, O_k − max(O_j, j < k))`만 쓴다.
- **결손 프레임** `x_k = max(δ_k, ω_k)`, 단 허용 오차 ε 이하면 0. ε은 아래 절차로 정한다.
- 반 주기 반올림은 하지 않는다.

### 따로 기록하는 세 값

1. **결손 프레임 수.** 실행의 `Σ x_k`.
2. **결손 사건 수.** `x_k > 0`인 깨어남이 잇따르는 한 묶음을 사건 하나로 센다. 두 묶음 사이에 장치가 정상으로 진행한 양이 한 주기(P프레임) 미만이면 한 사건으로 합친다. 사건마다 결손 프레임 `X = Σ x_k`와 시작·끝 `q`를 적는다.
3. **주기 환산값.** 사건마다 `X / P`(소수 둘째 자리까지, 반올림·올림 없음). 이 값은 결손의 크기를 주기 단위로 나타낸 것이며 **"실제 놓친 주기 수"라고 부르지 않는다.**

### 연속 2주기 결손 (실제 시간축에서 정의)

장치 위치–QPC 쌍의 시간축에서, **한 사건 안에서 장치가 진행하지 못한 시간의 합이 2 × Pt 이상**인 경우다. 계산은 `X / 48000 ≥ 2 × Pt − ε / 48000`, 곧 `X ≥ 2P − ε`. 주기 환산값을 정수로 만들어 세지 않는다.

### 구분해서 기록하는 세 가지 사건

1. **빈 큐 관측.** `p_k = 0`. 정책 A에서는 정상 상태라 이상 신호가 아니다. 횟수만 적고 판정에 쓰지 않는다.
2. **마감 초과.** 결손 사건(`x_k > 0`).
3. **출력 예정 시점 초과.** 원본 샘플 `s`의 출력 예정 위치를 `X(s) = F0 + (s − s_0)`로 둔다(`s_0`는 첫 블록의 첫 샘플). 장치 시간 진행량 `A_k = D_k + Σ δ_j`(j ≤ k, ε 초과분만)는 멈춘 구간을 포함해 장치 쪽 시간이 흐른 양이다. 쓰기 완료 시점에 `A_k > X(s_k) + ε`이면 그 블록은 출력 예정 시점을 넘겨 쓴 것이다. 횟수와 초과량의 최대를 적는다.

### 허용 오차 ε을 정하는 절차 (절차를 먼저 고정, 값은 본 실행 전에 동결)

1. 정책 A 정상 대조군(부하 없음, 5스트림, 0µs, 60초 3회)의 모든 깨어남에서 `δ_k`와 `ω_k`의 분포(최소, P50, P99, P99.9, 최대)를 낸다.
2. `|δ_k|` 또는 `ω_k`가 P/4를 넘는 깨어남을 후보로 뽑아 원시값으로 가린다. 같은 깨어남 또는 바로 앞 깨어남에서 `L_k ≥ Pt / 2`(쓰기 완료가 실제로 늦음)이면 **진짜 결손**, 아니면 **오탐**(계측 특성)으로 적는다.
3. ε = 진짜 결손으로 가려진 깨어남을 뺀 나머지의 `max(|δ_k|, ω_k)`를 프레임으로 올림한 값 + 1프레임.
4. ε ≥ P/2이면 이 측정으로는 한 주기 결손을 가릴 수 없다는 뜻이므로 측정기 확인 실패로 보고 정의를 고친다.
5. 정책 B 대조군에서도 같은 분포를 내서 적되, **ε은 정책 A의 값만 쓴다.**

## 회복 규칙 (늦은 음성 건너뛰기)

- 결손 사건이 끝난 깨어남에서, 그 사건의 결손 프레임 `X`만큼 원본을 건너뛴다(렌더 코어의 `skip`). 늦은 음성을 뒤로 미루지 않는다.
- **건너뛴 원본 샘플 범위를 기록한다**(`skip_k`). 이후 블록도 `s_k`를 계속 기록하므로 "스트림 위치 `W` ↔ 원본 샘플 번호"의 대응이 실행 끝까지 유지된다.
- **건너뛰기 전에 발생한 마감 초과와 출력 예정 시점 초과는 취소하지 않는다.** 건너뛰기는 그 뒤 블록의 예정 위치를 다시 맞출 뿐이다.
- **건너뛴 샘플은 보존율 손실로 따로 센다**(아래).

## 보존율과 무음

상대마다 계산한다.

- 대상 샘플 = `played_samples + skipped_samples`(재생 커서가 지나간 원본 샘플).
- **정상 샘플 보존율** = `(played_samples − missing_samples) / 대상 샘플`.
- 손실은 사유별로 따로 적는다: 건너뛰기 손실(`skipped_samples`), 공급 미도착 손실(`missing_samples`).
- **최대 연속 무음** = 원본이 나가지 않은 샘플(무음으로 채운 블록과 건너뛴 범위)이 원본 시간축에서 끊기지 않고 이어진 최대 길이(샘플, ms). 깨어남별 기록의 상대별 증가량과 `skip_k`로 계산한다.

## 원인 분류 (사건마다 실측값으로)

중앙값으로 원인을 단정하지 않는다. 사건마다 그 사건에 속한 깨어남과 바로 앞 깨어남 가운데 **쓰기 완료 지연 `L_k`가 가장 큰 깨어남**을 골라, 항등식 `L_k = a_k + b_k`(`b_k = c_k − c_(k−1)`, 처리 시간 증가분)의 두 실측 성분으로 나눈다.

| 분류 | 조건 |
|---|---|
| 깨어남 지연 | `L_k > 0`이고 `a_k ≥ 0.8 × L_k` |
| 처리 시간 | `L_k > 0`이고 `b_k ≥ 0.8 × L_k` |
| 복합 | `L_k > 0`이고 위 둘 다 아님(두 성분이 각각 20%를 넘게 기여) |
| 미분류 | `L_k ≤ 0`(결손은 잡혔는데 쓰기 완료는 늦지 않음) |

수치 예시(Pt = 2.667ms):

- 예 1: 깨어남 간격 8.200ms, `c_k` = 0.050, `c_(k−1)` = 0.040. `a` = 5.533, `b` = 0.010, `L` = 5.543. `a / L` = 99.8% → **깨어남 지연.**
- 예 2: 깨어남 간격 2.667ms, `c_k` = 6.000, `c_(k−1)` = 0.050. `a` = 0.000, `b` = 5.950, `L` = 5.950. `b / L` = 100% → **처리 시간.** (다음 깨어남은 간격이 6.0ms로 길지만 `b` = −5.950이라 `L` = −2.617로 늦지 않으므로, 같은 정지가 깨어남 지연으로 다시 분류되지 않는다.)
- 예 3: 깨어남 간격 4.167ms, `c_k` = 1.450, `c_(k−1)` = 0.050. `a` = 1.500, `b` = 1.400, `L` = 2.900. 52% / 48% → **복합.**

- 사건마다 `a_k`, `b_k`, `c_k`, `L_k`, 분류를 모두 남긴다. 실행의 처리 시간 중앙값은 참고로만 함께 적는다.
- `7712c72` 기록의 수신 PC 독점 + 부하 + MMCSS 없음(처리는 짧은데 깨어남 수가 32~40%로 줄어듦)은 "깨어남 지연"에 해당하는 사례다.
- **구조 재검토 여부는 이 분류와 분석으로 판단한다.** 분류 하나로 자동 결정하지 않는다.

## 계측 켬/끔

- **항상 유지(판정용 최소 측정):** 위 "원시 측정값" 전부와 그 진단 링 전달. QPC 2회(`t_k`, `e_k`), padding 조회 1회, `GetPosition` 1회.
- **계측 켬에서만(상세 구간 계측):** 구간 경계 QPC 3회와 구간 필드.
  - 프레임 이동: 링에서 꺼내 `FrameLedger`에 넣고 저장소에 두기까지(`MediaFrame` 1KB 값 이동 포함). 꺼낸 프레임 수로 나눈 프레임당 값도 적는다.
  - 디코더: 전 상대의 디코딩(합성 디코드 비용 포함).
  - 믹서: 합산, 포화, 장치 형식 변환·쓰기.
  - WASAPI: 처리 시간에서 위 셋을 뺀 나머지.
- 주 결과는 계측 끔이다. 진단 링이 가득 차 버린 기록 수를 적는다(0이 아니면 그 실행은 원시값이 빠진 것이므로 표시한다).
- 분포는 실행 안에서 P50 / P95 / P99 / P99.9와 최대를 낸다. 실행 내부 분포이며 통계 단위는 재시작이다.

## 합성 스트림 공급과 입력 큐 고갈

- 상대마다 수신→렌더 링 1개(용량 16), 항목은 `MediaFrame`(PCM16 모노 128샘플, −60dBFS 사인, 상대마다 다른 주파수).
- 공급 스레드 1개가 수신 스레드 역할을 한다. 시작 전에 상대마다 4프레임을 선채움하고, 이후 약 1ms마다 렌더가 소비한 샘플 수(원자 변수)를 읽어 상대마다 "넣은 프레임 − 소비한 프레임 = 4"가 되도록 채운다.
- 공급 스레드는 MMCSS Audio로 등록한다(실제 수신 스레드 조건은 E5).
- **입력 큐 고갈(공급 미도착).** `missing_samples > 0`. 마감 초과와 합치지 않는다. 함께 적는 값: 링 가득 참으로 못 넣은 수, 렌더 코어의 폐기 사유별 카운터와 예산 소진 카운터.

## 합성 디코드 비용

- **디코드 1회당** 지정한 시간만큼 CPU를 쓰고 나서 PCM16을 푸는 합성 디코더. 값: 0 / 50 / 100 / 200µs.
- 디코드 1회 = 상대 한 명의 128샘플 프레임 하나를 푸는 호출. **주기당 디코드 횟수**(`dec_k`)를 주기마다 기록하고 분포를 적는다. 프레임이 없어 무음으로 채운 블록은 디코드로 세지 않는다.
- 결과에는 `synthetic_decode_us`로 적고 Opus 추정치라고 부르지 않는다.
- 0µs(PCM)의 결과는 **구조 검증**으로 기록한다. **E4 최종 판정은 Opus 디코딩 실측을 이 곡선에 대조해서 한다.** libopus는 아직 승인되지 않았다.

## 판정 기준 (미동결)

판정 조건: 수신 PC Realtek 헤드폰, 공유 최소 주기, **정책 A**, MMCSS Pro Audio, 부하 `threads=12;duty_percent=100;priority=normal`(`mdc-rig-load`), 5스트림, 계측 끔, 60초, 재시작 5회. 합성 디코드 비용 값마다 따로 판정한다.

- **통과:** 5회 모두 다음을 만족.
  - 마감 초과(결손 사건) 0, 출력 예정 시점 초과 0
  - 최대 처리 시간 < 한 주기(Pt)
  - 정상 샘플 보존율 100%, 최대 연속 무음 0 (일을 버려서 마감만 지킨 결과를 걸러낸다)
- **실패:** 어느 한 실행에서라도 연속 2주기 결손(위 정의). 이 경우 원인 분류와 분석으로 pull 구조 재검토 여부를 판단한다.
- **보류:** 그 사이. 원인을 분석하고 결론에 적는다. 손실이 공급 미도착뿐인 경우도 보류로 두고 공급 방식을 다시 본다.

경험적 목표값(통과/실패 조건이 아니다. 충족 여부를 함께 보고한다):

- 처리 시간 P99.9 ≤ 주기의 50%(1.33ms). `7712c72`까지의 내부 기록에서 같은 장치·부하·Pro Audio의 깨어남 간격 최대가 4.29ms(주기 대비 1.6ms 늦음)였다는 점에서 잡은 값이다. [추정]
- 구조 비용(합성 0µs)의 처리 시간 P99.9 ≤ 주기의 10%(0.27ms). [추정]

결과로 내는 곡선: 합성 디코드 비용별 판정과 처리 시간(P99.9, 최대). "디코드 1회당 몇 µs까지 통과하는가"를 읽는다.

## 측정기 확인 (본 실행 전)

1. **정상 대조군(오탐 확인).** 정책 A와 B 각각, 부하 없음, 5스트림, 0µs, 60초 3회. 여기서 ε을 위 절차로 정한다. 정책 A 대조군에서 잡힌 후보는 원시값으로 진짜 결손인지 오탐인지 가려 모두 적는다.
2. **강제 정지(미탐 확인).** 정책 A와 B 각각, 3주기 길이의 정지를 5초 간격으로 10회씩.
   - 처리 중 정지(쓰기 전에 멈춤): 10회 모두 결손 사건으로 잡히고 "처리 시간"으로 분류돼야 한다. 사건의 결손 프레임이 넣은 정지 길이와 얼마나 맞는지 적는다.
   - 깨어남 직전 정지(`t_k`를 찍기 전에 멈춤): 10회 모두 잡히고 "깨어남 지연"으로 분류돼야 한다.
   - **스케줄링으로 만든 깨어남 지연:** 이 확인에서만 렌더 스레드를 MMCSS 없이 한 코어에 고정하고, 같은 코어에 고정한 높은 우선순위 스레드를 3주기 동안 돌린다. 10회 모두 잡히고 "깨어남 지연"으로 분류돼야 한다. 코드로 넣은 정지가 아니라 실제 스케줄링 지연에서도 정의가 반응하는지 보는 것이다.
   - 정지가 없는 구간에서는 결손 사건이 0이어야 한다.
3. 적는 것: `δ_k`와 `ω_k` 중 실제로 반응한 항, 큐가 비었을 때 장치 위치가 멈췄는지, 정책 B에서 `p_k = 0`이 정지와 함께 나타났는지, 넣은 정지 길이 대비 결손 프레임의 비.
4. 통과하면 ε 값과 함께 정의·판정 기준을 사용자 확인 뒤 **동결**하고, 이 파일의 상태 줄에 날짜와 커밋을 적는다. 통과하지 못하면 본 실행 전에 정의를 고치고 이유를 여기에 적은 뒤 확인을 다시 한다. 본 실행 결과를 본 뒤에는 고치지 않는다.
