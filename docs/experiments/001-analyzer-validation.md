# 001 — 분석기 검출·분류 검증 (신호·분석 기준 동결 전)

- 단계: P0 / 관련: `ROADMAP.md` P0 분석기, `RIG.md` 4·5장
- 상태: 계획
- 선행 조건: 이 검증은 기존 명동콜링 기준선 녹음 **전에** 끝낸다. 채택되면 신호(`ChirpConfig` 기본값)와 분석 기준(아래 후보 값)을 동결한다. 동결 뒤에 바꾸려면 새 실험 번호로 다시 검증한다.

## 가설

## 검증 후보 (사용자 승인: 검증할 후보로만, 확정 아님)

- **q_min = 0.4.** bit_q_min 0.5와 그 밖의 `DetectorConfig` 기본값은 고정한다.
- **중첩 표시:** 같은 채널에서 다른 후보가 ±marker_len(8736샘플) 안에 있는 후보에는 "중첩" 표시를 붙인다. 중첩된 Normal의 시각 허용은 2샘플이다.
  - 개정 기록(검증 실행 전, 2026-11-09): 처음에는 ±sync_len으로 정의했다. 이 정의로는 간격 21ms가 중첩이 아니게 된다. 그런데 21ms에서도 강한 경로의 비트 처프(동기 시작 뒤 22ms부터)가 약한 경로의 동기와 겹치며, 배경 표의 21ms 오차 1.307샘플이 그 결과다. 정의가 간섭 범위를 덮지 못하는 계획 오류였으므로 ±marker_len으로 고쳤다. 판정 기준 수치(2샘플, 0.5샘플, 합격선)는 바꾸지 않았다. (이때는 "구분 가능 조건"의 ±sync_len을 유지했으나, 개정 3에서 주입 조건 정의로 바꿨다.)
- **판정 지연값:** 보정 전 원시 R−L 시간차(ADC 샘플, 동기 처프 시작 기준)다. 요약 통계(P50/P95/P99/최소/최대)도 이 값으로 낸다.
  - 오프셋 보정값(R−L−o)은 마커 CSV에 참고값으로만 남긴다.
  - 근거: `RIG.md` 4장은 채널 오프셋을 보정 대상이 아니라 자체 검증 항목(0 ± 서브샘플)으로 둔다.
  - 실제 리그에서 |o| ≥ 1샘플이면 보정하지 않고, 리그 자체 검증 실패로 처리한다.
  - 합성 검증의 정답 지연은 주입한 R−L 시간차다(주입한 채널 오프셋 포함).
- **단일 경로 0.05샘플**은 "합성 신호 조건의 알고리즘 정확도"다(잡음 없음, 단일 경로). 실제 장치 경로의 정확도 주장이 아니다.
- **누화 제외 창: 고정 기본값을 두지 않는다.** 리그 자체 검증의 교정 결과에서 사전에 정한다.
  - 채널 오프셋 o: 같은 신호를 L·R에 동시에 넣은 녹음에서 R−L 시간차의 중앙값
  - 누화 지연 범위 [x_min, x_max]: R 연결을 뺀 녹음에서 검출된 R 후보의 R−L 지연 최소·최대
  - 누화비 범위 [g_min, g_max] dB (A_R/A_L): 같은 R 연결 해제 녹음에서 구한다
  - 창 W = [min(x_min, o) − 2, max(x_max, o) + 2] 샘플이다. 여유 2샘플은 사전에 고정한다.
  - 교정 파일이 없으면 측정 모드 분석은 "판정 불가"로 거부한다.
  - 기존 설계 초안의 "1ms 근접 지연 보호"는 이것으로 대체한다.
- **누화 −6 dB 기준은 두지 않는다**(미확정). R과 누화의 상대 세기로 실행을 무효 처리하는 규칙은 이 실험 결과를 본 뒤 별도로 정한다.
- **최종 분류는 다섯 가지다.**
  - Normal: 창 W 밖의 R 후보이고, ID(Exact/Corrected)가 예상 ID와 같다.
  - IdUndecodable: 창 밖의 R 후보가 ID 해독 불가(Erased/Uncorrectable)이고, 일정·지연 중앙값으로 그 마커에 유일하게 배정된다. 소리는 도착했다.
  - IdMismatch: 창 밖의 R 후보가 유효한 다른 ID다(오정정 의심).
  - Ambiguous: 창 밖에 배정할 R 후보가 없고, 창 안에 관문을 넘는 후보가 있다. 실제 경로가 누화와 구분되지 않으므로 **낮은 지연으로 확정하지 않는다.** 사유를 기록한다(누화비 범위 안: 누화 아래 실제 경로가 가려졌을 수 있음 / 범위 밖: 비정상 근접 경로).
  - Ambiguous(사유 unassigned_undecodable): Normal·IdUndecodable·IdMismatch가 아니다. 창 밖에 해독 불가(Erased/Uncorrectable) R 후보가 있고, 그 후보가 이 마커의 가능 범위 (t_L + W 상한, t_L + max_delay] 안에 있다. 그러나 유일하게 배정할 수 없다(지연 중앙값이 없는 경우 포함).
    - Normal이 0개인 실행에는 "지연 기준 없음" 경고를 붙인다.
    - 개정 기록(검증 실행 전, 2026-11-09): 구현 중 Codex가 지적했다. 이 경우를 Missing으로 두면 판정 기준 6(ID 해독 실패를 손실로 세지 않음)을 어긴다. 실행 전체를 판정 불가로 버리는 대신 마커 단위로 대응 불명을 보고하도록 고쳤다. 판정 기준 수치는 바꾸지 않았다.
  - Missing: 창 안팎 어디에도 관문을 넘는 후보가 없다. 뜻은 **"마커 미검출, 원인 미확정"**이다.
    - 음성 손실일 수도, 관문 아래로의 감쇠(AGC 등)일 수도, 검출기 한계일 수도 있다.
    - 분석기 출력과 보고서에서 Missing을 음성 손실로 단정하지 않는다.
- 창 안 후보는 어떤 경우에도 Normal이 되지 않는다.
- **비율 표기:**
  - 마커 검출률 (Normal + IdUndecodable)/L_ok는 마커 단위 대리 지표다. **원본 샘플 보존율이 아니다.**
  - 구간 보존률(17개 처프 구간 중 존재 비율)도 대리 지표다.
  - 원본 샘플 보존율은 P0 리그로 측정하지 않는다. 앱 내부의 원본 샘플 대응 기록 같은 별도 수단이 필요하다.
  - 보고서에서 두 지표를 같은 이름으로 쓰지 않는다.

## 판정 기준 (검증 전 확정, 이후 변경 금지)

정의. 합성 신호라 각 마커의 정답(실제 경로 유무·지연, 누화·에코 유무)을 안다.

- **잘못 확정:** 최종 분류가 Normal인데 다음 중 하나다. (a) 정답 실제 경로가 없다(누화·에코만 있음). (b) 지연이 정답 실제 경로 지연과 허용치 넘게 다르다. 허용치는 중첩 표시면 2샘플, 아니면 0.5샘플이다. (c) 지연이 창 W 안이다.
- **놓침:** 정답 실제 경로가 있고 "구분 가능 조건"인데 최종 분류가 Normal이 아니다.
- **구분 가능 조건(사전 정의, 주입 조건만으로 판정):**
  - 하네스가 마커마다 주입한 정답 메타데이터만으로 정한다. 분석기 출력·검출 결과·q 값으로 정하지 않는다.
  - 마커 하나는 아래 5개를 모두 만족할 때 구분 가능이다.
    1. 정답 실제 경로가 있다(G4 누화 단독, G5 삭제 마커, censored 마커는 놓침 판정 대상 아님).
    2. 주입 실제 경로 지연이 창 W 밖이고 max_delay 이하다.
    3. 주입 SNR(실제 경로 비무음 구간 RMS 대 잡음 RMS)이 10 dB 이상이거나, 잡음이 없다.
    4. 같은 R 채널에 주입한 다른 모든 경로(누화, 에코, 다른 마커)마다 다음 중 하나다.
       - 실제 경로와 시작 시각 차이가 marker_len(8736샘플)을 넘는다.
       - 주입 레벨이 실제 경로 주입 레벨 이하다(dB, 같은 L 기준).
    5. 다른 모든 경로와의 시작 시각 차이가 2×dedup_radius(96샘플) 이상이다.
  - 그룹별로 미리 펼친 결과:
    - G1: 전부 구분 가능
    - G2: 실제 레벨 ≥ 누화 레벨인 칸만 구분 가능. 실제 지연 5/20/100ms가 모두 marker_len 안이기 때문이다.
    - G3: 에코 상대 세기 ≤ 0 dB이고 간격 ≥ 2ms인 칸만 구분 가능. 간격 1ms 칸과 +6 dB 칸은 제외된다.
    - G5: 클리핑·±100ppm·비트 손상 마커는 구분 가능. 삭제 마커와 censored 마커는 제외.
  - 구분 가능이 아닌 마커에서는 놓침을 판정하지 않는다. 대신 Normal(정답)·Ambiguous·Missing 분포를 측정값(분해 한계)으로 보고한다. 잘못 확정 판정(기준 1)과 기준 3·4는 모든 마커에 적용한다.

| # | 기준 | 합격선 |
|---|---|---|
| 1 | 잘못 확정 수 (전 조건 합계, 실제 경로 마커 ≥ 20,000) | **0건** |
| 2 | 놓친 비율 (구분 가능 조건) | 전체 ≤ 0.5%, 조건 칸 하나라도 ≤ 5% |
| 3 | 누화 단독(R 연결 해제 모사) | Normal 0건 |
| 4 | 실제 경로가 겹친(±marker_len) 누화보다 약하고, 누화가 관문을 넘는 조건 | 최종 분류는 정답 경로의 Normal 또는 Ambiguous만 허용. Missing(마커 미검출)으로 분류하거나 누화 지연으로 Normal 확정하면 실패 |
| 5 | 단일 경로 알고리즘 정확도(합성, 잡음 없음) | 최대 절대 오차 ≤ 0.05샘플 |
| 6 | ID 해독 실패의 마커 미검출 오분류 | Normal이 있는 실행에서 비트 1개·2개 반전, 비트 무음 마커가 Missing으로 분류되면 실패. 정답은 Normal(1개 반전) 또는 IdUndecodable(2개 반전·무음) |

- **채택:** 1~6을 Windows MSVC와 Linux **양쪽에서** 모두 충족하면 후보를 채택하고, 신호와 분석 기준을 동결한다. Linux 검증이 끝나기 전에는 채택이나 동결 완료로 보고하지 않는다.
- **실패:** 기준을 바꾸지 않는다. 실패 마커마다 원인을 다음으로 분류해 보고한다.
  - (i) 동기 구분 능력: 비트 처프·다른 경로와의 교차 상관으로 생긴 잘못된 동기 후보, 또는 겹침으로 동기 후보를 잃음
  - (ii) 분류·매칭 규칙
  - (iii) 구현 결함
  - (iv) 시각 추정 편향
  - (i)이 원인이면 동기 신호 재설계(A안)를 검토한다. 재실험은 새 번호로 한다.

## 개정 3 (검증 실행 전, 2026-11-09, 사용자 지시)

- 판정 지연값을 보정 전 원시 R−L로 정했다. 요약 통계는 원래 이 값을 쓰므로 코드 변경은 없다.
- Missing의 뜻을 "마커 미검출, 원인 미확정"으로 바꿨다. 마커 검출률과 원본 샘플 보존율의 표기를 분리했다.
- 구분 가능 조건을 주입 조건만으로 다시 정의했다. 간섭 범위는 sync_len에서 marker_len으로 넓혔다. 최소 간격 2×dedup_radius를 추가했다.
- 기준 4·6의 적용 범위를 명시했다. 기준 4는 누화가 관문을 넘는 조건, 기준 6은 Normal이 있는 실행이다.
- **합격 난이도 영향:** 판정 수치(0건, 0.5%, 5%, 0.05/0.5/2샘플)는 그대로다. 그러나 분류 규칙과 적용 범위가 바뀌었으므로 합격 난이도가 처음 계획과 달라질 수 있다.
  - 쉬워지는 방향: 기준 2(놓침)의 판정 대상이 줄었다. G2의 "실제가 누화보다 약한" 칸, G3의 1ms·+6 dB 칸이 빠졌다.
  - 어려워지는 방향: Ambiguous(unassigned_undecodable)이 추가되면서 기준 6과 지연 산출 가능 비율이 영향을 받는다. 판정 지연을 원시값으로 고정했다.
  - 빠진 칸은 분해 한계 측정값으로 반드시 보고한다. 결과를 해석할 때 이 개정을 함께 적는다.

## 독립 검증 보고 항목 (필수)

- 잘못 확정된 마커 수와 비율(전체, 그룹·조건 칸별)
- 놓친 마커 비율(구분 가능 조건, 전체와 칸별 최댓값)
- Ambiguous 비율, 지연 산출 가능 비율(Normal / L_ok). 둘 다 전체와 그룹별
- 구분 가능이 아닌 마커의 분류 분포(분해 한계)
- ignored 테스트 목록과 각 내용. 검증에서는 ignored 테스트를 **전부** 실행하고 결과를 적는다.
- 구현 Codex가 "가장 보수적인 쪽"으로 스스로 정한 설계 판단 목록(구현 세션 보고와 코드에서 확인)
