# Claude–Codex 개발 위임

작업 요청: $ARGUMENTS

당신은 명동콜링 v2의 개발 오케스트레이터다. `CLAUDE.md`와 `AGENTS.md`를 따르고 아래 절차를 순서대로 실행한다. 재시도·재위임 한도와 Claude 직접 수정 예외는 `CLAUDE.md`에 정의돼 있다.

Codex 호출은 공식 Codex 플러그인의 `codex:codex-rescue` 서브에이전트(`/codex:rescue`)를 쓴다. 플러그인은 요청을 한 번에 하나만 처리하므로 Codex 작업은 **순차로** 진행하고, 이전 작업이 끝났는지 `/codex:status`로 확인한 뒤 다음을 시작한다. 실행 중인 작업을 중복으로 만들지 않는다.

## 0. 사전 점검

- 현재 브랜치가 `v2`인지 확인한다.
- `git status --porcelain` 결과를 **기준선**으로 기록한다. 기존 사용자 변경사항은 보존한다.
- `docs/DESIGN.md`, `docs/ROADMAP.md`, 관련 소스 코드를 읽는다.
- 이미 진행 중인 Codex 작업이 있으면 새로 만들지 않는다.
- DESIGN의 채택 결정을 무단으로 바꾸지 않는다.

## 1. Claude 설계

다음을 작성한다.

- 작업 목표와 현재 로드맵 단계
- 관련 크레이트, **수정 허용 파일**, 범위 밖 파일
- 유지해야 할 불변식
- 구현 계획
- 수용 테스트와 실패 조건
- 실시간 성능·보안 위험, 고위험 변경 해당 여부(`CLAUDE.md`)
- 하드웨어 검증 필요 여부(Windows 실장치, 외부 리그)

설계 변경이나 P3 관문 결정이 필요하면 **여기서 멈추고 사용자 승인을 요청한다.**

## 2. Codex 설계 검증 (고위험 변경이면 필수)

`/codex:rescue --fresh`로 새 세션을 열어 독립 검증을 맡긴다. 요청에 포함할 것:

- 목표와 기존 설계, 관련 문서와 코드 위치
- 불변식
- 구체적인 반례와 실패 상황 조사, 대안의 장단점
- **파일 수정, 커밋, 푸시 금지**

검증이 끝나면 `git status --porcelain`을 기준선과 비교한다. **파일이 바뀌었으면 검증 실패로 처리하고 중단해 사용자에게 보고한다**(되돌리지 않는다). 읽기 전용은 프롬프트로만 지켜지기 때문이다.

이 단계는 구현 전 설계 분석이다. 코드 변경을 대상으로 하는 `/codex:adversarial-review`(5단계)와 구분한다. 검증 결과를 평가해 설계를 확정한다.

## 3. Codex 구현 위임

`/codex:rescue`에 아래 위임서를 넘긴다.

```
목표:
[정확한 구현 목표]

수정 허용 범위:
[크레이트 및 파일. 이 밖은 수정 금지]

읽어야 하는 문서:
- AGENTS.md
- docs/DESIGN.md [관련 절]
- docs/ROADMAP.md [관련 단계]

불변식:
[절대 위반하면 안 되는 규칙]

수용 테스트:
[실행할 테스트와 합격 기준]

금지 사항:
- 범위 밖 리팩터링, 무단 설계 변경
- 사용자 변경사항 삭제
- 커밋, 푸시, 병합, 브랜치 전환
- AGENTS.md, CLAUDE.md, docs/DESIGN.md, .claude/ 수정
- 사용자 승인 없는 의존성 추가

완료 전 AGENTS.md '작업 완료 전 검증' 명령 네 개를 실행할 것.

결과 보고:
- 수정한 파일
- 구현 내용
- 실행한 명령과 결과 (성공 / 실패 / 미실행 구분)
- 발견된 위험
```

Codex가 실행 중인 동안 같은 작업 트리를 수정하지 않는다. 완료를 확인한 뒤 다음 단계로 간다.

## 4. Claude 독립 코드 리뷰

Codex의 설명이 아니라 `git diff`(기준선 대비)를 직접 읽는다.

- 구현 목표 충족, 허용 범위 준수
- DESIGN·ROADMAP과의 일치, 크레이트 의존성 방향
- `timeline` 불변식
- 실시간 경로의 힙 할당·해제, 블로킹 락, I/O, 패닉 가능성
- 테스트가 반례를 충분히 다루는지
- 기존 동작 회귀 위험

문제가 있으면 근거와 재현 절차를 적어 Codex에 수정을 재위임한다(한도는 `CLAUDE.md`).

## 5. 고위험 변경 적대적 리뷰

고위험 변경이면 **새 세션**에서 `/codex:adversarial-review`로 diff를 검토한다.

- 앞선 구현 결론을 정답으로 가정하지 않는다.
- 설계 결함, 경쟁 상태, 반례, 불변식 위반을 찾는다.
- 리뷰 중 코드를 수정하지 않는다(2단계와 같이 `git status`로 확인).

Codex 리뷰 결과와 Claude 리뷰 결과를 대조한다.

## 6. 최종 검증

`AGENTS.md` '작업 완료 전 검증'의 명령 네 개를 Claude가 다시 실행한다. 기존 경고, 새 경고, 테스트 실패를 구분한다.

외부 지연 측정은 `docs/RIG.md`를 따른다. 하드웨어 측정이 없으면 지연 개선으로 확정하지 않는다.

## 7. 최종 보고

간결하게 보고한다.

1. 완료된 작업
2. 변경된 파일
3. Codex 구현과 Claude 리뷰 결과 (고위험이면 적대적 리뷰 대조 결과 포함)
4. Claude 직접 수정 (있으면, `CLAUDE.md` 예외 범위 안인지)
5. 테스트 성공 / 실패 / 미실행
6. 외부 측정 여부
7. 남은 위험
8. 사용자 결정이 필요한 사항

## 8. 커밋 (사용자 승인 후)

보고를 받은 사용자가 승인하면 Claude가 커밋한다. 승인 전에는 커밋하지 않는다. 푸시는 사용자가 지시할 때만 한다.
