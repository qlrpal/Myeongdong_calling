# 0.3.3 개발 기준점 · 2026-10-07

현재 버전을 다음 개발의 기준으로 보존합니다. 잔여 버퍼·지연 미세 튜닝은 앱 완성 후 유지보수로 진행합니다.

## 완료

- 기존 웹 프로젝트와 네이티브 앱/서버 분리
- C#/.NET Windows 앱과 Node.js 연결 관리 서버
- 네이티브 WebRTC ICE·DTLS/SRTP·Opus 통화, 향후 엔진 교체를 위한 ICallEngine 분리
- Opus 48kHz 모노/20ms 프레임, WASAPI 공유 모드의 입력·출력
- 마이크 콜백과 네트워크 송신 분리, 제한된 송신 큐와 명시적인 RTP 시간축
- 장치 오류 표시, 한 번의 자동 출력 복구, 통화를 유지하는 수동 출력 재시작
- 실시간 RTT·양방향 보고 손실·지터·패킷 간격·코덱/콜백 처리 시간·장치 상태
- 큐 누적·버퍼 부족·부족 길이·송신 대기/버림 진단
- LAN UDP/경로/ping 검사, 읽을 수 있는 UTF-8 한글 JSON 저장·복사
- 빌드 스크립트와 전송·RTCP·재생·입력 검증 도구

## 검증한 범위

- 동일 공유기의 Windows PC 두 대에서 실제 음성 통화
- Tailscale 내부망 우회 문제를 식별하고 해제 후 직접 연결 확인
- 기존 WaveOut의 느린 소비를 재현하고 WASAPI 전환 후 큐 누적과 심한 끊김 개선
- 물리 이어폰 분리 중 캡처 공백과 출력 오류/자동 복구 확인
- 마지막 양쪽 비교 보고서는 0.3.2: 약 4분 통화, 큐 정리/송신 큐 버림/양방향 보고 손실 0
- 해당 보고서의 마지막 큐는 약 60~62ms, 버퍼 부족은 노트북 0회/PC 6회
- PC 부족 구간의 요청·소비량 차이 합계는 약 48ms로 추정
- 0.3.3은 코덱 사전 준비와 부족 길이 계측을 보완했으며 실제 입력·버퍼 테스트/빌드 통과

0.3.3의 새 양쪽 장시간 보고서는 아직 확보하지 않았습니다. 전체 음성 지연과 주관적 음질은 아직 정밀 측정하지 않았습니다.

## 유지보수로 이관

- 잔여 순간 버퍼 부족과 시작 시점의 오디오 처리 지연
- 장치 전환/분리 중 캡처 중단 시간 최소화
- 더 낮은 입출력 버퍼, 클록 차이 보정과 세밀한 지터 튜닝
- 재현 가능한 양쪽 음질/종단 간 지연 측정과 환경별 회귀 검증

기능 개발 중 심한 끊김이나 연결 실패가 재발하면 해당 회귀는 즉시 수정합니다.

## 다음 기능 개발 순서

1. **장치와 음질 설정:** 마이크/출력 장치 선택, 음소거/볼륨, Opus 품질 프로필과 적용 상태 표시. 기존 안정 프로필을 유지하며 새 설정을 추가합니다.
2. **외부망 연결:** Ubuntu TURN, 만료되는 중계 자격 증명, 서로 다른 회선에서 직접/중계 연결 검증. 기존 HTTPS 프록시를 활용하고 서버 자동 시작/재시작을 구성합니다.
3. **앱 사용 흐름:** 참가자/통화 상태 화면, 방 입장/초대, 이해하기 쉬운 실패 안내와 재접속. 정밀 진단은 별도 화면으로 분리합니다.
4. **배포:** 런타임을 포함한 Windows 패키지, 버전 표시, 설정 저장, 라이선스 고지와 설치/업데이트 방식 정리.
5. **완성 검증:** 다른 장치·회선, 장시간·그룹 통화, 권한/장치 변경/네트워크 단절 검증. 실제 결과로 지원 범위 확정.

현재 최대 6명 메시 구현은 그룹 실통화 미검증입니다. TURN은 아직 운영 환경에 없고 현재 배포는 .NET Desktop Runtime이 필요합니다.
커스텀 전송 엔진, 계정/채팅/화면 공유 등 추가 기능은 기본 통화 앱 완성 후 별도로 판단합니다.
