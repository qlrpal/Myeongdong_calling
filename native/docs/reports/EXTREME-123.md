# EXTREME-123: 참가·장치 선택의 오류 안내

2026-10-29 / `codex/extreme-latency`. 사용자가 당장 실제 통화 시험을 할 수 없는 상황에서, 오디오 정책을 바꾸지 않고 설정/참가 흐름의 완성도를 보완했다.

## 확인한 문제

- 저장한 고정 장치가 목록에서 사라지면 Windows 기본 장치로 조용히 바뀌었다.
- 입력 목록 갱신 뒤 출력 조회가 실패하면 목록의 일부만 바뀔 수 있었다.
- 잘못된 참가 입력을 고쳐야 할 위치가 분명하지 않았고, 자동 복구의 최종 실패 뒤에도 입장 안내에 이전 참가 완료 문구가 남을 수 있었다.

## 변경

- `AudioDeviceChoice`: 사용 가능 여부를 추가했다. 사라진 고정 ID는 `저장한 장치 · 연결 안 됨` 항목으로 보존한다. 다시 나타나면 실제 목록 항목을 사용한다. 활성 장치가 없으면 기본 선택에도 사용할 수 없음을 표시한다. Windows 기본 장치를 명시적으로 고른 기존 동작은 유지한다.
- `RefreshDeviceChoices`: 양쪽 목록을 먼저 조회하고 성공한 뒤 UI를 갱신한다. 조회 실패는 설정 화면에 안내하며, 사라진 선택을 자동 대체하지 않는다. 참가 시 다시 조회하고 사용할 수 없는 선택이면 연결을 시작하지 않는다. 실제 마이크를 열거나 장치 형식 지원을 미리 검사하는 기능은 아니다.
- `CallRequest.Create`: 기존 검증 규칙을 유지하고 필드 정보가 있는 ArgumentException 하위 예외를 사용한다. 비밀번호가 포함된 잘못된 URL 등의 입력 원문을 안내에 붙이지 않는다.
- `CallForm.Setup.cs`: 입력 오류 때 해당 필드에 포커스를 이동하고, 설정에 있는 필드는 패널을 열어 보이게 한다. 입력 수정 시 오류 안내를 해제한다. 장치가 없을 때 연결/다른 선택을 안내한다.
- 최종 참가/재연결 실패·복구 중단·정리 오류를 입장 화면에도 표시한다. 상태가 새로 바뀐 경우에만 반영해 사용자가 수정 중인 안내를 매초 덮어쓰지 않는다.

네트워크·WASAPI·코덱·프레임·재생 여유·재연결 횟수/간격은 그대로다. 기존 사용자 설정의 장치 ID를 보존하며 서버·운영 설정·기존 dist를 변경하지 않았다.

## 검증

- Release 정적 분석/빌드: 경고 0, 오류 0.
- 제품 검사 통과: 기존 오디오/설정/통화 수명 검사와 신규 설정 안내 회귀를 실행했다.
- 신규 합성 검사: 사라진 ID 보존, 원본 목록 불변, Windows 기본 선택 유지, 재연결된 ID의 중복/오표시 방지, 빈 필드/잘못된 URL/방 이름/닉네임의 필드 분류, 입력 다듬기, 자격 증명 원문 비노출, 최종 오류와 일시적 재시도 상태 구분을 통과했다.
- 실제 RichEdit 읽기 위치·선택·로그 추가/삭제·숨김 복원 30회 갱신 회귀 통과.

이는 내부 합성/컴포넌트 검사다. 실제 USB 탈착, RDP 전환, 참가/외부 통화, 게임, 마이크/출력 개방·물리 지연 시험은 하지 않았다. 필드 포커스 이동의 실제 사용자 조작 검증은 후속 확인 항목이다. 설정 가능 여부만으로 장치 동작이나 통화 품질을 합격으로 판단하지 않는다.

원본은 Git 제외 `native/.local/ui-polish-20261029/setup-*`와 `native/.local/setup-20261029/`에 보존한다. 코드·사용법 문서를 갱신했으며 요청 없는 커밋/푸시와 기존 배포본 갱신은 하지 않았다.

## 실행·후속 확인

`./native/run.ps1`로 소스 UI를 실행한다. 이후 시험할 수 있을 때 빈/잘못된 참가 입력의 포커스, 저장 장치를 뺀 상태의 선택 보존, 재연결 후 새로고침, 최종 재연결 실패 안내를 확인한다. 저장 장치를 사용할 수 없으면 다른 장치를 직접 선택하거나 원래 장치를 다시 연결한다.
