# EXTREME-126 — 베타 통화 진단과 PCM16 공유 출력 지원

2026-10-30 / `codex/extreme-latency`, 기준 `ab9718a`.

## 관측과 한계

사용자가 제공한 두 진단(16:01:52 / 16:01:55)을 분석했다. 개인 원본·주소·닉네임·장치 식별자는 커밋하지 않는다. 약 12분의 1:1 통화는 UDP 직접 연결을 유지했고 수정 SDK와 네이티브 Opus를 사용했다. 양쪽 시계를 동기화하지 않았으므로 다른 PC의 사건 시각을 직접 빼거나 정확한 동시 사건으로 판정하지 않는다.

|지표|사용자 PC 수신|상대 PC 수신|
|---|---:|---:|
|RTCP RTT 표본 중앙값|15.87ms|15.60ms|
|재생 큐 표본 중앙값 / P95|27.96 / 53.98ms|30.17 / 47.35ms|

PLC 비율은 각각 디코딩+PLC 음성 시간 대비 약0.172% / 0.085%다. 패킷 개수의 PLC 비율이 아니다. RTT와 큐는 물리 입→귀 지연이 아니다. 최종 손실 보고0%는 마지막 RTCP 구간 값이므로 전체 무손실을 뜻하지 않는다. 상세 pipeline 기록은 비어 있어 송신·소켓·복호화·재생 마감을 패킷별로 연결할 수 없다.

사용자 PC 출력은 저지연 공유 경로(API 보고 약5.83ms), 상대는 믹스 형식 거부로 호환 경로(API 보고40ms)였다. 호환 플레이어가 보고한 최종 출력은44.1kHz float 모노지만 **이것은 거부 당시 장치 믹스 형식과 같다고 보장되지 않는다**. 기존 코드도44.1kHz float는 이미 지원하므로 샘플레이트 자체를 원인으로 확정하지 않는다. 진단 지연 모델 중앙값 약62/98ms 역시 음향 실측이 아니다.

## 변경

- `SharedRenderPlayer.AdaptSource`: 기존32bit float mono/stereo에 PCM16 mono/stereo 및 extensible PCM16 지원을 추가했다. 장치 믹스 형식과 엔진 주기를 그대로 사용하고, 필요한 리샘플링·채널 복제·PCM16 변환을 pull 경로에서 수행한다. 별도 큰 PCM 큐는 없다. 지원하지 않는24bit/다채널은 계속 호환 출력으로 돌아간다. 형식 거부 이유에 실제 믹스 형식을 포함한다.
- `AudioSendQueue`: 큐 초과로 버린 음성의 누적ms와 폐기 시 최대 나이를 기록한다. 용량 초과와 나이 제한 폐기를 구분한다. 초과 콜백에 상수 비용 카운터만 추가했고 패킷별 로그/새 할당은 없다. `CallForm` 상세 진단과 JSON에서 확인할 수 있다.
- 큐 용량3·스레드풀 송신·10ms 프레임·수신20ms 여유·출력 안전 복귀 정책은 유지한다.35개 폐기만으로 전용 송신이나 큐 확대가 더 낫다고 결론 내리지 않는다.

## 검증

- `RenderDeviceChecks.Targets`: 48kHz 모노 신호를44.1kHz PCM16 모노/스테레오/extensible 및48kHz float 스테레오로 실제 읽기 변환했다. 길이·샘플 형식·신호 RMS·스테레오 동일성을 검사한다. 기존 경로는 PCM16을 형식 검사에서 거부했지만 새 경로는 변환한다. 지원하지 않는24bit/6채널 거부를 확인한다.
- `DedicatedSenderChecks`: 정상 큐는 폐기 시간0, 두2.5ms 프레임 초과는5ms이며 폐기 나이가 기록되는지 확인한다. 나이 제한 폐기를 용량 초과 시간에 중복 합산하지 않는다. 기존 묶음 보존·RTP 시간축 회귀를 유지한다.
- 실행: `./native/verify.ps1 -NoRestore -Integration`. 원본 로그는 Git 제외 `native/.local/buildtools-migration/verify-126.log`에 보존한다.
- 결과: 경고0·오류0 빌드, BuildTools58검사, 제품/읽기 위치·송신·RTP/PLC·서버/자동 실행기 회귀, localhost IPv4/IPv6 ICE/DTLS/SRTP/RTCP 및 가변 프레임 통합 검사를 통과했다. 실제 장치 출력 검사가 아니라 변환/로컬 전송 회귀다.

## 남은 확인과 적용

상대 헤드셋의 실제 믹스 형식·지원 엔진 주기·RAW 지원과 새 경로의 장시간 연속성은 미실시다. 실제 게임/다른 회선/물리 입→귀 지연 비교도 미실시다. 합성 변환 성공을 장치40ms 감소나 끊김 해결로 표현하지 않는다.

소스 실행은 `./native/run.ps1`, 베타 생성은 `./native/build.ps1 -Beta -Package`다. 이번 작업에서 기존 dist·사용자 설정·공개0.6.1-beta.1 릴리즈는 교체하지 않는다. 장치 설정 변경 없이 지원 형식일 때 새 공유 경로를 시도하며 엔진 초기화 실패 시 기존 호환 경로로 복귀한다. 코드 변경 전 비교는 기준 커밋을 별도 체크아웃해 같은 장치·프레임·여유로 수행한다.
