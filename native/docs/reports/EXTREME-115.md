# EXTREME-115 — No-IP A 레코드 정상화와 공개 주소 회귀

한국 시각2026-10-28, `codex/extreme-latency`, HEAD `78ef68a`와109–114 미커밋 작업을 보존했다. 기존 Release 바이너리와 격리된 노트북 복사본을 사용했고 제품 오디오 알고리즘·기본값·기존 dist는 변경하지 않았다.

## 원인과 실제 변경

114에서 확인한 도메인/배포 주소 불일치를 사용자 계정의 No-IP 관리 화면에서도 확인했다. 사용자가 직접 로그인한 뒤 기존 호스트의 A 레코드 Content만 OCI의 공인 IPv4로 저장했다. TTL60초, 호스트 이름, 다른 레코드 및 계정 설정은 유지했다. 편집 화면의 Enable Dynamic DNS는 이미 해제 상태였고 변경하지 않았다.

저장 완료 후 UI의 A 레코드와 갱신 시각을 확인했다. PC·노트북·OCI의 DNS 결과가 모두 OCI 주소였고, 세 환경의 일반 `https://qlrpal.ddns.net/health` 요청은 인증서 검증을 유지한 채 HTTP200을 반환했다. `--resolve`, hosts 수정, HTTP 프록시, SSH 신호 포워딩, TURN URL/IP 대체를 사용하지 않았다.

이번 정상화는 운영 도메인의 실제 변경이다. 이전 값과 저장 화면은 Git 제외 원본에 보존했다. 정상 운영을 위해 새 값을 유지하며 이전의 잘못된 주소로 자동 복구하지 않았다. 호스트가 이전에 왜 집 주소로 갱신됐는지는 미확정이다. 다른 장치/계정 도구의 추후 재갱신 여부를 이번 단기 관측으로 보장하지 않는다.

## 시험 조건과 한계

실제 PC/노트북의 공유 WASAPI 입력·출력, 합성 음성 입력 교체, 기본10ms·네이티브 Opus·LowLatency 정책·수신 여유20ms·기존 출력으로 비교했다. 각 경로에 새 RunId를 사용하고 baseline30초 후 양방향 전달·음소거/해제·각자의 퇴장/재참가·정리6검사를 수행한다. 직접은 통화별 LAN 인터페이스 지정이며 중계는 ForceRelay로 실제 TURN 경로를 확인한다. 시스템 VPN/라우팅/방화벽은 변경하지 않는다.

SSH는 노트북 시험 프로세스 실행·보고서 수집에만 사용한다. 신호는 양쪽 모두 공개 HTTPS로 직접 요청하고 미디어도 신호 SSH를 통하지 않는다. 두 PC는 같은 집 회선이므로 친구의 외부 회선·게임 부하·물리 입→귀·장시간 품질을 대신하지 않는다.

## 결과와 판정

직접·강제 TURN 모두 양쪽 프로세스 종료 코드0, 자체 timeout 없음,6검사 성공과 양쪽 보고서 병합 pass였다.114의 재참가 HTTP 응답 중단은 이번 두 실행에서 재현되지 않았다. 이를 일반적인 HTTP 오류의 영구 해결로 단정하지 않는다.

| 수신 경로/호스트 | PLC 오디오 시간 / 관측 비율 | 늦은 폐기 | 캡처 불연속 | 새 RTCP RTT 중앙값 |
|---|---:|---:|---:|---:|
| 직접 / PC |30ms /0.101% |1 |0 |1.48ms |
| 직접 / 노트북 |0ms /0% |0 |3 |1.70ms |
| TURN / PC |85ms /0.285% |2 |0 |20.79ms |
| TURN / 노트북 |15ms /0.050% |0 |14 |21.78ms |

각 baseline은 약30초이고 양쪽 모든 구간의 재버퍼·PCM 공급 부족·렌더 empty·송신 폐기는0이었다. 남은 PLC·캡처 불연속을 무시하고 품질 완성으로 판정하지 않는다. RTT는 로컬 RTCP 보고이며 물리 입→귀 지연이 아니다. 직접→TURN은 경로 기능 확인이며 A/B/A 지연 최적화 대조가 아니다.

시험 후 TTL60초를 넘긴 시점에도 DNS는 OCI 주소, 일반 HTTPS health는200이었다. 자체 PC/노트북 시험 프로세스 잔류0을 확인했다. DNS 이외의 시스템/서버 설정 및 기본 장치는 수정하지 않았다. 운영 A 레코드는 정상 값으로 유지한다. 이번 변경은 DNS 및 문서뿐이므로 제품 빌드/Integration을 반복하지 않았으며 직전114의11개 Node 도구 회귀 통과 기록을 보존한다. 커밋·푸시는 하지 않았다.

## 원본과 재현

Git 제외 `native/.local/extreme-115`에 원본을 보존한다. `dns-pc.json`, `health-pc.txt`, `health-laptop.txt`, `oci-health.txt`가 일반 주소 도달성 기록이며 `noip-record.png`가 저장 후 관리 화면이다. `connectivity-results.json`은 양쪽 참가자 원본 위치와 실제 종료 코드 목록이다. 토큰·TURN 비밀값·계정 인증 정보는 이 문서나 Git에 저장하지 않는다.

일반 재현은 [두 PC 검사 가이드](../PAIR-CHECKS.md)의 동일 RunId·반대 역할, 공개 서버 주소에 `-Route direct/relay -ObserveSeconds 30 -ReserveMs 20 -MediaAddress LOCAL_IP -NoBuild`를 사용한다. 보고서 양쪽을 병합해 기능 성공을 확인한다. 기본 앱은 기존 공개 서버 주소 그대로 사용하며 이번 DNS 수정만을 위해 새 앱 배포가 필요하지 않다.
