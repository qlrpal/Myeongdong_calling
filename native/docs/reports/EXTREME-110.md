# EXTREME-110 · 두 PC 단계 동기화와 기능 판정

2026-10-28 / `codex/extreme-latency`. 109의 미커밋 로컬 검사 도구를 보존하며 실제 두 참가자 자동 검사를 추가했다. 일반 앱의 프레임·버퍼·출력 기본값과 운영 서버·라우팅·방화벽·장치 기본값은 바꾸지 않았다.

## 구현

- `PairFunctionalProbe`: 실제 공유 입력/출력, 합성 PCM, 양방향 송신·수신·디코딩 진행, 로컬 마이크 음소거/해제, 각 역할의 명시적 퇴장/재참가, 상대의 새 세션 관측, 최종 정리를 검사한다. UI와 같은 LowLatency 정책·10ms 프레임을 사용한다.
- `PairBarrier`: 기존 DTLS 데이터 채널에서 실행 ID·역할·설정/빌드/파형 식별·단계/확인을 교환한다. 단계 신호를 제한된 주기로 반복하고 로컬 단조 시계로 시간 제한을 적용한다. PC 시계의 차이를 빼지 않는다.
- `WebRtcCallEngine`: 진단 엔진에서만 활성화되는 제한된 제어 메시지 송수신 훅을 추가했다. 일반 앱은 콜백을 설정하지 않으며 별도 포트/서버나 패킷별 진단 로그를 추가하지 않았다. 진단 콜백은 미디어 콜백을 깨뜨리지 않도록 격리한다.
- `test-pair.ps1`/`pair-checks.mjs`: 한 PC의 실행·빌드·시간 제한·원본 보고서와 두 보고서 병합을 제공한다. 직접/강제 TURN, 기존/단일 출력 선택은 양쪽이 일치해야 한다.
- `pair-summary.mjs`: 한쪽 누락·불완전 검사·오류·역할/실행/빌드/파형/SDK 불일치는 실패. 같은 호스트 식별자는 로컬 기능이 성공해도 두 PC 판정은 incomplete다. 식별자는 컴퓨터 이름 해시이며 독립 하드웨어를 인증하는 수단은 아니다.
- `synthetic-fixture.mjs`: 로컬/두 PC 실행 도구가 동일한 합성 WAV 생성기를 공유한다.

마이크 PCM은 인코딩 전에 합성 파형으로 교체한다. 실제 목소리·세션 토큰은 보고서에 저장하지 않는다. 주소·장치 식별자가 있는 원본은 Git 제외 폴더에 보존한다. 설정·진단 파일을 사용자 배포 폴더에 섞지 않는다.

PairBarrier의 확인 왕복·중복/이전 단계·다른 실행/역할·설정 불일치 검사를 제품 검사에 포함했다. PowerShell/Node 구문과 `git diff --check`를 확인했다. 기능 성공은 송수신/디코딩이 진행된다는 뜻이다. PLC/늦은 폐기·재버퍼의 품질 기준은 판정하지 않으며, 큐·RTT를 물리 입→귀 지연으로 사용하지 않는다.

## 환경과 미해결

노트북은 기존에 승인된 SSH 접속으로 확인하고 고유한 사용자 임시 폴더에 시험 바이너리와 포터블 Node를 배치했다. Node/Pwsh가 기존 PATH에서 발견되지 않았으며 시스템 설치나 영구 PATH·실행 정책 변경은 하지 않았다. 기존 앱·dist는 덮어쓰지 않았다. 시험 폴더/초기 패키지는 재현용으로 보존했다. 양쪽 시험 프로세스가 남지 않았고 노트북 기본 입력/출력은 전후 동일했다.

노트북의 새 시험 실행 경로에 정확히 일치하는 활성 인바운드 규칙은0개였다. 이것만으로 Windows의 유효 방화벽 정책 전체나 직접 연결 실패 원인을 확정할 수 없다. 직접 연결 실패는 현재 미해결이며 물리 네트워크 조사를 재개하거나 허용 규칙을 임의로 추가하지 않았다. 초기 준비 실패/직접 실패 원본을 이후 TURN 통과로 덮지 않았다. 최종 LowLatency 코드로 실제 두 PC direct 성공은 확인하지 않았다.

독립 다인 PC, 게임 부하, 장시간 유지, 실제 장치 분리, 친구의 다른 회선, 물리 입→귀 지연은 미실시다. 같은 집에서 OCI TURN을 거친 성공을 다른 사용자 환경 전체의 성공으로 확장하지 않는다. 재참가는 명시적 Leave/Join이며 네트워크 단절 후 자동 복구와 구분한다.
