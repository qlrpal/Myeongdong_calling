# 직접 연결·TURN 비교와 공백 발생 구간

2026-10-21. 게임·개인 장치 효과 설정을 제외하고 두 PC에서 직접 → TURN → 직접 각 120초, OS 계측을 동반한 직접 연결 120초를 추가 시험했다. 유효 통화 측정은 양방향 합계 8분이다. 모든 회차는 고정 20ms, Opus LowDelay64 / 48kHz 모노 / 10ms, 표준 공유 입력·RAW 우선 공유 이벤트 출력을 사용했다. 동일 TTS PCM을 캡처 프레임 완성 후 인코딩 전에 반복 공급했다. 물리 마이크 음질·전체 입→귀 지연·청감 평가는 아니다.

## 확인한 위치

큰 직접 연결 공백은 **송신 API 이후부터 상대 RTP 수신 콜백 이전**에서 대부분 늘어났다. 같은 시간 출력 요청은 약 10ms 간격으로 계속 진행됐다. 이번 큰 공백을 코덱·재생 큐 정지로 설명할 근거는 없다. 이전 TURN 공백 기록에서도 같은 구간의 확장이 확인됐으므로 TURN만의 문제도 아니다.

| --- | ---: | ---: | ---: | ---: |

직접 A2 두 사건의 송신 큐 대기는 약 0.01/0.03ms, 송신 API 실행은 0.03/0.09ms, 수신 핸들러 전체는 0.01ms 미만이었다. 해당 구간 주변의 최대 출력 요청 간격은 노트북 10.46ms·PC 10.19ms, 최대 출력 읽기 작업은 0.16/0.06ms였다.

이 표는 송수신 양쪽에서 같은 SSRC·RTP 타임스탬프를 맞춘 뒤 **각 호스트 안에서 구한 간격끼리 비교**했다. 절대 시계를 서로 빼지 않으므로 약 13.6초의 시스템 시계 차이에 영향받지 않는다. 간격 추가 확장은 송신 이후 네트워크·상대 OS·소켓·WebRTC 수신 처리의 합이며 편도 네트워크 지연 자체가 아니다. 패킷 누락으로 원본 시간 간격이 20–40ms인 사건도 표에 명시했다.

## OS 네트워크 계측

노트북의 기존 SSH 관리자 세션에서 `Microsoft-Windows-Kernel-Network` 메타데이터만 180초·최대 32MiB 수집했다. 패킷 내용·음성은 수집하지 않았다. 실제 ETL 6,946,816바이트, 이벤트 손실 0, 자체 세션 정상 종료를 확인했다. 시험 PID 14752에서 원시 QPC UDPv4 이벤트 29,035개를 추출하고 실제 통화 주소·포트로 필터링했다. 분석 구간 전체의 송수신 이벤트 범위를 확인했다.

계측 회차에서는 큰 200ms대 공백 대신 30ms 이상 공백 5개가 잡혔다. 5개 모두 공백 사이 OS 수신 이벤트가 없었고 앱/OS 공백 경계 오차는 최대 0.157ms였다. 가장 큰 사건은 앱 45.549ms, OS 45.576ms였다. 같은 패킷 쌍의 PC 송신 완료 간격은 9.869ms, 수신 간격 추가 확장은 35.680ms였고 출력 요청은 약 10ms 간격으로 계속됐다.

따라서 **계측된 이 사건들은 OS UDP 이벤트 이전에도 공백이 존재**했다. 앱이 OS에서 전달받은 패킷을 디코더 큐 앞에서 수십 ms 붙잡은 형태와 다르다. 다만 ETW 이벤트는 NIC 하드웨어 도착 시각이 아니며 동일 주소·포트의 STUN/RTCP 등도 포함된다. AP·Wi-Fi 무선·NIC 드라이버·OS 처리 중 최종 원인을 분리한 것은 아니다. 큰 직접 연결 공백이 계측 회차에 재현되지 않았으므로 같은 원인으로 확정하지 않는다.

이 회차 측정 구간에서 추가 무음·재버퍼링은 양쪽 0이었다. 준비 중에는 이미 장애가 있었지만 예약 시작 전이라 앱 파이프라인 상세 기록에는 포함되지 않았다. 따라서 준비 구간 장애는 OS/앱 사건별 대조에서 제외한다.

## 수정과 검증

- 직접 경로 전용 진단 옵션을 추가해 시험 때 TURN 후보를 제외했다. 기존 자동 ICE 회차가 실제로 TURN을 선택한 경우를 직접 결과로 오인하지 않고 실패 처리한다. 일반 앱에서는 새 내부 옵션 기본값이 꺼져 있어 기존 직접 연결·TURN 우회 정책을 유지한다.
- 예약 경로 비교 및 단일 회차 명령을 추가했다. 노트북 시스템 시계 오차 13.43–13.80초를 재측정해 예약값만 14초 보정했다. OS 시계는 변경하지 않았다.
- `analyze_packet_gaps.py`를 추가해 RTP 쌍별 송신·수신 간격, 캡처 프레임 간격, 송신 큐·API, 수신 핸들러와 주변 출력 간격을 함께 출력한다. 불완전·다중 상대·동일 호스트 입력과 입력 덮어쓰기를 거부한다. 짝이 없는 수신 패킷도 보고한다. 부분적으로 어긋난 추적 시작·종료 경계의 패킷을 네트워크 손실로 세지 않는다.
- 합성 자료로 시계 오프셋 불변성·RTP 래핑·100ms 간격 확장·짝 없는 패킷·출력 진행 판정을 확인했다. 기존 OS 공백 분류 및 원시 QPC 정규화 자체 검사도 통과했다.
- 경고를 오류로 취급한 Release 빌드, 전체 정적 분석·회귀·서버 7개·실제 로컬 WebRTC/DTLS/SRTP·RTCP 통합 검사와 Python 구문 검사, `git diff --check`가 통과했다. 양쪽 시험 프로세스 잔류 0, ETW 정상 종료 코드 0을 확인했다.

첫 자동 ICE 시험은 TURN이 선택돼 무효 처리했다. 초기 ETW 변환은 원시 시각 옵션과 요약 옵션의 동시 사용이 거부돼 각각 따로 변환했다. 유효 분석은 재변환 후 원시 QPC만 사용한다.

확인된 앱 내부 병목이 없으므로 네트워크 공백을 숨기기 위해 제품 버퍼·PLC·재생 속도 한도를 임의로 변경하지 않았다. 기본 고정 20ms 및 자동 저지연 시험 모드를 유지한다. 남은 최종 원인은 NIC/무선 이전·이후의 동시 계측 없이는 확정할 수 없다.
