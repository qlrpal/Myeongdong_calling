# EXTREME-130 — 사건 ID 협조·통화 중 재준비·분석 상태

2026-10-31 / 기준 `baadb47`에 미커밋129의 조기 동결 수정을 유지하고 구현했다. 커밋·푸시·공개 릴리즈 교체는 이번 작업 범위에 없다.

## 구현

- `IncidentProtocol`/`IncidentPeerLink`: 기존 암호화 데이터 채널로 지원 확인, GUID 사건 알림, accepted/linked/busy/not-ready 응답을 교환한다. 크기384바이트·상대별1초 제한·질의/알림3회 상한·늦은 응답 거부를 둔다. 음성/주소/토큰은 추가 전송하지 않는다.
- `IncidentRecorder`: 미리 준비한 사건 ID로 로컬 사건을 표시한다. 원격 요청은 인증된 음성 수신과 워밍업 조건을 지켜 수집하고, 이미 인접 구간을 기록 중이면 ID를 연결한다. 오래된 동결 기록은 덮어쓰지 않는다. 실시간 쓰기는 값 형식·고정 배열·TryEnter를 유지한다.
- `WebRtcCallEngine.Incidents`: 오디오 콜백 대신 기존 GetDiagnostics 경로에서 알림을 보낸다. 종료한 상대의 응답도 제한적으로 보존한다. 재준비는 세션 gate로 퇴장/종료와 직렬화하고, 최근2개 캡슐과 당시 상대 상태를 보관하며 상한 축출 수를 보고한다. 오래된 라운드 알림은 새 라운드를 덮어쓰지 않는다.
- `CallForm`: 이 PC 기록 다시 준비 버튼, 상대 지원/확인·누락 상태, 복사/저장 시 경계 존재와 상대 파일 필요 여부를 표시한다. JSON은 현재 incident와 incidentDetails의 이전 캡슐/상대 상태/Review를 포함한다.
- `PairFunctionalProbe`: auto/off/exercise 시험 모드를 프로세스 한정 환경 변수로 지원하고 설정 핸드셰이크에 포함한다. 기록 활성 표본 비율·기준선 자료와 실제 재준비/ID 수락/기존 자료·같은 피어 유지 검사를 보고한다.

프레임·Opus·수신/출력 여유·미디어 경로·SDK 보안 정책·시스템 설정은 변경하지 않았다. `PeerConfirmations`는 상대 파일 확보를 뜻하지 않는다. 공통 ID도 같은 물리 원인이나 양쪽 시각 동기화를 보장하지 않는다.

## 회귀와 시험 중 발견

전체 verify Integration을 통과했다. 최종 추가 보호/설명 뒤 경고0·오류0 빌드와 기록/프로토콜 검사를 재실행했다. 기록10만 회1.80ms·관리형 할당0bytes, Opus 입장/읽기1만 쌍의 끔/켬/끔104.31/104.73/106.00ms·동일PCM·부족0이었다. 미세 벤치마크이지 계측 비용0 또는 실제 지연 감소의 증거가 아니다.

노트북의 같은 빌드로 독립 두 PC의 기록 꺼짐60초를 완료했다. 기록 켬 시험 중 통화 상태 공유가 끊기고 SSH가 reset됐다. 이후 SSH 초기 응답이 오지 않았고 Tailscale에서도 오프라인이었다. 이 실행은 실패로 보존하며 독립 두 PC A/B/A 완료로 표현하지 않는다. 사용자에게 절전/네트워크 확인을 요청했다.

PC의 두 프로세스로 검증을 이어가며 새 검사 단계 이름이 PairBarrier 허용 목록에 빠져 있음을 발견했다. incident-rearmed/incident-confirmed를 추가하고 전체 허용 단계의 왕복 회귀를 보강했다. 수정 후 같은 호스트의 실제 공유 장치/암호화 통화에서 재준비·ID·수락·동결·과거 기록·피어 유지와 기능6검사를 양쪽 모두 통과했다. 같은 호스트 성공은 독립 PC 성공이 아니다.

## 노트북 재개 후 독립 두 PC 결과

사용자가 노트북을 다시 켠 뒤 SSH/장치를 확인했다. 중단된 임시 시험 폴더를 먼저 원본으로 복구한 다음, 별도 `native/.local/extreme-130-resumed/`에서 같은 최종 빌드로 새 실행 ID를 사용했다. 자체 원격 제어 스레드에만 일시적인 시스템 실행 요청을 두고 finally에서 해제했다. 전원 계획·장치·라우팅 설정은 변경하지 않았다.

최종 독립 두 PC의 직접 off→exercise→off 각60초와 TURN exercise60초는 **모두 양쪽6개 기능 검사와 병합을 통과**했다. exercise 구간은 기준선 뒤 통화를 유지한 채 재준비하고, 이전 자료/상대 상태1개 보관, 공통 사건 ID, 수락1/1, Frozen 및 송신·수신·재생·전후 경계 존재를 확인했다. 직접/TURN 각각 양쪽 사건 ID 집합에 공통 ID1개가 있었고 피어 ID는 바뀌지 않았다.

### 자연 발생 사건의 실제 양쪽 연결

직접 기록 켬 기준선에서는 자연적인 양방향 수신 공백이 발생해 양쪽이 각각 로컬 사건을 만들었다. 양쪽 보고서에 서로의 ID가 연결돼 ID 집합 교집합2개를 얻었다. PC의462개 수신 콜백은 모두 노트북의 동일 SSRC/RTP 타임스탬프 송신 API 관측에 대응했다. 노트북575개 중462개도 반대쪽 보존 구간에 대응했다. 수집 창/누락이 달라 미대응을 손실로 판정하지 않는다.
