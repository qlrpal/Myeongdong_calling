# EXTREME-081: 자동 프레임 연속성 평가와 송수신 재현

2026-10-22. [080](EXTREME-080.md)의 외부 통화 부족·폐기 관측에 따른 보완.

## 변경

자동 프레임 피드백에 누적 `UnderfillMs`와 `RecoveryDiscardedMs`를 추가했다. 예전 클라이언트가 이 값을 제공하지 않으면 자동 제어를 정지하고 현재 프레임 길이를 유지한다. 기존 음성 통신과 텔레메트리 버전은 호환된다. 양쪽 최신 빌드가 필요하다.

3초 창에서 PLC 비율·지연 패킷 비율 외에 공급 부족/벽시계 시간과 복구 폐기/벽시계 시간을 별도 평가한다. 두 값은 중복될 수 있어 더하지 않는다. 부족 또는 폐기 0.5% 초과도 악화 창으로 취급한다. 시험 전환 후 어느 성분이 기준보다 0.05%p 이상 악화하면 첫 창에서 복귀한다. 두 시험 창 평균의 최대 압력이 10% 이상 개선되지 않아도 복귀한다. 실패한 긴 프레임 재시도는 60초 제한한다. 정상 단축 조건은 유지하며 추가 고정 버퍼는 넣지 않았다. 짧은 창의 휴리스틱이지 외부망 원인의 증명은 아니다.

정책 회귀에는 PLC만 감소하고 부족·폐기가 늘어나는 경우, 실패 재시도 제한, 누락된 확장 피드백, 음수 카운터 거부, 조용한 구간 단축을 추가했다.

수신 진단은 다음 필드를 추가한다.

- `LastPacketDurationMs`: 최근 유효 최신 패킷의 실제 Opus 길이. 기존 PacketQuantumMs는 최소 PLC 단위이므로 현재 패킷 길이와 다르다.
- `LastTimestampStepMs`: 최신 전진 패킷 사이 RTP 타임스탬프 차이.
- `ForwardTimestampGapMs`: 이전 최신 패킷 끝보다 새 패킷이 앞서는 간격의 누적. 손실·재정렬·송신 시간축 공백 모두 가능하며 순수 네트워크 손실 카운터가 아니다.
- `PacketDurationChanges`: 유효 최신 패킷의 길이 변경 횟수. 재동기화로 시간축이 끊긴 구간의 변경을 모두 복원하지는 못한다.

송신의 누적 샘플 타임스탬프 계산을 공통 함수로 추출하고 실제 엔진과 통합 시험이 같은 함수를 사용하게 했다.

## 재현과 한계

`--variable-frame-integration`에 실제 WindowsAudioDevice 캡처 조립→실제 Opus 인코딩→앱의 송신 메타데이터/타임스탬프 함수→ICE/DTLS/SRTP→RTP 수신 재생 버퍼→10ms 재생 요청 검사를 추가했다. 2.5/5/10ms와 복귀를 반복하고 uint RTP 순환 경계도 통과한다. 총 27초 미디어 시간, 6316패킷에서 길이/타임스탬프 일치와 PLC·부족 0을 확인했다.

이 시험은 수신 도착 완료 뒤 가상 장치 요청을 진행하는 결정적 검사다. 실제 마이크/스피커를 열거나 외부망 손실·게임 스케줄링을 재현하지 않는다. 따라서 080의 약 50% PLC 구간 원인을 찾았거나 외부 통화 끊김 전체를 해결했다고 판정하지 않는다. 잘못된 성공 판정 가능성을 보완하고 전환 자체의 기본 경로를 검사한 결과다.

원본 진단·dist·서버·OS 설정은 변경하지 않았다. Release 빌드 경고·오류 0, 전체 회귀·서버8개·IPv4/IPv6 미디어 통합을 통과했다. 공통 RTP 함수 추출과 진단 필드 최종 보완 뒤에도 빌드·송신 큐·RTP 재생·제품 검사·실제 캡처/SRTP 반복 전환 검사를 다시 통과했다. 실행 로그는 Git 제외 `.local/extreme-081-verify.log`, `.local/extreme-081-final.log`에 보존한다.

## 다음 실제 통화

양쪽 앱을 최신 소스로 다시 실행해 같은 방에서 자동 구성으로 통화한다. 이상이 있으면 나가기 전에 양쪽 JSON을 저장한다. 기존 구성과의 비교는 별도 통화에서 고정 `opus-adaptive-5`로 하고, 동시에 장치·라우팅 설정을 변경하지 않는다. 정확한 전환 원인 분리에는 상세 파이프라인 기록 또는 제어된 손실 대조가 추가로 필요할 수 있다.
