# 극저지연 입력 주기·재생 여유 대조

2026-10-21, `codex/extreme-latency`. 실제 PC와 노트북에서 합성 음성을 실제 공유 입력 콜백으로 공급하고 WebRTC/SRTP와 강제 TURN을 통해 전송했다. 장치 시스템 설정은 변경하지 않았다. 각 시험은 15초이며 아래 값은 약 14.8초 간격의 첫/마지막 진단 스냅샷 차이다. 준비 구간 누적값을 제외했다.

## 결과

| 조건 | PC 수신 부족 / 보간(ms) | 노트북 수신 부족 / 보간(ms) | 노트북 입력 불연속 증가 |
| --- | --- | --- | --- |
| 이전: Opus 2.5ms, 여유 2.5ms, 절대 최소 입력 | 6276 / 2950 | 345 / 5655 | 1884회 |
| Opus 2.5ms, 여유 2.5ms, 지원 5ms 기준 입력 | 808 / 3435 | 590 / 1043 | 0회 |
| Opus 2.5ms, 여유 10ms, 지원 5ms 기준 입력 | 91 / 708 | 0 / 20 | 0회 |
| PCM 1ms, 여유 10ms, 지원 5ms 기준 입력 | 67 / 934 | 0 / 0 | 0회 |

부족은 요청한 PCM 중 채우지 못한 시간이고, 보간은 실제 패킷 대신 생성한 시간이다. PCM의 보간은 무음이다. 두 항목을 실제 마이크→귀 지연으로 해석하거나 합산하면 안 된다. 시험은 순차적으로 수행했으므로 무선망 변동과 실행 순서의 영향을 통제한 반복 실험은 아니다.

## 확인한 사실과 해석

이전 노트북 입력은 1.33ms 엔진 주기에서 다수의 불연속 플래그를 보고했다. 송신 RTP 시간은 약 15.3초 동안 약 10초만 진행했다. 앱은 불연속 시 조립 중인 부분 프레임을 폐기하므로, 장치 경로의 불연속과 앱의 조립 초기화가 함께 송신 오디오 부족에 영향을 줄 수 있다. 플래그만으로 드라이버 내부 결함이나 손실 위치를 확정하지 않았다.

입력을 5.33ms 주기로 바꾼 대조에서는 불연속 증가가 0회였고, 송신 RTP 시간도 실제 시간과 거의 같았다. PC 입력은 10ms였다. 따라서 짧은 패킷 크기와 장치 입력 주기는 별개이며, 무조건 절대 최소 주기를 선택하는 것은 이 환경에서 유리하지 않았다.

입력 조건을 유지하고 여유만 10ms로 늘렸을 때 양쪽의 부족과 보간이 줄었다. 현재 2.5ms/0ms 여유는 장치의 입력 묶음·재생 요청과 네트워크 도착 변동을 감당하기 어렵다는 근거다. PCM과 Opus의 결과는 방향별로 엇갈려 우열을 확정할 수 없다. PCM은 패킷 빈도와 전송량이 크며, 이번 시험에서 Opus보다 좋은 전체 지연을 입증하지 못했다.

## 반영

- 실험 프리셋에서 절대 최소 입력을 기본 요청하지 않도록 수정했다. 약 5ms 기준 입력과 기존 호환 복귀를 사용한다. 안정 기본 모드는 변경하지 않았다.
- `opus-2.5-r10` 프리셋을 UI와 실행 스크립트에 추가했다. 실행: `./native/run.ps1 -Experiment opus-2.5-r10`.
- 5.33ms 입력 묶음과 약 10.17ms 출력 요청을 독립적으로 진행시키는 3초 모사 검사를 추가했다. 2.5ms 패킷·10ms 여유에서 부족/PLC 없이 통과했다. 이는 네트워크 품질 보장이 아니다.
- 시험 도구 콘솔은 누적값 대신 측정 스냅샷 구간의 증가량을 출력하고, 연결·전송 검사 통과를 `FUNCTIONAL PASS`로 명시한다.

원시 결과: Git 제외 경로 `native/.local/extreme-062/`의 `pc-c5.json`, `laptop-c5.json`, `pc-r10.json`, `laptop-r10.json`, `pc-pcm.json`, `laptop-pcm.json`. 이전 비교 자료는 `native/.local/extreme-061-r2/*opus-r3-call.json`.

최종 검증: Release 빌드 경고·오류 0개, `verify.ps1 -NoRestore -Integration` 전체 통과. 서버 8개 검사와 실제 로컬 WebRTC/RTCP/암호화 음성 회귀를 포함한다. 최초 제한 환경 실행은 localhost 연결 EACCES로 중단되었으며, 로컬 네트워크 권한으로 재실행하여 통과했다. 노트북 시험 프로세스는 종료됐다. 커밋·푸시와 배포본 교체는 하지 않았다.

## 남은 검증

현재는 실험 후보이며 배포 기본값으로 승격하지 않는다. 동일 조건의 안정 모드 대조와 반복 시험, 직접 연결 대조, 실제 입력→출력 지연 측정이 필요하다. PC 수신에서 남은 늦은 패킷·보간은 입력 수정만으로 해소되지 않았다. 다음 조사는 패킷 도착과 재생 마감의 관계를 재현해 여유를 더 낮출 수 있는 범위를 찾는 것이다.
