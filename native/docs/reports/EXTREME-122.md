# EXTREME-122: 게임용 마이크 토글 단축키

2026-10-29 / `codex/extreme-latency`. 통화 중 창 전환 없이 마이크를 전환하는 선택 기능을 추가했다. 게임 소리와 함께 쓰는 WASAPI 공유 모드·오디오 지연/버퍼·코덱·전송 정책은 바꾸지 않았다.

## 동작과 구현

- `MicrophoneHotkey.cs`: Windows `RegisterHotKey`와 `MOD_NOREPEAT`를 사용한다. 키보드 훅·폴링·추가 작업 스레드/타이머를 사용하지 않는다. [Microsoft RegisterHotKey 문서](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey).
- 기본은 `사용 안 함`. Ctrl+Alt+M / Ctrl+Shift+M / Alt+Shift+M을 제공한다. 사용자가 고른 조합을 통화 중에만 등록하고, 등록 실패 코드와 다른 조합 선택 안내를 표시한다. 같은 상태를 매 진단 갱신마다 재등록하거나 충돌 조합을 계속 재시도하지 않는다.
- `CallForm.Hotkey.cs`: 유효한 WM_HOTKEY에서 기존 마이크 체크 상태를 전환한다. 엔진 음소거·설정 저장·기존 상대 상태 공유 경로를 그대로 사용한다. 토글 동작은 메시지를 받은 UI 스레드에서 처리한다.
- 선택 변경·나가기·종료·창 핸들 종료 때 등록을 해제한다. 재등록마다 새 ID를 사용해 이전 설정/통화에서 큐에 남은 알림을 거부한다. 해제 실패 시 새 조합을 중복 등록하지 않고 입력을 비활성화한다. 창 핸들을 다시 만들면 새 등록이 필요하다.
- `UserSettings`: 선택을 저장한다. 기존 파일은 기본 꺼짐이며 알 수 없는 값은 다른 사용자 설정을 보존한 채 꺼짐으로 정규화한다.
- 설정 패널에 선택 목록과 상태 안내를 추가했다. 아래 버튼은 스크롤로 접근할 수 있다. 기본 크기 렌더링에서 글자·조작부 배치를 확인했다.

## 검증

- Release 정적 분석/빌드: 경고 0, 오류 0.
- 제품 회귀: 새 단축키 상태 검사와 기존 오디오/설정/통화 수명 검사 통과. 비활성/대기, 자동 반복 억제 플래그, 등록 중복 방지, 충돌 유지/재시도, 선택 변경, 이전 통화 메시지, 해제 실패, 창 수명, 새 설정/구버전 설정 호환성을 검사했다.
- 실제 Windows 등록 검사: 임시 Ctrl+Alt+Shift+F24로 숨겨진 시험 창의 등록 → 다른 창의 충돌 1409 → 해제 → 다른 창 재등록을 통과했다. 등록과 해제는 finally에서 정리했다. 사용자 설정·실제 키 입력·오디오 장치·서버는 사용하지 않았다.
- 같은 시험 창에 주입한 WM_HOTKEY가 등록 중에는 처리되고 해제 뒤에는 처리되지 않는 것을 확인했다. 이는 물리 키 입력이나 실제 게임 호환성 검증이 아니다.
- 진단 읽기 위치 30회 갱신 회귀 통과. 설정 화면 PNG를 확인했다.

첫 native 검사는 샌드박스에서 접근 거부 5로 실패했다. 같은 명령을 제한 밖에서 실행해 통과했으며 사용자 앱에 관리자 권한을 요구하는 기능으로 구현하지 않았다. 최종 원본은 Git 제외 `native/.local/ui-polish-20261029/hotkey-*`와 `native/.local/hotkey-20261029/`에 보존한다.

실제 게임 포커스 상태의 물리 단축키·게임 부하·독립 PC 통화·물리 입→귀 지연 시험은 미실시다. 새 지연 감소나 게임 호환성 완료를 선언하지 않는다. 키 상태는 로그에 기록하지 않고, 단축키로 바꾼 마이크 켬/꺼짐 이벤트만 기존 로컬 로그에 남긴다.

## 실행·복귀

`./native/run.ps1` → 설정 → 마이크 토글 단축키에서 선택한다. 등록 충돌이면 다른 조합을 선택한다. `사용 안 함`으로 바꾸면 해제된다. 기존 배포 dist·서버를 수정하지 않았고 커밋/푸시는 하지 않았다.

빌드 후 `TransportProbe.exe --microphone-hotkey-checks`로 순수 상태 검사와 실제 Windows 등록 검사를 함께 실행한다. 임시 시험 조합이 이미 점유됐거나 등록 권한이 없으면 실패로 남긴다. 일반 `--product-checks`에는 실제 전역 키 등록 없이 순수 상태/설정 검사만 포함한다.
