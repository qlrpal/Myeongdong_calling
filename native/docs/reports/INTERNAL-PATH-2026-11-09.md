# 내부 수신→출력 경로 재측정

2026-11-09. 기존 `--render-presentation-device` 검사기를 현재 PC에서 실행했다. 앱 소스·기본값·운영 배포·시스템 설정을 변경하지 않았다. 기존 미커밋 계획/검토 문서는 보존했다.

## 측정 범위

같은 호스트에서 미리 인코딩한 native Opus LowDelay64/10ms 패킷을 RTP 버퍼에 입장시키고, 렌더 PCM의 같은 내용 위치를 인접한 IAudioClock 관측 사이에서 보간했다. 고정 수신 목표20ms, WASAPI 공유/RAW GameChat, 실제48kHz float32 stereo, 장치 주기2.667ms. 기본 출력은 Realtek 헤드폰이었다.

입력/프레임 조립/실시간 인코딩/송신 큐/UDP·SRTP/네트워크/물리 DAC·귀는 제외한다. 미리 디코딩한 PCM 참조이므로 코덱 내용상 lookahead도 제외한다. 검사기 관측 부담은 포함하며 관측을 끈 대조는 이번에 미실시다. 장치 스트림 시계의 정확도를 외부 음향으로 검증하지 않았다.

기존 검사기는 추가 출력 여유 인자5→3→5ms를 각32초 신호로 비교한다. 실제 적용 목표 패딩은 장치 용량 제한으로5.833→5.667→5.833ms였다. 명목 인자 차이2ms를 실제 패딩 차이2ms로 해석하지 않는다. 총 시험 시간에는 장치 준비와 사후 분석이 추가된다.
