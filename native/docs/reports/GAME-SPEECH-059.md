# 0.5.9 지속 발화·게임 공존 10분 시험

2026-10-20 KST 00:55–01:05, PC에서 Monster Hunter Wilds를 실행한 상태로 PC·노트북 사이에 합성 발화를 600초씩 송수신했다. 양쪽 정상 종료, 버퍼 부족·재버퍼·송신 큐 폐기0이었다. 노트북의 출력 안전 복귀1회는 재현됐다. 이는 통화 경로의 진행·부하 시험이며 전체 입→귀 지연이나 청감 검증은 아니다.

## 방법

앞선 [2분 시험](GAME-LOW-DELAY-059.md)은 조용한 입력이 많아 지속 발화 부하를 충분히 확인하지 못했다. 이번에는 Windows 내장 TTS로 생성한 약32.4초의 영어 문장을 반복했다. 양쪽 모두 48kHz 모노16bit PCM WAV를 시작 전에 메모리에 읽었다. 실제 WASAPI 마이크 캡처·프레임 조립은 유지하고, 인코딩 직전에 PCM을 합성 발화로 교체했다. 파일 읽기·TTS 생성은 시간 측정 구간 밖에서 실행했다.

따라서 캡처 스케줄링과 불연속은 관측하지만 마이크 하드웨어·노이즈 제거가 음성에 미치는 영향은 제외된다. WAV는 합성 음성만 포함하며 실제 마이크와 수신 음성을 저장하지 않았다. 정상 앱 실행에는 PCM 교체가 활성화되지 않는다.

Opus LowDelay64 / 10ms, 고정20ms 예비량, RAW 우선 WASAPI 공유/이벤트 출력을 유지했다. LAN 주소를 소켓에 지정한 직접 연결이며 TURN은 사용하지 않았다. 게임·오디오 설정과 노트북 DTS 등록은 변경하지 않았다. 게임 PID 22880은 준비 시 CPU 누적1439.52초, 중간2009.19초, 후반3168.86초로 진행했다. 게임의 그래픽 설정·GPU 부하·FPS는 측정하지 않았다. 시험 중 빌드나 파일 전송은 하지 않았다.

## 이전 시험과 비교

노트북 출력 안전 복귀는 첫 진단 후 약14초에 관측됐다. 이후 제한 공급을 해제한22ms 전체 용량으로 계속 재생했고 RAW는 유지됐다. 앞선2분 시험에서도 안전 복귀1회가 있었으므로 지속 발화에서 새로 나타난 현상은 아니다. 별도 회차·별도 부하이므로 발생 시각 차이로 원인을 추정하지 않는다. 현재 안전 복귀는 장치 정지·재시작과 구분한다.

PC 입력 불연속 누적은 첫·마지막 모두1회였다. 노트북은3→4회였으며 증가는 첫 진단 후 약1초에 관측됐고 나머지 구간에는 추가 증가가 없었다. 앞선2분 시험의 중간 입력 불연속3회가 이번에는 같은 형태로 재현되지 않았다. 입력 시각 오류는 양쪽0이다. 캡처 콜백 간격 최대 관측값은 PC19.68ms, 노트북20.88ms였다.

수신 간격 최대 관측값은 PC66.45ms, 노트북62.63ms였다. PLC가 발생했으므로 모든 패킷이 재생 기한에 맞게 도착했다고 주장할 수 없다. 한 번의 LAN 시험으로 게임·Wi-Fi·스케줄러 중 원인을 분리하지 않는다. 출력의 안전 복귀와 수신 공백이 같은 사건인지도 현재 표본으로 확정하지 않는다.

## 판단과 다음 단계

지속 발화 부하에서도10분 동안 큐가 누적되거나 통화가 정지하지 않았으므로 현재 코덱·예비량·안전 복귀 기본값을 유지한다. PC는15.17ms 제한 공급을 유지했고 노트북은22ms로 복귀했다. 양쪽이 항상15ms로 동작한다고 안내하지 않는다. 장치 효과 제거 없이도 이번 경로는 진행됐지만 물리 장치 지연을 검증하거나 제거한 것은 아니다.

다음 제품 검증은 실제 외부망의 직접 연결·TURN 경로다. 외부 참가자 없이 LAN 결과를 원거리 성능으로 대체하지 않는다. 노트북 출력 복귀의 추가 조사는 별도 과제로 남기며, 무음 부족이 없다는 이유로 안전 복귀를 제거하거나 지연 목표를 위해 버퍼를 무조건 줄이지 않는다. 음질 청감과 전체 입→귀 지연도 별도 검증이 필요하다.

## 구현·재현·정리

`--bound-speech-soak`은600초 고정 시험으로, 합성 발화 WAV를 전부 읽어 검증한 뒤 실제 캡처 프레임마다 연속 교체한다. 진단 JSON의 `speechFixture`에 입력 교체 여부·샘플 수를 표시한다. 별도 지연 신호 측정과 동시에 사용하지 않는다.

```powershell
TransportProbe.exe --bound-speech-soak SERVER ROOM OUTPUT.json pc PC_LAN_IPV4 SPEECH.wav
TransportProbe.exe --bound-speech-soak SERVER ROOM OUTPUT.json laptop LAPTOP_LAN_IPV4 SPEECH.wav
```

WAV 조건은48kHz·모노·16bit PCM·1–120초이며 조용한 파일을 거부한다. Windows 내장 `SAPI.SpVoice`와 `SAPI.SpFileStream`의48kHz16bit모노 형식으로 합성했다. 문장 반복 경계에는 자연 발화와 다른 패턴이 생길 수 있다.

Release 빌드 경고0·오류0. 합성 프레임 연속성·기존 순수 회귀·서버7개·실제 ICE/DTLS/SRTP/RTCP·RTP 재생 통합 검사 통과. 최초 제한 환경의 서버 검사에서는 localhost 연결 EACCES가 발생해 호스트 네트워크 권한으로 전체 검사를 다시 실행했고 통과했다. `git diff --check` 통과.

원본·분석·합성 WAV는 Git 제외 경로 `native/.local/game-speech-059/`에 보관한다. 시험 후 양쪽 진단 프로세스 잔류0을 확인했고 게임은 종료하지 않았다. 시스템 오디오 설정 변경이 없어 복구할 변경도 없다. Git 커밋·푸시·배포 ZIP 생성은 하지 않았다.
