# EXTREME-079: 수신 상태 기반 프레임 전환과 선택적 실행 옵션

2026-10-22 / codex/extreme-latency. 지연 우선 실험이며 기본 구성 승격 보고서가 아니다.

## 적용 내용

새 `opus-auto-frames`는 2.5ms로 시작하고, 호환되는 수신자의 PLC 시간과 지연 폐기 피드백을 보고 5ms→10ms를 제한적으로 시험한다. 직접/TURN이라는 경로 이름만으로 프레임을 늘리지 않는다. 기존 `opus-adaptive`와 기본 실행은 유지한다.

- 3초 관측창에 미디어 1초 이상·수신 100패킷 이상이 필요하다. PLC 시간 비율 1% 초과 또는 지연 패킷 비율 0.5% 초과가 두 창 연속이면 한 단계 늘린다.
- 시험 두 창 뒤 압력이 10% 이상 감소하지 않으면 이전 단계로 복귀한다. 이 비교는 짧은 휴리스틱이며 인과관계의 증명은 아니다.
- 변경 뒤 일반 재변경은 15초 기다리며, 압력 0.1% 이하가 30초 지속되면 짧은 프레임으로 돌아간다. 실패 시험의 복귀는 대기보다 우선한다.
- 현재 자동 제어는 연결 상대 1명일 때만 동작한다. 다자 통화·지원하지 않는 상대·3초 넘게 오래된 피드백·출력 비정상이면 현재 길이를 유지한다. 그룹 합의 제어는 미구현이다.
- 기존 UI 진단 폴링이 피드백과 정책 평가를 구동한다. 엔진을 별도 호스트에서 사용할 때도 `GetDiagnostics` 호출이 필요하다.

캡처 프레임 저장소는 120/240/480샘플을 미리 만들고 완성된 프레임 경계에서만 전환한다. RTP 시간은 고정 패킷 번호 곱셈 대신 누적 샘플 위치로 계산해 길이 전환·송신 폐기에도 시간축을 보존한다. 파이프라인 기록에도 실제 샘플 수와 누적 위치를 추가했다. 수신 여유 하한은 최근 유효 패킷 길이를 반영한다.

## 추가 옵션과 진단

- MMCSS: 캡처 `ProAudioCapture`, 작업 스레드 `CriticalAudioPriority`를 시험 JSON에서 선택한다. 등록 결과·실패 코드를 진단에 기록하며 작업 종료 시 해제한다. 기본값은 모두 false다. 전체 시스템 우선순위 설정은 바꾸지 않는다.
- ReadyToRun: `./native/build.ps1 -ReadyToRun -StageOnly`. win-x64, 프레임워크 종속 출력이며 RID 잠금 파일을 격리한다. 기존 dist를 바꾸지 않는다. 코드 크기 증가와 일부 JIT 잔존이 있으며 시작 시간 개선량은 측정하지 않았다.
- IPv6: 미디어 목록에서 실제 로컬 전역/ULA 주소를 선택할 수 있다. 주소군별 인터페이스 바인딩과 후보 주소군을 진단한다. 링크 로컬 주소는 범위 지정 문제로 제외했다. IPv6 루프백 통과는 공인 IPv6 연결 보장이 아니다.
- TURN: 선택된 후보 프로토콜은 클라이언트→TURN 서버 구간의 UDP/TCP/TLS 증명이 아니다. 설정 URL의 transport와 실제 전송 계측을 구분한다. `server/deploy/inspect-turn.sh`는 coturn 서비스 전체 CPU·메모리를 읽기만 한다. 계정별 부하·400pps 용량 판정 도구가 아니다.

## 검증

Release 빌드 경고/오류 0. 전체 `verify.ps1 -NoRestore -Integration` 통과: 관리형 회귀, 서버 8개, 실제 IPv4·IPv6 ICE/DTLS/SRTP/RTCP, 2.5/5/10ms 혼합 패킷 전송·디코딩을 포함한다. 마지막 파이프라인 진단 필드 추가 뒤에는 빌드·파이프라인·송신 큐·제품 검사를 다시 통과했다.

자동 정책의 악화→시험→복귀, 조용한 구간 복귀, 오래된 피드백·카운터 초기화를 결정적으로 검사했다. 실제 캡처 메서드에 부분 프레임을 공급해 이전 프레임 완성 뒤 길이가 바뀌는 것도 검사했다. 실제 장치와 같은 PC의 두 엔진으로 자동 프레임/우선순위 구성을 각각 15초 시험했다. 오류·무효 패킷·송신 폐기·출력 버퍼 부족 증분은 모두 0이었다. 자동 구성은 양쪽 피드백 지원을 확인하고 2.5ms를 유지했다. 실제 통화에서 강제 악화로 자동 전환을 유발한 시험은 아니다.

MMCSS 선택 시험에서는 캡처 Pro Audio와 캡처/렌더 CRITICAL 등록 성공을 확인했다. 이 짧은 기능 시험으로 우선순위가 성능을 개선했다고 결론 내리지 않는다.

ReadyToRun 출력의 PE 네이티브 헤더를 확인했고 해당 DLL을 로드한 제품 검사도 통과했다. 당시 DLL은 약 1,036KB, 일반 DLL은 약 410KB였다. 마지막 진단 필드 추가 전 빌드의 비교이며 시작 지연 수치는 없다.

현재 공개 TURN 설정은 UDP이며, OCI coturn 읽기 전용 2초 관측에서 active·약 12MB와 CPU 약 0.000273코어를 확인했다. 이는 유휴 구간의 서비스 합계이고 짧은 프레임의 부하 검증이 아니다. 서버 설정·서비스·방화벽을 변경하지 않았다.

원본 로그와 격리 출력은 Git 제외 `.local/extreme-079/`와 `.local/publish-*`에 있다. 기존 배포본·공유기·시스템 라우팅은 유지했다.

## 다음 검증

서로 다른 두 PC의 실제 자동 전환, 장시간 직접/TURN 통화, 게임 부하, 다자 송신과 입퇴장을 확인한다. 기존 TURN 연속성 실패를 이번 기능 검사로 해결 판정하지 않는다. 최단 입→귀 지연이나 모든 환경의 안정성을 보장하는 결과는 아니다.
