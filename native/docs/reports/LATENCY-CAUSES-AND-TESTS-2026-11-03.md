# 지연 구간·예상 원인·시험 종합 보고서

2026-11-03 / `codex/extreme-latency` / 비교 기반 HEAD `ab2833e` 이후150·151 변경 포함.

이 문서는 기존 보고서와 보존된 시험 결과의 종합이다. 문서 작성 자체를 새로운 통화·네트워크·게임 시험으로 계산하지 않는다. 세부 조건과 실패 원본은 각 보고서를 따른다.

## 1. 목표와 현재 결론

목표는 게임 소리와 함께 사용하는 WASAPI 공유 모드에서 **실제 평상시 입→귀 지연을 줄이고 통화 연속성을 유지**하는 것이다. CPU·GC 감소나 연결 성공을 그 자체로 입→귀 지연 개선으로 대체하지 않는다.

- 물리 입→귀 총지연은 현재 하나의 신뢰 가능한 실측값으로 확정하지 못했다.
- 평상시 큰 항목은 입력 전달/프레임 완성, 수신 재고 유지, 출력 장치까지의 경로다. 최신 시험에서 송신 큐·코덱 연산은 이보다 작았다.
- 순간 지연·PLC·출력 소진·입력 불연속은 서로 다른 사건이다. 모든 현상을 무선, SDK, 특정 장치 하나로 설명할 수 없다.
- SDK 수신 시작 경쟁 등 실제 결함은 수정했지만 이후에도 일부 품질 사건이 남았다. 과거의 수정 완료와 전체 문제 해결은 다르다.
- 최근 채택한 제품 변경은 진단 통계 정렬의 무할당화다. 전체 프로세스 할당률은 시험 조건에서 약6.1% 감소했지만 새로운 물리 입→귀 단축은 입증하지 않았다.
- 정상10ms 전용 송신 후보는 작은 큐 대기 감소만으로 전체 송신 꼬리/품질 이득을 확인하지 못해 기본값 승격을 기각하고 비교 훅을 제거했다.

## 2. 현재 기본 구조

```text
입/주변 음향 → 마이크·ADC·장치 DSP
→ Windows 캡처 전달 → 10ms PCM 프레임 완성 → native Opus
→ 제한 송신 큐 → 상대별 SRTP·송신 API → OS 소켓
→ 직접 경로 또는 TURN → 수신 OS·SDK UDP·SRTP 인증/복호화
→ 상대별 RTP 버퍼·디코더·시계 보정
→ WASAPI 공유 출력 → Windows 오디오 엔진·드라이버·DAC → 귀
```

기본은48kHz mono, native Opus LowDelay64,10ms 프레임, 고정 수신 여유20ms, 스레드풀의 단일 채널 소비자 송신, 상대별 공유 출력이다. 패킷마다 `Task.Run`을 만드는 구조는 아니다. 직접 연결 우선/TURN 대체와 수정 SDK `10.0.17+myeongdong.2 / udp1-turn1-rtp0`를 유지한다. 공통 출력과 극저지연 프리셋은 별도 비교 후보이며 기본 제품과 혼동하지 않는다.

bounded 출력의 추가 여유는 실제 주기5ms 이상에서3ms, 짧은 주기에서5ms이고 장치 용량을 넘지 않는다. 초기 전체 패딩·정착·소진 시 안전 복귀는 유지한다. 시험 PC의 출력 목표5.833ms와 노트북13ms는 해당 장치의 적용값이지 모든 사용자의 고정값이 아니다.

### 채팅에서 제시한 약52ms·80ms의 의미

산술은 `19.2 + 2.5 + 30 = 51.7ms`, `19.2 + 2.5 + 58.2 = 79.9ms`다. **그러나19.2ms는 최신 동일PC6엔진/5상대 송신 상세 시험이고,30/58.2ms는 이전의 각 장치 단독 출력 시험이다. 하나의 실제 통화에서 같은 음성 샘플을 입부터 귀까지 대응한 합이 아니다.**

따라서52ms/80ms는 서로 다른 조건의 내부 수치를 합친 참고 예산으로만 보존한다. 검증된 총지연·현재 사용자의 예상값·물리 하한·여기에 미측정값만 더하면 되는 완성된 모델로 인용하지 않는다. 전체 입→귀와 양방향 차이는 **미확정**이 현재의 정확한 상태다.

## 7. 채택한 변경과 제거한 후보

### 유지/채택

- 기존 UDP 수신 경쟁·TURN 수명·인증 후 RTP 초기 상태 반영 수정과 보안 회귀.
- native Opus, 검증된 저장소/PCM 계산 최적화, 장치 주기 조건부 출력 여유 정책.
- 150 `ProcessingWindow.Snapshot`: FIFO를 유지하면서 스택 scratch/span 정렬로 계산 할당 제거. 선택된 반복 계산은 호출당5,440바이트→0, 실제6엔진 전체 할당률 약6.1% 감소.
- 151 그룹 검사: 기능 PASS와 `qualityCounters`/`qualityCountersClear`/`QUALITY` 로그를 분리. 렌더는 소유 출력당 한 번 집계하고 누락값/부분 관측을 보존한다. 새 패킷별 기록은 추가하지 않았다.
- 반복 시험은 고정 Release 검사 경로와 앱 한정 방화벽 규칙을 사용. 전역 방화벽/UAC/알림은 유지. [준비와 복구](../TEST-FIREWALL.md).

### 기본값으로 채택하지 않음

- 5ms 프레임 단독 축소, 자동 수신 하한10~14ms, 같은 주기 캡처 교체, 일회성 정착/지속 PI, 단일GCM 키 재사용, 정상10ms 전용 송신.
- 공통 출력은 비교 후보 유지 상태이며 이번에 기본값으로 바꾸지 않았다.
- 과거 시험의 기각은 해당 구현·조건의 판정이다. 개념 자체의 불가능을 증명한 것은 아니지만 같은 후보를 새 근거 없이 반복하지 않는다.

SDK·프레임·수신/출력 여유를 이번150/151에서 함께 바꾸지 않았다. 일반 앱 DLL은151 종료 시150 보존 bin과 SHA-256이 같았고, 비교용 전용 송신 훅은 최종 소스에 남지 않았다. 기존 베타/dist/운영 서버를 이번 Git 정리로 새 배포하지 않는다.

## 8. 다음 계획과 중단 기준

1. PC/노트북 앱 하나씩의 실제 사용 조건으로 기준선을 잡는다. 집중30출력 결과를 일반1인 앱의 병목으로 대체하지 않는다.
2. 기존140에서 PC 방향에 남은 가능성을 확인하려면 **PC 수신만20→15→20ms**, 노트북20ms 고정으로 짧은 반복 대조를 한다. 이것은 아직 미실시 계획이며 성공을 전제하지 않는다.
3. 설정값/큐 길이가 아니라 같은 내용의 정상 수신 대기와 신뢰 가능한 장치 공급 경계를 확인하고, 전체 PLC·늦음·재버퍼·출력 소진·송신/입력 폐기를 함께 본다.
4. 짧은 대조에서 감소가 재현되지 않거나 연속성이 악화되면 종료/원복한다. 통과한 후보만 저계측 유지·TURN·다인·준비 가능한 실제 게임으로 확대한다.
5. 물리 입→귀가 필요하면 입력·출력의 실제 음향을 대응하는 유효한 시험이 별도로 필요하다. 현재 내부 수치를 합쳐 그 검증을 대체하지 않는다.

암호화/할당 감소와 단일 출력은 비용 개선 후보지만 평상시 입→귀 단축이 보장된 해결책으로 순위를 올리지 않는다. 스캔·MCC·qWAVE 등 효과 없는 환경 조치를 무작정 반복하거나 공유기/드라이버/라우팅/VPN 설정을 임의 변경하지 않는다.

## 9. 실행·검증·자료 보존

```powershell
./native/run.ps1
./native/verify.ps1 -NoRestore -Integration
# 개발 비교용: 기본값 변경/권장값이 아님
./native/run.ps1 -ReceiveReserveMs 15
./native/run.ps1  # 일반20ms로 복귀
```

최신 코드의 전체 Integration 회귀는 경고/오류0으로 통과했다. 실제 UDP/SRTP·가변 프레임·IPv6·제품/UI·서버/실행기·그룹 카운터 회귀를 포함한다.149의 Stress/이전 Python 회귀와 최신 실행을 혼동하지 않는다. 이번 종합 보고서 작성 중 새로운 게임·외부 사용자·수시간 통화를 수행했다고 표시하지 않는다.

이번 커밋 준비에서는 `--precision-self-test`와 `--product-checks`를 다시 실행해 통과했다. 무할당 통계·공유 렌더 집계·SRTP oracle/위조/재전송·수명/종료·큐/프레임/시계 회귀를 확인했으며, 이 짧은 자체 검사를 새로운 실사용 통화/게임 검증으로 계산하지 않는다.

원본 JSON/ETW/EventPipe/Npcap/바이너리·기기/주소/인증 정보는 Git 제외 `.local` 등에 보존한다. 최근 자료 입구는150의 `.local/extreme-152`,151의 `.local/extreme-153`·역순 `.local/extreme-154`다. 이 로컬 자료 경로와 공개 보고서 번호는 서로 다른 번호 체계다.

Git에는 요약 문서·소스·회귀 검사만 올린다. 사용자 진단 원본·음성·세션 토큰·SSH/서버 비밀값·개인 네트워크 정보는 이번 커밋에 추가하지 않는다. 공유기 상태·장치/드라이버/전원·라우팅/VPN·운영 서버는 이 문서 정리 때문에 변경하지 않는다.
