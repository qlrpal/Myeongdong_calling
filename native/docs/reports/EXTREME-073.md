# EXTREME-073 — 독립 휴대폰 핫스팟 AP 교차 대조

## 승인 범위와 가설

사용자는 메인 공유기 직결 유선 불가 조건에서 휴대폰 모바일 데이터 핫스팟을 선택하고 접속 정보를 제공했으며 연결 전환도 자율 진행하도록 요청했다. 기존 AP→핫스팟→기존 AP 각180초와 원래 연결 복구가 범위다. 암호는 보고서·시험 스크립트·진단 로그에 기록하지 않으며 이미 저장된 WLAN 프로필로 접속한다. 프로필 key 평문 조회·추출 없음.

같은 PC·Realtek8852CE·드라이버/전원 설정을 유지하고 AP 연결 환경에 지연이 종속되는지 본다. **AP 하드웨어 자체의 고장 확인 시험이 아니다.** AP 변경에는 무선 채널·신호·보안 협상·연결 상태 초기화가 동반될 수 있다. 핫스팟은 사용자가5GHz 우선·WPA2/WPA3-Personal로 설정했으며 기존 AP는2.4GHz·WPA-Personal이다. 실제 연결 대역·인증을 매 단계 기록하고 다르면 교란 변수로 표시한다. 어댑터 재시작이나 모드/보안 변경으로 임의 일치시키지 않는다.

예상 관측: 기존 AP A1/A2에서 로컬 지연이 재현되고 B에서 낮아지면 '모든 AP에서 동일한 고정 PC 지연' 설명은 약해지고 AP/대역/연결 상호작용 가설이 강화된다. 세 단계 모두 비슷하면 현재 AP만의 원인 설명이 약해지지만 서로 다른 원인이 같은 결과를 낼 가능성은 남는다. 기준 단계에서 재현되지 않으면 무발생을 개선으로 판정하지 않는다.

## 측정과 해석 범위

- 두 NIC source/IP_UNICAST_IF 명시. PC 이더넷→버디5GHz 백홀은 동일 시간 대조로 유지한다.
- 각 단계 자체echo·OCI/외부 STUN·자체OCI 제한 부하 및 독립 Python 게이트웨이 UDP를 기록한다. 요청/응답 순번과 같은 호스트QPC로 계산한다.
- 게이트웨이 UDP는 같은 비재귀 CHAOS TXT 질문·응답 코드·길이를 기록한다. 핫스팟이 응답하지 않으면 무손실/정상으로 처리하지 않고 동일 UDP 로컬 대조 불가로 표시한다.
- 각 AP와 이더넷 게이트웨이에 source/interface를 고정한 ICMP echo도5Hz로 함께 기록한다. raw socket은자체nonce/ID/순번·응답 목적지만 수용한다. ICMP와 DNS는 다른 처리이며 서로의RTT 수치를 대체하지 않는다.
- 핫스팟 외부 경로에는 이동통신망이 추가되므로 외부RTT 차이를 AP 지연 개선량으로 해석하지 않는다. 자신에게 보낸echo는 실제 무선 왕복이 아니다.
- 전체180초 교집합의 첫5초·끝2초 제외. 패킷 최대값 하나보다분포·초과 빈도·미응답과 A1/A2의 재현 여부를 함께 본다. 짧은 시험의 무발생은 장시간 안정화 보장이 아니다.

시스템 라우팅을 수동 변경하지 않는다. AP 연결에 따른 Windows의 DHCP/IP/연결 경로 자동 변경은 기록하며 시험 소켓만 명시적으로 바인딩한다. 공유기·핫스팟 설정·드라이버·오디오·기존 배포본 변경 없음. 원시 자료는Git제외 `native/.local/extreme-073/`에 보존한다.

## 실행·복구 결과

3단계 각180초를 완료했고 최종 `restored=true`, 오류없음이다. 첫 B 전환은Windows 가용 목록에 핫스팟이 없어 거부돼 기존 AP를 유지했다. A1은 이미 정상 완료한 별도 자료다. 일회성Native WLAN 검색을 갱신하고 저장 프로필로 연결 성공 후 B/A2만 재개했다. 최초 실패 상태를 `result-initial.json`에 보존했으며 중복 측정 프로세스를 실행하지 않았다. 프로필 보안 조회는key=clear 없이 수행했고 암호를 사용하거나 수정할 필요가 없었다.

| Wi-Fi 경로 | 게이트웨이 UDP P50 / P95 / 최대 | UDP 미응답 | 게이트웨이 ICMP P50 / P95 / 최대 | ICMP 미응답 |
|---|---:|---:|---:|---:|
| A1 기존2.4GHz | 1.17 / 15.50 / 1,565.46ms | 72 / 5,568 | 1.45 / 22.73 / 4,116.94ms | 3 / 853 |
| B 핫스팟5GHz | 3.26 / 7.65 / 137.76ms | 0 / 5,560 | 2.48 / 5.91 / 99.41ms | 0 / 853 |
| A2 기존2.4GHz | 1.17 / 11.42 / 166.62ms | 0 / 5,562 | 1.47 / 12.20 / 182.55ms | 0 / 853 |

ICMP는명시적source/interface raw echo의자체nonce를대응한앱 경과RTT이며커널RTT나음성지연이아니다. 미응답은분석창 송신에종료시점까지응답을대응하지못한건수이며단방향손실확정이아니다. A1의수초사건 중다른NIC이더넷 게이트웨이UDP최대30.34ms / ICMP19.98ms, 자체echo최대2.95ms여서PC전체정지만으로설명하기어렵다. 그러나이번에는동시NIC/DPC캡처가없어기존071/072의발생경계를이수초사건에소급적용하지않는다. A1시간대WLAN Operational 이벤트는0건으로연결해제원인확정근거도없다.

B는실제5GHz채널161·WPA3-Personal·RSSI약−36dBm, IP10.37.0.172/게이트웨이10.37.0.215였다. A1/A2는2.4GHz채널5·WPA-Personal·RSSI약−56~−59dBm이다. 따라서대역·보안·신호·AP가동시에다르다. 더구나B의DNS응답은NOERROR(0), A의NOTIMP(4)와달라DNS서버내부처리까지같다고가정하지않는다. B에서UDP5,560건모두응답됐지만휴대폰의내부처리/전달여부를패킷길이만으로증명하지않는다.

B의OCI P50은39.33ms로 A1 11.50 / A2 10.21ms보다높았다. 이는모바일망을포함한외부RTT이며AP악화량이아니다. 반대로 B의로컬UDP/ICMP에서도수십~100ms대기가남아기존공유기를통과하지않는경로에도지연사건이존재한다. 이것만으로Realtek드라이버를확정하지않으며두AP가5GHz채널161등주변무선환경을공유할수있다는점도남는다.

사용자는5GHz추가대조대신휴대폰핫스팟을2.4GHz로변경했다. B측정은18:06대종료됐고사용자변경은A2시간대에일어났으므로A2는주변RF환경이완전히고정된엄밀한대조가아니다. 사용자변경시각을추정해임의구간을제거하지않는다. 최종대역이실제2.4GHz채널1·WPA3임을새검색으로확인했다. 최초5GHz조건의자료는예비결과로보존하고, **새075의2.4GHz A/B/A를별도로진행한다.**

074의메인5GHz→핫스팟5GHz→메인5GHz실행안은준비만했고사용자가2.4GHz변경을선택해실행하지않았다. 075에서073의A2를재사용하지않고새A1부터측정한다. 공유기·드라이버·전원·라우팅수동변경없음. 자세한원자료는`summary.json`, `connection-{a1,b,a2}.json`, 각DNS/ICMP/path JSON에보존했다.
