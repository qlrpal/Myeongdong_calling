# 적응형 여유 축소 속도 비교 (2026-10-21)

## 목적과 변경 범위

지연을 우선하면서 기존 `opus-adaptive`의 부족·보간을 악화시키지 않는지 확인한다. 안정 대기 시간을 실험 JSON의 `ShortReserveQuietSeconds`로 분리했다. 허용 범위는 2~10초, 누락 시 기존 6초다. 축소 속도 1ms/초, 5~20ms 여유 범위, PLC 상한, 출력 목표와 기본 프로필은 바꾸지 않았다. 늦은 패킷·보간이 발생하면 대기 시간은 다시 시작한다.

후보 설정은 안정 대기 2초다. 빠른 축소를 새로운 권장값으로 채택한 것은 아니다. 기존 기본 모드·안정 브랜치·배포본도 그대로다.

## 동일 기록 재생

EXTREME-064의 최신 5분 TURN 시험 마지막 30초 기록을 같은 패킷 도착/렌더 요청 순서로 재생했다. 초기 2초와 마지막 1초는 제외한다. 원래 큐 이력이 없고 합성 페이로드를 사용하므로 실제 장치 출력이나 음질 판정은 아니다. 지연은 살아남은 재생 패킷만의 수신→렌더 중앙값이며, 반드시 폐기·보간과 함께 비교한다.

| 수신 측 | 대기 6초: 지연 / 보간 | 대기 2초: 지연 / 보간 |
| --- | --- | --- |
| PC | 14.29ms / 122.5ms | 13.28ms / 127.5ms |
| 노트북 | 14.99ms / 217.5ms | 14.20ms / 247.5ms |

3초/4초 후보도 비교했다. 빨리 줄일수록 지연이 조금 낮아지지만 보간이 늘어나는 경향이 있어, 재생 결과만으로 채택하지 않았다. 재생 도구는 적응형 프로필에서 다른 설정을 고정하고 2/3/4/6초만 비교한다. 비적응형 프로필의 여유·보류 시간 비교 기능은 유지한다.

## 실기 비교 조건

PC와 노트북에서 실제 WASAPI 공유 입력·출력 및 합성 음성 송신, 동일 TURN 강제 경로를 사용한다. 기존 6초(A)→후보 2초(B)→기존 6초(C)를 각 120초 양방향으로 실행한다. 사용자 음성을 저장하거나 장치 설정을 변경하지 않는다. 시간에 따른 환경 변동을 확인하는 순차 대조이며 무작위 교차 반복이나 동일 네트워크 손상의 재현 시험은 아니다.

원시 기록·재생 결과는 Git 제외 경로 `native/.local/extreme-065/`에 보존한다. 원시 기록에는 빌드 식별자와 후보 설정이 포함된다.

각 행은 약 119.7초의 첫/마지막 스냅샷 차이다. 지연 통계만 마지막 30초의 원시 기록에서 구한다. 송신 누락·잘못된 패킷·장치 재시작은 전부 0회였지만, 부족+보간 1% 이하 조건을 모두 넘었으므로 엄격한 연속성과 송신/RTP/큐 판정은 모두 FAIL이다. 기능 연결 성공 로그를 연속성 PASS로 해석하지 않는다.

실제 목표 여유의 중앙값과 P95는 여섯 조건 모두 20ms였다. 후보의 부족·보간은 적었으나 순차 실기에서 입력·망·스케줄링의 변동을 고정하지 않았으므로 해당 감소를 후보의 효과로 확정할 수 없다. 노트북 지연은 A보다 B가 약간 높다. 이번 실행을 지난 EXTREME-064의 14~16ms 결과와 동일 상태라고 간주하지 않는다. 지금 상태에서 보편적 안정화를 주장할 근거도 없다.

오늘 A 기록을 같은 순서로 다시 재생해 6초/2초만 바꾼 결과, PC 지연 중앙값은 19.38→18.82ms, 보간은 290→310ms였다. 노트북 지연은 21.26→21.24ms, 보간은 300ms로 동일했다. 재생의 초기 이력/합성 페이로드 한계를 감안해도 빠른 축소가 노트북의 현재 병목을 크게 바꾸는 근거는 없다.

**권장 `opus-adaptive`는 기존 6초를 유지한다.** 2초 후보는 시험 JSON으로만 남긴다. 이번 변경의 결과는 검증 가능한 축소 간격 설정·회귀 검사·동일 기록 비교 기능이며, 추가 지연 개선을 달성했다고 주장하지 않는다. 다음 최적화는 상한까지 회복 여유를 올리는 부족 이벤트의 연속 구간과 출력 공급 시점을 함께 조사하는 것이 적절하다. 고정 버퍼를 늘리거나 개인 장치 설정을 변경하여 결과를 숨기지 않는다.

## 검증

`verify.ps1 -NoRestore -Integration` 전체 통과. Release 경고·오류 0개. 빠른 축소의 2초 대기, 보간/늦은 패킷에서의 타이머 초기화, 1ms 단위 감소를 검사했고 기존 기본 동작·짧은/긴 Opus 혼합·실제 로컬 SRTP/RTCP 통합 회귀도 통과했다. 원시 실기 연속성 FAIL과 구현 회귀 PASS는 별개의 결과다. 커밋·푸시·배포본 교체는 하지 않았다.
