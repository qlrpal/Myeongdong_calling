# 0.6.0 핵심 통화 앱 구현·검증

2026-10-21. 네트워크 최종 원인 조사는 보류하고 사용 가능한 Windows 통화 앱의 기본 흐름을 구현했다. 지연 우선·품질 2순위, WASAPI 공유 모드, 기존 고정 20ms 기본 정책과 Opus LowDelay64를 유지한다.

## 구현

- 통화 탭: 닉네임·방 이름·서버, 새 방 생성·참가·초대용 방 이름 복사·나가기, 참가자별 연결 상태.
- 마이크 음소거: 인코딩 직전 PCM을 무음으로 바꾸고 재연결 뒤에도 유지한다.
- 상대별 볼륨 0~200%·음소거: 출력 직전 PCM에 적용하며 음소거 중에도 원본 타임라인은 소비한다. 같은 상대 세션 ID가 유지되는 자신의 자동 재접속에서는 선택을 유지한다. 상대 재입장 또는 명시적 나가기는 초기화한다.
- 입력·출력 장치 선택: 실제 Core Audio endpoint ID를 캡처·저지연 출력·호환 출력에 전달한다. 통화 중 선택 변경은 같은 방 재접속으로 적용한다. Windows 기본 장치 변경 감지와 기존 출력 복구를 유지한다.
- 재연결: 서버 세션 종료·지속적인 ICE 실패·입력 정지·장시간 음성 미수신을 감지해 최대 5회, 대기 1/2/4/8/15초로 재시도한다. 명시적 나가기·창 닫기는 재시도를 취소하고 진행 중인 연결이 끝나더라도 다시 남지 않도록 정리한다.
- 설정·로그: 서버·방·닉네임·장치·마이크 음소거를 사용자 LocalAppData에 원자적으로 저장한다. 손상된 설정은 기본값으로 복구한다. 이벤트 로그는 현재·이전 파일로 크기를 제한한다. 토큰·음성은 저장하지 않는다.
- 기존 상세 진단·고급 설정은 별도 탭에 보존했다. 사용자 가이드와 폴더형 배포 ZIP을 준비했다.

## 실제로 발견·수정한 참가 버그

양쪽이 장치를 바꾸며 동시에 나갔다 들어오는 시험에서, 참가 응답의 상대 목록이 협상 시점에는 만료될 수 있었다. 나간 상대에게 offer를 보내 서버의 404를 받으면 기존 클라이언트는 참가 전체를 실패 처리했다. 이 상황에서 상대가 다시 참가해도 한쪽은 방을 떠나 다른 쪽은 시간 초과했다.

신호 전송의 404 중 서버가 명확하게 ‘참여자가 통화를 나갔습니다.’라고 응답한 경우만 정상적인 상대 퇴장으로 처리한다. 대기 중인 peer-left 이벤트가 기존 상대를 정리하도록 협상 게이트를 해제하고 방은 유지한다. 인증 만료·기타 HTTP 오류는 계속 실패 처리한다. 서버 배포 변경 없이 기존 응답과 호환된다. 서버 계약 회귀 검사도 추가했다.

수정 후 동일한 동시 재입장·기본 장치 전환 시험이 양쪽 모두 통과했다. 노트북 결과에는 이 404 처리 경로가 실제로 1회 실행된 로그가 있어 단순히 경쟁 조건을 피한 성공만은 아니다.

## 검증

### 순수 기능·상태 검사

방 이름·닉네임·서버 주소 검증, 볼륨 포화 처리·음소거 중 타임라인 소비, 비정상 볼륨 거부, 읽을 수 있는 한글 설정의 저장·로드, 손상 파일 복구, 임시 파일 정리, 연결 끊김 감지 후 성공 재시도, 5회 한도, 재시도 대기 취소, 최초 참가 중 나가기, 재연결 참가 진행 중 나가기와 리소스 해제를 검사했다.

### PC·노트북 실통화

실제 공유 입력·출력 장치와 OCI TURN으로 같은 합성 발화를 송수신했다. 물리 마이크 PCM 대신 TTS를 인코딩 전에 넣어 개인정보 음성은 저장하지 않았다. 검증 도구의 입력은 표준 10ms 공유 캡처이며 UI의 짧은 입력 주기 선택에 대한 성능 비교는 아니다.

- 명시적인 캡처·출력 endpoint ID로 통화 시작.
- 발화 → 마이크 음소거 → 해제, 상대 볼륨 0 → 100%.
- 마이크를 다시 음소거하고 강제 세션 재연결, 재접속 후에도 무음 유지 확인.
- 고정 장치 ID에서 Windows 기본 장치 선택으로 바꾸며 같은 방 동시 재입장.
- 정상 나가기 후 자동 재참가가 없는지 확인.

최종 결과는 양쪽 오류 없음, 각각 84개 표본이다. 음소거 구간과 재접속 후 음소거 구간의 로컬 PCM RMS는 양쪽 모두 -120dBFS였고, 활성 구간 최대 표본은 PC 약 -14.57dBFS·노트북 -15.68dBFS였다. 상대 볼륨 처리의 실제 게인·포화·타임라인 소비는 별도의 PCM 검사로 확인했다. 실제 통화 시험에서 상대 음량의 청감을 판정한 것은 아니다.

첫 기본 시험은 양쪽 통과했다. 확대 시험에서 동시 참가 버그를 발견했고 실패 기록을 보존한 뒤 수정·재시험했다. 회차 사이의 의도적 장치 전환이 상대의 관측 구간을 끊지 않도록 시험 도구에는 짧은 경계 대기도 추가했다.

### 빌드·화면·회귀

Release 빌드 경고·오류 0, 제품 기능 검사 및 전체 기존 정적 분석·회귀·서버 8개 검사·실제 로컬 WebRTC/DTLS/SRTP·RTCP 통합 검사 통과. 기본 화면·최소 창 크기·진단 탭을 실제 WinForms 렌더 이미지로 확인하고 잘리던 음소거 버튼과 장치 새로고침 폭을 수정했다.

원본은 Git 제외 경로 `native/.local/product-060/`에 보관한다. 사용자 장치·게임·OS 음량·오디오 효과·서버 운영 설정은 바꾸지 않았다. 시험 뒤 노트북 진단 프로세스 잔류 0을 확인했다.

## 범위와 남은 검증

핵심 통화 흐름의 첫 제품 버전이다. 실제 두 PC에서 검증했으며 3~6인 그룹·게임 부하·장시간 재연결 스트레스·물리 장치 탈착의 모든 조합·배포 대상별 DPI/장치 호환성을 보장하지 않는다. 자체 에코 제거·로그인·방 비밀번호·친구 목록·채팅은 구현 범위가 아니다. 이전에 확인한 수신 전 공백과 전체 입→귀 지연 문제를 이번 기능 구현으로 해결했다고 주장하지 않는다.

배포는 .NET 10 Desktop Runtime이 필요한 Windows 폴더형 패키지이며 런타임 포함 설치 프로그램·코드 서명은 제공하지 않는다. Git 커밋·푸시는 하지 않았다.
