# EXTREME-092 — 두 Windows 호스트의 다인 통화·복구·Git 준비

2026-10-25 / codex/extreme-latency. 제품 기반0.6.0, 새 안정판 태그 확정은 아니다.

## 방법

실제 PC/노트북에 각각 통화 엔진3개를 실행했다. 처음3명은 PC1+노트북2,6명은 각3개다. 모든 엔진이 실제 WASAPI 공유 입력/출력과 WebRTC를 사용하고 마이크 PCM만 합성 음성으로 대체한다. 참가자마다 상대별 별도 공유 출력 스트림을 사용하며 Windows 오디오 엔진에서 합산된다. 테스트 피어의 앱 볼륨만 낮추고 기존 앱 설정·시스템 오디오·드라이버·공유기·라우팅은 바꾸지 않았다.

각 참가자가 나머지5명과 주고받는 전체 메시를 검사한다. 여러 사용자의 CPU/장치 부하가 두 컴퓨터에 집중돼 독립된6대PC의 성능으로 일반화하지 않는다. 같은 호스트 연결과 PC 간 연결은 별도로 집계한다. 실제6명 음성·게임 부하·친구 WAN·물리 입→귀 지연 시험은 아니다.

양쪽 Windows UTC 시계 차이는 원격 조회를 로컬 송수신 시각으로 감싸 범위를 확인했다. 원격이 약20.8~24.3초 앞선 조회 범위에서 호스트별 시작 시각을23초 보정했다. 시스템 시계는 변경하지 않았고 단계 끝5초는 측정에서 제외한다. 음성 지연을 서로 다른 QPC/UTC 원점의 차로 계산하지 않는다.

## A — OS 자동 선택 전체 시나리오

3명60초 →6명120초 →한 명 퇴장30초 →재참가60초 →한 명10초 퇴장 후 재접속60초 →전체 퇴장20초 →6명600초 순서다.

3명/6명 성립, 한 명 퇴장·재참가, 엔진 Leave/Join 재접속, 전체 퇴장 후 재입장은 성공했다. 그러나 마지막 유지 구간 약93초에 특정 노트북 참가자와 PC 참가자들 사이의 수신이 멈추고 ICE disconnected가 발생해 양쪽 시험을 중단했다. 이 시도는 **장시간 무중단 기준 실패**로 보존한다. 실패 전 참가자의 마이크와 송신 카운터는 계속 진행됐다. 초기 호스트 평균 CPU는 PC 약0.34코어, 노트북 약0.57코어였으므로 이 값만으로 CPU 포화나 특정 네트워크 원인을 확정하지 않는다.

자동 선택에서 PC가 기록한 상대 주소가 노트북의 현재 LAN 주소와 다른 사설 주소였다. 이것은 선택 경로의 관측이며 NAT/후보 선택/물리 네트워크 중 특정 원인 확정이 아니다. 실패 뒤 양쪽 엔진 정리 상태는 정상이다. GUI의8초 감시/자동 재시도까지 포함하는 시험이 아니라 엔진 무중단 유지의 엄격 검사였다.

## B — 앱의 LAN 인터페이스 명시 대조

기존 SetMediaInterface 기능으로 각 호스트의 현재 LAN 주소를 앱에만 명시했다. 시스템 라우팅 변경은 없다.3명60초/6명90초 짧은 CPU 대조와, 별도 새 세션의6명600초 시험을 수행했다. 자동 선택 시험과 새 세션/순서도 달라 단일 변수 A/B/A나 원인 확정으로 보지 않는다.

최신 시험 도구 SHA256은 양쪽 동일함을 확인했다. 명시 주소 조건의 짧은 시험에서는 실제 LAN 주소들이 선택됐다. 기본 OS 자동 경로를 임의 변경하거나 VPN 경로를 우회하는 제품 기본값을 추가하지 않는다.

## 도구·실험 모드 정리

- TwoHostGroupProbe: 3/6명, 입퇴장·재접속·전체 종료·유지, 피어 수/장치 오류/디코딩/프레임 제어 제한/정리 검사와 구간별 호스트 CPU/메모리/핸들 기록.
- analyze_group_probe.py: 실패/정리 실패/누락 단계·클라이언트/미수신·미디코딩/피어 카운터 역행을 거부하고 수신 측 로컬 시간으로 피어별 큐·PLC·부족·폐기를 집계한다. Source 최대값은 참가 이후 누적이며 구간 독립 최대값으로 표시하지 않는다. 메모리에 보존 진단이 포함돼 전후 값만으로 누수를 판정하지 않는다.
- 기본 실행은 기존 모드 유지. opus-adaptive는 지연 우선 비교 후보, opus-auto-frames는1:1 자동 프레임 시험(그룹은 현재 길이 유지), opus-learned는 성능 우위 미확인 정책 시험으로 문서에서 구분한다. 기존 모드 이름은 실행 호환성을 유지한다.
- 원본/로그/합성 WAV/임시 바이너리/기각 후보는 Git 제외 .local에 보존한다. 기존 dist와 그 안의 진단 자료는 변경하지 않는다.

재현 조건은 [두 호스트 시험 가이드](../TWO-HOST-GROUP-TEST.md), 실행·배포 소스 범위는 [Git 가이드](../GIT-RELEASE.md)에 기록한다. 커밋/푸시는 별도이며 이 정리에서 실행하지 않는다.

## B 최종 결과

양쪽3명/6명 짧은 대조와6명600초 시험 모두 연결 기능·디코딩·장치 오류0·정리 검사를 통과했다.600초 설정에서 준비/종료 완충/첫10초를 제외한 각 피어의 유효 분석 창은 PC 약580.5초, 노트북 약581.5초였다. 전체30개 방향의 송수신·디코딩 진행을 확인했고, 그룹에서는 전 구간2.5ms 유지/1:1 자동 프레임 제어 비활성을 확인했다. 송신 큐 드롭0, 송신 대기 누적 최대는 PC 약1.54ms / 노트북 약3.28ms였다.

|호스트|3명 구간 로컬 엔진 수 / CPU 코어|6명 구간 로컬 엔진 수 / CPU 코어|6명 유지 CPU 코어|
|---|---:|---:|---:|
|PC|1 / 0.072|3 / 0.406|0.406|
|노트북|2 / 0.301|3 / 0.775|0.710|

코어 값은 해당 시험 프로세스의 CPU 시간/경과 시간이며 audiodg.exe·커널/드라이버·다른 앱은 제외한다.0.4코어는 시스템 전체 CPU40%가 아니다. 로컬 엔진 수까지 함께 늘어나므로6대 독립PC의 단일 사용자 비용으로 환산하지 않는다.

**연속성은 합격으로 판정하지 않았다.** 유지 구간의 방향별 시간을 가중한 평균 PLC는 PC 수신의 같은 호스트 약3.73ms/s / 다른 호스트9.46ms/s, 노트북 수신의 같은 호스트59.85ms/s / 다른 호스트8.81ms/s였다. 노트북 같은 호스트 방향에서 PLC가 높았고 수신 부족/회복 폐기도 남았다. 큐 중앙값은 PC 같은 호스트12~16ms / PC 간22.2~22.6ms, 노트북 같은 호스트10~17.5ms / PC 간20ms였다. 이 숫자는 앱 큐이며 전체 입→귀 지연이 아니다.

## 마지막 패킷 기록에서 분리한 미해결 항목

각 참가자 마지막5초 기록의 퇴출0을 확인하고,30개 방향을 SSRC/RTP로 대응했다. 이 짧은 창에서 송신 API 기록의 앱 시퀀스 공백은 전 방향0이었다.

- PC 같은 호스트6개 방향: 수신 콜백 미관측0.
- PC 간18개 방향: 대응 범위의 수신 콜백 미관측0이지만, 수신 후 큐 미입장 패킷이 방향별94~98개였다.
- 노트북 같은 호스트6개 방향: 약2,000개 송신 프레임 중 방향별0~357개가 수신 콜백에 관측되지 않았다. 도착한 대응 패킷의 큐 미입장은0이었다.

따라서 노트북 내부 방향의 문제를 모두 무선망이나 앱 재생 큐 탓으로 설명할 수 없다. 현재 경계는 송신 API 호출 기록~복호화된 RTP 콜백이며 SDK의 전송/복호화·검증, 로컬 OS/수신 처리 등을 아직 분리하지 못했다. NIC 실제 송신·물리 패킷 손실로 확정하지 않는다. 같은 호스트 식별은 참가자의 실행 호스트 기준이며 실제 선로/필터 경로를 패킷 캡처로 증명한 것은 아니다. 새 원인 분리에는 raw UDP 수신과 SDK 검증 뒤 콜백의 대조가 필요하다. 이 시험에서 근거 없는 버퍼/우선순위 설정 변경을 제품에 넣지 않았다.

OS 자동 선택 실패와 LAN 명시 조건의 연결 기능 완료를 모두 보존한다. 명시 조건에서도 PLC가 남고 시험 순서/새 세션이 달라, 자동 경로의 근본 원인 해결이나 모든6명 통화 안정화로 승격하지 않는다.

## Git 준비 및 최종 확인

소스 후보243개의 UTF-8·생성물/바이너리·개인 키/식별자 패턴·내부 Markdown 링크 검사를 통과했다. Git 제외 대상이 이미 추적된 경우도 없었다. 원본 소스의 Release 경고/오류0, 전체 회귀·서버8개·IPv4/IPv6 WebRTC 미디어 통합 통과. 후보 소스만 복사한 폴더에서도 잠금 복원·새 Release 빌드·제품 검사·분석기4개 self-test·서버8개 통과를 확인했다. 캐시를 사용했고 격리 복원에서는 NuGetAudit 조회를 생략했다. 보안 감사/빈 캐시 검증/안정판 승격을 뜻하지 않는다.

시험/SSH 세션은 모두 종료했다. 기존 dist·사용자 진단·시스템 설정은 유지했고 소스와 문서의 준비만 마쳤다. Git stage/commit/push는 하지 않았다. 최신 상태의 다음 우선순위는 [현재 상태](../CURRENT-STATUS.md)에 정리했다.
