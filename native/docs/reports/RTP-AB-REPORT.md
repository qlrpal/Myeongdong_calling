# 두 PC PCM / RTP / PCM 실통화 비교 · 0.5.0

2026-10-16 01:55~01:59 KST. PC와 SSH로 실행한 노트북에서 각75초씩 PCM→RTP→PCM 세 구간을 비교했습니다. 각 구간에서 방향별3회, 총18회 루프백 측정이 성공했고 모두 동일 페이로드 해시의 송수신/출력 추적과 연결됐습니다. 앱 코드와 기본 설정은 측정 중 변경하지 않았습니다.

## 조건

- 두 기기는 같은 LAN에서 직접 연결했습니다. OCI는 연결 관리와 ICE 설정에 사용했으며 이 실통화의 선택 경로는 TURN이 아닙니다.
- 기본 Opus48kHz 모노10ms, 기본 코덱, WASAPI 저지연 우선·복귀 요청40ms 고정. 각 구간에서 통화 엔진을 새로 만들고 수신 경로만 바꿨습니다.
- 양쪽 출력 저지연 활성·엔진 주기10ms. PC는 Realtek44.1kHz 스테레오 부동소수점 출력으로 리샘플링했고, 노트북은 Realtek48kHz 스테레오 부동소수점 출력입니다.
- PC가12/21/30초, 노트북이44/53/62초 부근에 테스트 신호를 주입합니다. 마이크/출력 장치는 열지만 원음은 저장하지 않습니다. 디지털 WASAPI 루프백이며 물리 입→귀 실측이 아닙니다.

## 결과

### 추적 패킷의 수신→출력 제출 시간

구간당 방향별3회 중앙값입니다. `ReceiveToDecodeMs + DecodeMs + PcmQueueMs`로 계산했습니다. RTP 경로에서는 대기가 디코딩 앞에 있고, PCM 경로에서는 디코딩 뒤에 있으므로 `PcmQueueMs`만 비교하면 안 됩니다.

| 방향 | PCM A1 | RTP B | PCM A2 |
|---|---:|---:|---:|
| PC→노트북 | 44.31ms | **27.13ms** | 39.72ms |
| 노트북→PC | 42.85ms | **24.87ms** | 40.97ms |

이 표본에서는 새 경로가 양쪽 PCM 구간보다 약13~18ms 짧았습니다. 방향별3개 표본의 결과이며 장시간·인터넷 환경에서의 보장값은 아닙니다.

### 전체 디지털 루프백

각 측정의 하한/상한 중간값을 구한 뒤 구간 중앙값을 계산했습니다. 시계 보정 범위 약15~31ms 및 검출 여유±20ms가 있어 아래 숫자를 정밀한 종단 실측값으로 해석하면 안 됩니다.

| 방향 | PCM A1 | RTP B | PCM A2 |
|---|---:|---:|---:|
| PC→노트북 | 266.94ms | 252.64ms | 259.73ms |
| 노트북→PC | 122.15ms | 103.61ms | 104.02ms |

PC→노트북은 낮아지는 경향이 있지만 불확실성 범위가 겹칩니다. 노트북→PC는 RTP와 재검사 PCM이 사실상 비슷합니다. 따라서 **전체 지연의 일관된 감소를 입증했다고 결론내리지 않습니다.** 노트북 출력 제출→루프백 검출 중앙값은 약198~208ms, PC는 약50~59ms로 장치/수집 경로 차이가 계속 큽니다.

## 진단 이상치와 제한

- 첫 PCM 노트북 수신 RTCP 보고서 하나에서 손실99.21875%와 누적 손실-4가 함께 나왔습니다. 당시 순서 뒤바뀜4, 중복0이었고 같은 보고서가5~7번 스냅샷에 반복됐습니다. 이후는0%이며 RTP 구간은 양쪽 모든 보고 구간0%였습니다. 이 첫 보고서는 해석이 불일치하는 진단 이상치로 남깁니다. 실제99% 손실이라고 해석하거나 원인을 확정하지 않습니다. 라이브러리 보고서 생성/초기 시퀀스 처리 확인이 필요합니다.
- A2 도중 원격 PowerShell5에서 UTF-8 JSON을 기본 인코딩으로 읽는 보조 집계가 실패했습니다. JSON 파일 자체는 UTF-8로 유효하며 복사 후 명시적 UTF-8로 정상 파싱했습니다. 이때 SSH 콘솔 오류 출력 부하가 있었으므로 A2를 완전히 외란 없는 구간으로 볼 수 없습니다.
- 각 방식의 관측 시간이 짧고 장치 상태가 고정됐습니다. 불안정 인터넷·TURN 경로·패킷 손실 부하·장시간 클록 오차·장치 탈착은 이번 비교에 포함하지 않았습니다.

## 재현과 자료

`TransportProbe`에 `--rtp-ab-test SERVER UNIQUE_PREFIX REPORT ROLE`을 추가했습니다. ROLE은 `pc` 또는 `laptop`입니다. 양쪽을 비슷한 시점에 시작하며 각 구간의 상대 연결 후75초를 측정합니다. 현재 통화 중인 앱은 먼저 나가고 실행합니다.

```powershell
dotnet publish native/TransportProbe -c Release -o native/.local/rtp-ab-050
# 이 PC에서
./native/.local/rtp-ab-050/TransportProbe.exe --rtp-ab-test https://qlrpal.ddns.net/ UNIQUE_PREFIX pc-report.json pc
# 노트북에는 같은 게시 폴더를 복사하고
./TransportProbe.exe --rtp-ab-test https://qlrpal.ddns.net/ UNIQUE_PREFIX laptop-report.json laptop
```

원본은 `native/.local/rtp-ab-050/pc-report.json`, `laptop-report.json`, 요약 `summary.json`입니다. IP·닉네임을 포함하므로 Git 제외 경로에 보존합니다. 노트북에는 `voice-rtp-test-20261016/` 아래 검사 프로그램·보고서를 남겼고 검사 프로세스 종료와 SSH 종료를 확인했습니다. 서버 설정·방화벽은 변경하지 않았습니다.
