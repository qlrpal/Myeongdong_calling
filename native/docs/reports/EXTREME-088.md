# EXTREME-088 — 내부 장시간 대조와 유지 상태 시간창 수정

2026-10-25. 외부 통화·장치·공유기 설정 변경 없이 내부 시험을 진행했다.

## 재현과 수정

가설: 학습값 유지 상태의 조기 반환이 지연 도착 압력의 시간 경과를 막을 수 있다.

도착 간격 초과 통계를 만든 뒤 30초 학습/유지에 진입시키고, 지연 도착 두 건을 2초 떨어뜨려 입력했다. 기존 구현은 1초 압력 시간창을 초기화하지 않아 서로 다른 구간의 두 사건을 합산하고 불필요하게 안전 복귀/목표 증가를 일으켰다. `ReserveLearningChecks`에 재현을 추가해 수정 전 실패를 확인했다.

압력 시간창의 진행을 유지 상태의 조기 반환보다 앞에서 처리하도록 수정했다. 동일 시험이 통과하고 연속 자동 정책에도 기존과 동일한 시간창 처리를 유지한다. 장치/코덱/네트워크 지연을 없애는 수정은 아니며 불필요한 수신 여유 증가를 방지한다.

## 시험 설계

- 새 회귀: 시간창을 벗어난 드문 지연 도착을 누적하지 않음, 소스 초기화 후 다시 학습/유지 가능.
- 기존 회귀: 초기 학습, 높은 목표 고정 방지, 필요한 대기의 안전 복귀, 지속 부족, 긴 공백, 소스 초기화, 기존 연속/비활성 정책.
- `--reserve-learning-soak REPORT.json` / `--reserve-continuous-soak REPORT.json`: 동일 50개 조건을 각각900초 가상 시간으로 대조. 정상/2.5·5·10ms 전환/1% 손실/400ms 공백/재정렬/7초 반손실/출력 정지/입력 묶음 및 주기 변화/488샘플 및 가변 출력/±200·500ppm을 포함한다.
- 각 조건의 마지막20초 복구, 전체 PLC·부족·폐기와 큐 표본을 비교한다. 테스트 자체의 허용 기준 통과와 비교 대상보다 좋아졌다는 판정은 구분한다.

## 한계와 복구

가상 시간의 소프트웨어 시험이다. 실시간 OS 스케줄링·물리 장치·WAN/TURN·게임 부하·입→귀 실측을 대신하지 않는다. 소프트웨어 NIC 경계나 RTT를 음향 지연으로 해석하지 않는다. 기본 모드 승격은 하지 않는다. 원본 로그와 JSON은 Git 제외 `native/.local/*088*`에 보존한다. 시스템 설정·라우팅·공유기·서버·기존 배포 폴더를 바꾸지 않았으므로 해당 설정의 복구 작업은 발생하지 않았다.

## 결과

빌드 경고/오류0, 관리형 회귀 및 서버8개 통과. 수정 전 재현 실패와 수정 후 통과를 확인했다. 50개×900초×두 정책(총25시간의 가상 미디어 시간)을 대조했으며 양쪽 복구 기준 실패0. PLC·출력 부족·폐기 합계와 워밍업5초 이후 큐 중앙값/P95의 차이가 있는 조건은 1개였다. 최대 증가: PLC 0.0000ms, 부족 0.0000ms, 폐기 0.0208ms, 큐 중앙값/P95 0.0000/0.0000ms.

일부 시계 편차 조건에는 양쪽 모두 PLC가 남는다(가변 출력 -500ppm, 900초407.5ms). 따라서 시험 통과를 무손실이나 외부 환경 해결로 해석하지 않는다. 새 모드의 일관된 지연 우위도 입증되지 않아 기본값은 유지한다.
