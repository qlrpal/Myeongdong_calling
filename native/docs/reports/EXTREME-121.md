# EXTREME-121: 상대 마이크 상태 공유

2026-10-29 / `codex/extreme-latency`. 기능 구현을 재개하며 참가자가 말을 하지 않는 것과 마이크를 끈 것, 내가 그 상대의 소리를 끈 것을 구분한다. 실제 발화 감지나 새 오디오 처리 기능은 아니다.

## 구현

- `LatencyTelemetry`: 선택적 nullable `MicrophoneMuted` 필드를 추가했다. 기존 버전 1 메시지와 필드 생략을 허용한다. 잘못된 형식은 기존 JSON 검증에서 거부하며 마지막 유효 상태를 덮어쓰지 않는다.
- `WebRtcCallEngine.GetDiagnostics`: 기존 암호화 WebRTC 데이터 채널의 진단 보고에 앱의 마이크 음소거 선언을 함께 보낸다. 기존 1초 UI 갱신을 이용하며 새 타이머·프레임별 로그·오디오 콜백 작업·리스너를 추가하지 않는다. 별도의 서버 배포가 필요하지 않다.
- `ParticipantAudioStatus`: 연결됨 + 수신 후 3초 이내인 선택적 선언만 표시한다. 미수신·구버전·상태 만료·연결 끊김은 미확인이다. 침묵이나 작은 RMS로 마이크 음소거를 추측하지 않는다.
- 참가자 카드: 연결 경로 아래 마이크 상태를 표시하고, 로컬 음소거나 볼륨 0%는 `내 쪽 음소거`로 별도 표시한다. 볼륨을 펼쳤을 때 겹치지 않도록 조작부를 아래로 옮겼다. 기본/최소 크기 미리보기에서 줄 배치를 확인했다. 미리보기는 가상 참가자 데이터다.

기존 보안·수신 시간축·Opus·장치 주기·재생 여유·출력 방식 기본값은 그대로다. 사용자 설정·기존 dist·서버 설정도 변경하지 않았다. 양쪽이 최신 앱일 때 상태가 공유되며, 구버전과의 오디오는 기존 동작을 유지한다. 이 변경은 실제 입→귀 지연 감소를 주장하지 않는다.

## 검증과 범위

- 경고를 오류로 처리한 Release 빌드, 제품 회귀의 새 상태 검사: 통과. 켬/끔, 상태 만료, 비정상 시각, 연결 끊김, 구버전 필드 생략, 잘못된 필드 타입, 원격/로컬 동시 음소거를 검증했다.
- localhost IPv4/IPv6 WebRTC 통합: 실제 암호화 데이터 채널의 켬→끔 전파를 확인했다. 가변 2.5/5/10ms 스트림 회귀도 같은 필드를 전달한다.
- 기존 UI 읽기 위치 회귀를 유지했다. 기본/최소 크기 카드 미리보기에서 상대 마이크와 내 쪽 음소거 문구를 확인했다.
- 두 PC 도구의 음소거/해제 구간에도 상대 선언 검사를 추가했다. 이번 작업에서는 독립 PC·외부망/TURN·게임·물리 입→귀·장시간 품질 시험을 실시하지 않았다.

`test-app.ps1 -Profile group -NoBuild -NoRestore`는 총 16/16단계 통과했다. 실제 공유 캡처/출력에 합성 PCM을 넣고 같은 PC의 2·3·6엔진을 실행했다. 기존/공통 출력 각각 상대별 켬/끔 전파, 두 송신자의 독립 음소거, 로컬 수신 음소거와 원격 선언의 독립성, 음소거 유지 퇴장/재참가, 새 통화와 정리를 통과했다. 원본 보고서의 두 그룹 모두 `error:null`이다. 독립 6대 PC·외부 사용자 시험은 아니다.

원본은 Git 제외 `native/.local/app-checks/2026-10-28T22-29-15.502Z-jXfEan`과 `native/.local/ui-polish-20261029/participant-*`에 보존한다. 검사 보고서의 DLL 해시는 시험 실행 당시 빌드 식별이다. 이후 두 PC 도구에 같은 상태 검증을 추가한 최종 소스도 경고/오류 0으로 별도 빌드했다. 해당 두 PC 시험 자체는 미실시다.

## 실행

저장소 루트에서 `./native/run.ps1`로 실행한다. 양쪽 모두 최신 소스를 빌드한다. 상대 마이크 상태는 즉시 제어 응답이 아니라 기존 주기 보고이므로 표시가 늦을 수 있다. 3초 넘게 갱신이 없으면 미확인으로 돌아간다. 실제 마이크 음소거의 오디오 처리 방식은 변경하지 않았다.

`./native/test-app.ps1 -Profile group`은 같은 PC의 실제 공유 장치를 열고 입력을 합성 신호로 교체하여 기능을 확인한다. 독립 사용자 6명이나 외부 통화 품질 검증으로 해석하지 않는다. 일반 통화에서 나간 뒤 실행한다. 진단 원본과 사용자 자료는 커밋하지 않으며 이번 작업에서 커밋/푸시하지 않는다.
