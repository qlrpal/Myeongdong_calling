# EXTREME-120: 진단 읽기 위치와 UI 마감

2026-10-29 / `codex/extreme-latency` / EXTREME-119 이후 소스 변경. 통화 엔진·프레임·버퍼·보안·연결 정책은 이 보완에서 변경하지 않았다.

## 수정

- `CallControls.cs`: 비활성 항목도 밝은 회색으로 표시하는 콤보박스, 둥근 체크 스위치, 진단/로그용 얇은 스크롤바와 읽기 전용 RichEdit 컨테이너를 추가했다. 기존 체크/선택 이벤트를 유지한다. 설정 패널의 네이티브 스크롤은 어두운 테마를 사용한다.
- `CallForm.cs`: 통계 전체 교체 시 양방향 스크롤 위치와 선택을 복원한다. 이벤트 로그는 독자가 이미 맨 아래에 있을 때만 추가 항목을 따라간다. 오래된 로그를 지울 때 행/문자 오프셋을 보정하며 CRLF/LF를 정규화한다. 숨겨진 페이지 갱신 후 다시 표시해도 읽던 위치를 복원한다.
- `CallForm.Product.cs`: 장치 선택에도 동일한 콤보박스, 상대 음소거에 동일한 토글을 사용한다.
- `CallForm.Design.cs`: 헤더 높이를 줄이고 방 이름의 표시 폭에 맞춰 복사 버튼·상태·인원을 이어 배치한다. 좁은 헤더는 상태/인원을 위 행으로 옮겨 겹침을 피한다.
- `UiReadingChecks.cs`, TransportProbe CLI, verify 및 앱 검사 core: 실제 WinForms RichEdit의 읽기 위치 회귀를 추가했다. 통화·장치·네트워크를 열지 않는 UI 검사다.

## 확인

- Release 경고를 오류로 처리한 빌드: 경고/오류 0.
- 실제 앱의 고급 진단 화면에서 글자 대비·토글·스크롤바를 확인했다. 마우스 휠과 스크롤바 드래그로 아래 내용을 읽은 뒤 자동 갱신에서도 같은 위치를 유지했다. 시험 앱은 종료했다.
- 기본/최소 크기의 6명 배치 미리보기에서 방 이름·복사·상태·인원 배치를 확인했다. 이는 시험 데이터이며 실제 6인 통화 시험이 아니다.
- UI 자동 검사: 긴 CRLF 문서의 가로/세로 휠, 30회 본문 갱신 중 위치/선택 보존, 숨김 중 갱신 후 복원, 중간 읽기 중 추가 로그, 오래된 로그 삭제 후 행/선택 보존, 맨 아래 추적, 짧은 문서의 스크롤 범위 축소를 통과했다.
- `verify.ps1 -NoRestore -Integration`의 빌드·제품/UI·코덱/복구 등 서버 이전 단계는 통과했다. 샌드박스의 localhost TCP 연결 거부(EACCES)로 서버 단계가 중단되어 전체 스크립트 자체는 성공으로 기록하지 않는다. 해당 서버 회귀를 제한 밖에서 별도 실행해 8/8 통과했고, 나머지 검사 도구 회귀 12/12와 localhost 통합 5단계(LAN, RTCP, RTP 재생, 가변 프레임, IPv6)도 별도 실행해 모두 통과했다.

원본 로그·PNG·JSON은 Git 제외인 `native/.local/ui-polish-20261029` 및 기본 검사 결과 경로에 둔다. 물리 지연·외부 통화·게임 부하 시험은 이 UI 변경에서 실시하지 않았다. 새 지연 감소를 주장하지 않는다.

## 실행

소스 UI는 저장소 루트에서 `./native/run.ps1`로 실행한다. UI 회귀는 Release 빌드 후 `TransportProbe.exe --ui-reading-checks OUTPUT_DIRECTORY` 또는 기존 `verify.ps1`/`test-app.ps1` core로 실행한다. 기존 게시 dist는 수정하지 않았고 커밋/푸시는 수행하지 않았다.
