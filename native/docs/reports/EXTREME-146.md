# EXTREME-146 — 출력 정착 후보의 장치 이득과 실제 통화 반증

2026-11-03 · 기반 `e8a140b` · 작업 중간 기록. 후속 실험 결과와 최종 채택은 별도 기재한다.

## 가설과 비교

145의 모형에서 출력 패딩 축소분이 상위 수신 큐에 남았다. 첫 후보 R1은 축소분에 해당하는 유한한 샘플 예산을 최대0.5% 추가 소비율로 정착시킨다. 전체 소비율 상한1%, 고정 수신 여유20ms, 프레임10ms, 기존 출력 주기/패딩은 유지했다. 음성 프레임을 통째로 폐기하지 않지만 분수 보간에 따른 시간 압축과 샘플 내용 변화가 있으므로 무손실이라고 표현하지 않는다.

## 실제 출력 장치 A/B/A

위상 정렬 합성 RTP/native Opus를 각32초 출력하고14개 마커를 장치 스트림 위치와 대응했다. 이 구간은 수신 버퍼 입장→장치 스트림 시계이며 ADC·전송·DAC·귀까지의 물리 지연이 아니다. 장치 시계 대응은 렌더 소진이 없을 때만 유효하다.

| 장치 | A1 중앙값/P95 | 후보 중앙값/P95 | A2 중앙값/P95 |
|---|---|---|---|
| PC |30.106/30.147ms|30.122/30.145ms|30.053/30.255ms|
| 노트북 |58.377/60.352ms|52.666/52.811ms|58.305/60.522ms|

PC는 출력 용량=목표라 예산0이었다. 노트북은 요청/적용9ms, 남음/취소0, 최대 추가율5000ppm이었다. 두 장치 모두 총42개 마커 유효, PLC·재버퍼·부족·장치 소진0이었다. 노트북의 이 장치 시험에서 약5.7ms 감소했지만 실제 통화로 일반화할 수 없다.

## 두 독립 PC 직접 통화 A/B/A

PC와 노트북의 기존 유선 인터페이스를 검사 프로세스에만 지정했다. 시스템 기본 경로·VPN·공유기·장치 설정은 변경하지 않았다.45초와180초를 각각 A/B/A로 실행했고, 모든 회차 양쪽 연결·입퇴장·재참가를 완료했다.

45초의 같은 패킷을 대응한 내부 기간 합에서 PC→노트북 방향의 가중 평균/P95는 A1 45.882/54.418ms, 후보48.623/57.987ms, A2 44.820/53.295ms였다. 역방향 평균46.264/45.966/45.349ms였다. 이것은 동기화되지 않은 두 PC 시각의 차가 아니며, 네트워크 및 장치 전체를 포함한 입→귀도 아니다. 실제 통화에서는 목적 방향의 감소가 재현되지 않았다.

45초 세 회차의 PLC·늦음·재버퍼·부족·출력 소진은0이었다.180초 후보 회차에는 PC 수신 PLC2.5ms가 관측됐고 다른 기준선에서는0이었다. 해당 PC는 정착 예산0이므로 후보의 직접 효과로 단정할 수 없으며 희귀 사건의 인과는 미확정이다. 노트북 입력 불연속은45초 A/B/A에2/2/1회,180초에3/1/0회였다. 이를 PLC 전체의 확정 원인으로 연결하지 않는다.

## 해석과 판정

초기 일괄 가속은 실제 통화의 큰 시작 큐를 배출하는 기존 제어의 일을 대신할 수 있다. 실제 노트북에서는 시작 필터 큐가 약56.6/52.4ms였지만 최종 큐는 기준선·후보 모두 약25.2ms였다. 따라서 장치 단독 시험의 이득만으로 R1을 기본값에 승격하지 않는다.

후속 후보는 일회성 예산의 적용 시점과 장기 시계 편차를 분리해 검사한다. 기존 제어가 이미 낮은 큐를 유지하는 경우 악화시키지 않는지, 지터/손실/묶음 뒤 연속성이 유지되는지 먼저 확인한다. 실패 후보를 제품 옵션으로 계속 쌓지 않는다.

## 원본·복구·한계

Git 제외 `native/.local/extreme-146/`에 장치 원본,45/180초 각 A/B/A 보고서, 대응 분석과 실행 해시를 보존했다. 장시간 대조용 원래 검사 bin과 Runner를 별도로 백업했으며 최종 종료 시 둘 다 해시 검증해 복구한다. 해당 시험 종료 시 원본 DLL/Runner의 해시 일치와 자체 검사 프로세스0을 확인해 복구했다. 후속147도 별도 백업·복구를 완료했다.

실제 게임은 실행되지 않았다. 물리 입→귀, 외부 친구/독립 회선, 다인의 실장치 품질은 이 시험으로 검증하지 않았다. 운영 서버·기존 배포본·보안/전원/AP 설정은 바꾸지 않았다. 커밋·푸시·릴리즈를 하지 않았다.

## 기존 설정1시간 추가 관측

첫 후보 R1이 꺼진 동일146 검사 빌드로 직접 유선3600초와 이후 기능/정리를 양쪽 완료했다.PC는 PLC55ms·늦은 패킷1·출력 소진1회, 노트북은 PLC30ms·입력 불연속21회였다. 양쪽 재버퍼·무효/중복·복구/송신 폐기·공급 부족·안전 전환·입력 시각 오류는0이었다. 따라서 짧은 대조의0을 장시간 무오류로 일반화하지 않는다.출력 용량=목표인 PC는 소진이 있어도 추가 안전 전환0일 수 있다.

첫10초 이후 새 RTCP 보고만 추린 RTT 중앙/P95는 PC1.060/1.718ms(717개), 노트북0.790/1.250ms(724개)였다. 정상 네트워크 왕복이 짧아도 위 희귀 오디오 사건은 남았으며 RTT는 입→귀가 아니다.표본에서 본 최대 RTP 도착 간격은 PC27.376ms/노트북34.021ms다.1Hz 표본에 담긴 rolling max의 최댓값이지 모든 도착 간격을 별도로 보존한 전체 분포가 아니다.

후속 제어 후보의 기각·활성 소스 제거와 복구는 [147](EXTREME-147.md)를 참고한다.148에서 별도의 직접/TURN 출력 여유 대조를 진행한다.
