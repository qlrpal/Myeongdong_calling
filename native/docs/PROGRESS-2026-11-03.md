# 평상시 지연 개선 진행 정리

2026-11-03 · 대상 브랜치 `codex/extreme-latency`

## 목표와 현재 결론

최우선은 게임 소리와 함께 재생할 수 있는 WASAPI 공유 모드에서 평상시 실제 입→귀 지연을 줄이는 것이다. 버퍼 설정만 낮추거나 끊김을 증가시키는 변경은 개선으로 채택하지 않는다.

이번에 채택한 변경은 실제 출력 엔진 주기가5ms 이상인 bounded 공유 출력의 추가 안전 여유를5ms에서3ms로 줄이는 것이다. 짧은 주기 장치는 기존5ms 정책을 유지하고 장치 용량을 넘지 않는다. 기존 초기 여유·2초 정착·소진 시 전체 패딩 복귀를 유지했다. 수신 여유20ms, 기존 자동 모드 하한15ms,10ms 프레임, WebRTC 직접/TURN 및 수정 SDK는 그대로다.

시험 노트북의 수신 입장→장치 시계 지연 중앙값은 약59.95ms에서58.24ms로 약1.7ms 줄었다. 이는 물리 입→귀 전체 측정이 아니며, 모든 PC에서 같은 이득을 보장하지 않는다. PC의 짧은 출력 주기에서는 일관된 이득이 없어 기존 정책을 유지했다.

## 안정성 검증 범위

실제 PC↔노트북 유선 직접 통화로 기존→개선→기존을 각각180초 관측했다. **개선 설정 자체의 실제 통화 관측은180초**이며, 합계9분을 개선 설정9분으로 표현하지 않는다.

세 회차 모두 양쪽 PLC 음성시간·재버퍼링·PCM 부족·출력 소진·안전 전환·송신 폐기·늦은/중복/무효 패킷·복구 폐기·캡처 불연속 증가가0이었다. 양쪽 입퇴장·음소거·재참가 등6개 기능 검사와 원본 병합을 통과했다. 노트북 출력 목표15→13→15ms, PC5.833ms 유지, 수신 여유20ms 적용을 실제 표본에서 확인했다.

장치 지연 대조는 각32초/14개 신호로5→3→5ms를 비교했다. 프로세스 시작 위상에 따른 탐색 결과와 장치 시계에 위상을 정렬한 결과를 구분했다. 새 observer의 PCM 복사·시계 호출은 명시적인 장치 검사에서만 활성화되며 일반 통화에는 설치하지 않는다.

최종 `./native/verify.ps1 -NoRestore -Integration`은 경고/오류0 빌드, 오디오·복구·측정·UI·서버·실행기 회귀, 실제 로컬 SRTP·가변 프레임·IPv6를 통과했다. Python 분석 회귀12개도 통과했다. 최종 앱 DLL은 실제 두 PC 개선 회차의 바이너리와 해시가 일치한다. 검증 원본은 Git 제외 경로에 보존하고 개인 네트워크 정보·음성·인증 정보를 커밋하지 않는다.

## 남은 문제와 다음 검증

- 수시간 연속 통화, 실제 게임 부하, 다인, 강제 TURN/다른 회선·친구 환경에서 이번 변경의 안정성은 미검증이다.
- 물리 입→귀 전체 지연과 청감은 이번 측정 범위 밖이다.
- 과거 간헐적 출력 공급 공백과 별도 PLC의 원인은 여전히 미확정이다. 이번 정상 시험을 원인 해결로 표현하지 않는다.
- 다음에는 이번 출력 여유 변경의 게임/장시간 연속성을 확인하고, 평상시 캡처·프레임 조립·출력 대기를 같은 경계로 비교한다. 이미 기각한 프레임/수신 여유 후보를 근거 없이 반복하지 않는다.

## 실행·배포 상태

실행은 기존처럼 `./native/run.ps1`이다. 장치 주기에 따라 자동 선택하며 별도 설정은 필요하지 않다. 기존 공개 베타/배포 파일과 운영 서버는 갱신하지 않았다. 이번 요청은 소스·문서의 Git 커밋/푸시이며 새 릴리즈 게시와 구분한다.

노트북에 임시 교체한 검사 도구는 각 시험 후 원본 해시로 복구했다. 시스템 라우팅·VPN·공유기·장치·드라이버·전원 설정은 변경하지 않았다. 자세한 측정 한계와 기존 정책 복귀 방법은 [144 보고서](reports/EXTREME-144.md), 최신 실행 상태는 [CURRENT-STATUS](CURRENT-STATUS.md)를 참고한다.


## 야간·재개 후 추가 결과

위140~144 정리는 당시 검증 범위다. 후속145~147의 캡처/정착/PI 후보는 효과 또는 연속성 부족으로 제거했다.148 장시간 직접3회·TURN2회 완료와 마지막 실패,149의 복구·최종 회귀·일반 모드 다인·제어CPU 검증은 [최신149 보고서](reports/EXTREME-149.md)에 구분했다. 집중 다인의 출력 소진/PLC·입력 불연속은 남았고 새 물리 입→귀 감소는 입증하지 못했다. 현재 복구 대기는 없으며 제품 기본값/배포본을 유지한다.

## 후속 할당·송신 대조와 종합 정리

[150](reports/EXTREME-150.md)은 진단 통계 정렬을 무할당화해 동일PC6엔진의 전체 할당률 약6.1% 감소를 확인했다. [151](reports/EXTREME-151.md)은 정상10ms·같은 큐 정책의 전용 송신12회 대조를 완료했지만 전체 지연/품질 이득이 일관되지 않아 승격을 기각하고 비교 훅을 제거했다. 그룹 검사에는 기능 성공과 분리한 품질 카운터 및 소유 출력 단위 집계를 추가했다. 전체 Integration과 최종 상대별/공유 출력 확인을 통과했다.

전체 지연 예산·예상 원인·시험 줄기·미해결·다음 중단 기준은 [종합 보고서](reports/LATENCY-CAUSES-AND-TESTS-2026-11-03.md)에 정리했다. 문서 작성은 새 통화/게임 시험이 아니며, 내부52ms/80ms 산술 예산을 물리 입→귀 실측으로 승격하지 않는다. 새 베타/릴리즈/운영 서버 배포는 이번 Git 정리의 범위 밖이다.
