# 앱 정상 동작 자동 검사

흩어진 TransportProbe 검사를 한 명령으로 실행하고, 실패 원본과 판정 범위를 보존한다. 검사를 통과했다는 이유로 지연·음질·전체 앱 완성을 선언하지 않는다. 별도의 테스트 실행 도구이며 일반 통화 앱의 실시간 경로는 변경하지 않는다.

## 실행

Windows10 2004 이상, .NET10 SDK, Node.js22 이상에서 저장소 루트를 기준으로 실행한다. 첫 실행은 고정 의존성을 복원하고 빌드한다.

```powershell
./native/test-app.ps1                            # core: 장치를 열지 않는 기능·로컬 전송 검사
./native/test-app.ps1 -Profile devices            # core + 실제 장치 참가/퇴장/복구 검사
./native/test-app.ps1 -Profile group              # devices + 두 출력 방식의 2·3·6엔진 검사
./native/test-app.ps1 -Profile devices -NoRestore # 복원 캐시가 준비된 경우
```

`-NoBuild`는 기존 Release 바이너리를 검사한다. 소스 변경을 반영하지 않으므로 일반적으로 생략한다. 결과에는 이 옵션·실제 DLL SHA256·Git HEAD·미커밋 변경 유무가 기록된다. Git 정보가 없는 ZIP 소스에서도 검사할 수 있다. 실행 경로가 바뀌면 Windows 앱 방화벽 허용이 필요할 수 있지만 이 도구는 방화벽·라우팅·공유기·기본 장치 설정을 바꾸지 않는다.

devices/group는 기존 통화를 종료한 뒤 실행한다. 실제 공유 입력/출력을 열고, 인코딩 전 마이크 PCM을 자동 생성한48kHz 모노16bit 합성 파형으로 교체한다. 실제 마이크 음성은 전송하지 않는다. 시험 소리가 들릴 수 있다. 시스템 음량을 바꾸지 않는다. RDP 세션에서 장치가 보이지 않으면 장치 단계는 실패하고 종속 시험은 미실시로 남긴다.

## 자동 판정

| 범위 | 검증 |
|---|---|
| 빌드 | 고정 의존성 복원, 경고를 오류로 처리한 Release 빌드 |
| core | 수정 SDK 식별, 제품 제어·정리/동시성·믹서 회귀, 진단 읽기 위치/선택·로그 추적, RTP 버퍼, 장치 주기별 합성 복구, PCM 변환, localhost IPv4/IPv6 SRTP/RTCP, 가변 프레임, 서버 회귀 |
| devices | 기존/단일 출력 각각 실제 엔진3개. 정리 오류 주입 후 나머지 해제, 잘못된 장치 안내, 이전 세션 정리 격리, 참가/퇴장/재참가, SSE 종료 복구, 서버 퇴장 응답 정지 |
| group | 같은 PC의2·3·6엔진. 출력 재시작·음소거·상대 마이크 상태 전파/독립성·음소거 유지 재참가·입퇴장·새 통화 |
| 검사 도구 자체 | 비정상 종료·보고서 누락·시간 초과·취소를 실패로 판정, UTF-8 로그 보존 |

한 검사가 실패해도 독립된 후속 검사는 계속한다. 빌드·장치 준비 실패처럼 전제 조건이 깨지면 종속 검사를 통과로 표시하지 않는다. 실패한 시험을 자동 반복하지 않는다. 프로세스 제한 시간이 지나면 자신이 시작한 프로세스 트리를 종료하며, 사용자 앱이나 서버를 열거해서 종료하지 않는다. Ctrl+C는 실행 중 시험을 취소하고 결과를 남긴다. 강제 창 종료·전원 종료 상황의 보고서 완료는 보장하지 않는다.

## 결과 확인

매번 `native/.local/app-checks/<UTC시각>-<고유값>/`에 새 폴더를 만든다. 경로는 종료 시 표시하며 기존 결과를 덮어쓰지 않는다.

- `summary.md`: 사람이 읽는 검사별 결과·미실시·한계.
- `summary.json`: 자동 비교용 스키마1. 실행 중은 `running`, 최종 결과는 `pass`, `fail`, `incomplete`이며 각 단계의 로그·종료 코드·소요 시간·시간 초과/취소 여부를 남긴다. 완료 시각 없는 실행 중 보고서를 합격으로 취급하지 않는다.
- 검사별 `.log`, lifecycle/group 원본 JSON: 실패 원인 확인. 한글은 UTF-8로 저장한다.
- 생성 WAV: 재현 가능한 합성 파형. 과거 합성 음성 WAV와 CPU/비트레이트를 동일 조건으로 비교하지 않는다.

선택 범위 밖의 항목은 `outsideScope`와 미실시 목록에 남긴다. 예컨대 core의 성공은 실제 장치 검사를 포함하지 않는다. 선택한 검사 중 실패 또는 필요한 단계 미실시가 있으면 종료 코드1, 모두 완료하면0이다. core는 full `verify.ps1`의 모든 성능·버퍼 정책 검사를 대신하지 않는다.

진단에는 로컬 주소·장치 식별자 등이 포함될 수 있다. 전체 폴더는 Git 제외이며 사용자 진단 원본을 커밋하지 않는다. 로그·기존 dist·사용자 설정은 덮어쓰지 않는다.

## 두 PC 사용

PC와 노트북에서 같은 커밋으로 `-Profile devices`를 각각 실행하면 장치/로컬 기능 준비 상태를 같은 방식으로 확인할 수 있다. **이 명령은 두 PC를 서로 통화시키는 시험이 아니다.** 두 결과가 모두 통과한 다음 [두 PC 자동 기능 검사](PAIR-CHECKS.md)의 `test-pair.ps1`로 확장한다. 기존 [두 호스트 그룹 시험](TWO-HOST-GROUP-TEST.md)은 별도다. 게임 부하·장시간 연속성·물리 입→귀 지연은 추가 검증이 필요하며 단일 PC 성공으로 집 무선 문제나 원격 통화 품질 해결을 판정하지 않는다.

## 장치 주기별 합성 복구 관측

core의 `recovery-device-periods`는 실제 장치를 열지 않고128/256/480샘플 요청, 두 렌더 위상,10/20ms Opus와 정상/재정렬/밀린 도착/손실 조건120개를 실행한다. `recovery-device-periods.json`에 첫 재생·신선한 프레임 복귀·무음·PLC·복구 폐기를 기록한다. 기존 bounded-tail 후보와의 합성 대조이며 제품 기본값을 바꾸지 않는다.

이 단계의 pass는 정상 입력·큐/PLC 상한 등 회귀 검사의 성공이다. 일부 복구 측정이 null이어도 정상 복귀로0ms 대체하지 않는다. `qualityQualified:false`·`physicalLatencyMeasured:false`를 명시하며 제품 품질/지연 우위 합격과 구분한다. 자세한 결과와 한계는 [117 보고서](reports/EXTREME-117.md)에 기록했다.
