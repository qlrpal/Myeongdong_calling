# 모바일 핫스팟 외부망 시험

PC는 집 인터넷, 노트북은 휴대전화의 모바일 데이터 핫스팟을 사용한다. 시험 중 SSH는 필요하지 않다. 기존 통화 앱과 진단 실행기를 종료한 뒤 진행한다. 휴대전화가 집 Wi-Fi를 재공유하는 조건과 구분하기 위해 휴대전화 Wi-Fi를 끄고 모바일 데이터가 연결된 상태에서 핫스팟을 켠다. 노트북은 핫스팟 연결 후 인터넷 접속을 확인한다. 포트포워딩은 추가하지 않는다.

## 준비된 실행 위치

- PC: `C:\Users\begemi\Desktop\coding\voice_call\native\.local\external-test-059\test-external.cmd`
- 노트북: 실행 창(Win+R)에 `%USERPROFILE%\voice-external-test-059\test-external.cmd` 입력.

이미 두 기기에 실행기·의존 DLL·합성 발화 파일을 복사했다. 각 기기의 기존 .NET 실행 환경을 사용한다. 관리자 실행은 필요하지 않다. 이전 LAN IP를 고정하지 않고 OS 기본 경로를 사용한다. VPN이 활성화돼 있다면 그 경로도 시험 조건에 포함된다.

## 1회차: 자동 경로

1. 양쪽 실행기를 연다.
2. `Role`에는 PC에서 `pc`, 노트북에서 `laptop`을 입력한다.
3. `Mode`에는 양쪽 모두 `auto`를 입력한다.
4. `Run ID`에는 양쪽 모두 `20a`를 입력한다. 재시험 때는 `20b`처럼 바꾼다.
5. 양쪽을2분 안에 시작한다. 연결 후5분 동안 합성 문장을 자동 송수신하고 종료한다. 별도 마이크 발화는 필요하지 않다. 합성 음성이 상대 출력에서 들린다.

자동 경로는 직접 연결을 우선 시도하고 필요하면 TURN을 사용한다. 직접 연결에 성공했다는 의미가 아니며 실제 경로는 진단 JSON의 `Peers[].Route`로 확인한다. 실행 중 네트워크를 바꾸거나 창을 닫지 않는다. 게임 부하를 비교하려면 두 회차 모두 같은 게임 장면을 유지한다.

## 2회차: TURN 강제 경로

양쪽1회차 종료 후 실행기를 다시 열고 같은 Role·Run ID를 입력하되 Mode만 양쪽 모두 `relay`로 바꾼다. 다시 연결 후5분간 진행한다. 이 회차는 TURN 경로만 허용하며 직접 연결로 조용히 대체하지 않는다. 선택 경로가 TURN인지 검사한다.

## 결과 전달

각 실행 폴더의 `results`에 회차별 `.json`과 `.log`가 저장된다. 정상 완료는 `Exit code: 0`으로 표시한다. 실패해도 결과와 로그를 보관한다. 강제로 창을 닫으면 JSON이 완성되지 않을 수 있다. 로드 단계 등 연결 전 오류는 로그만 남을 수도 있다.

두 회차 뒤 노트북을 집 Wi-Fi로 다시 연결하고 알려주면 SSH로 결과를 회수할 수 있다. 직접 전달할 때는 양쪽 `results`의 두 회차 파일을 모두 전달한다. 진단에는 IP와 상태 정보가 포함되며 실제 마이크 원음은 저장하지 않는다.

이 시험은 외부망의 연결 성공·선택 경로·RTT·PLC·버퍼 부족·큐 변화를 확인한다. 실제 입→귀 지연 측정은 아니다. 휴대전화 이동통신 지연과 핫스팟 Wi-Fi 변동이 포함된다. 같은 장소의 PC·노트북 시험으로 먼 지역 친구와의 경로까지 검증한 것으로 해석하지 않는다.

## 구현 검증 범위

Release 빌드 경고0·오류0, 기존 회귀 검사, 서버7개, 로컬 WebRTC 통합 검사 통과. 현재 OCI에서 relay 전용 ICE·DTLS/SRTP·RTCP 통합 연결도 통과했다. 노트북 실행 파일·WAV·스크립트 존재와 실행을 확인했다. 핫스팟의 두 기기5분 회차는 사용자가 실행할 단계이며 아직 완료하지 않았다.
