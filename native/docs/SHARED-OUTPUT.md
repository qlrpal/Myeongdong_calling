# 공통 출력 비교 경로

게임 소리와 함께 재생하는 WASAPI 공유 모드는 유지한다. 상대별 출력 스트림을 사용하는 기존 경로와, 통화당 하나의 출력 스트림을 사용하는 후보를 선택해 비교할 수 있다. 기본값은 기존 경로다.

```powershell
./native/run.ps1 -SharedOutput
./native/run.ps1 -SharedOutput -Experiment opus-adaptive
```

패키지 실행 파일에서는 `VoiceNative.exe --shared-output true`를 사용한다. 이 옵션은 프레임·재생 여유·네트워크 선택을 바꾸지 않으며 설정 파일에 저장하지 않는다. 옵션을 생략하고 다시 실행하면 기존 출력으로 돌아간다. `dist`는 별도 빌드 전까지 이전 파일이다.

## 구조와 동작

각 상대의 인증된 RTP → 독립 RTP 버퍼·Opus 디코더·시계 보정 → 상대별 볼륨 → 공통 콜백의 PCM 합산 → WASAPI 공유 출력 하나로 연결한다. 상대별 PCM을 읽은 즉시 합산하므로 믹서 앞에 추가 재생 FIFO는 없다. 음소거해도 해당 상대의 시간축은 계속 소비한다. 패킷이 없는 상대는 자신의 기존 PLC/무음 정책을 사용하며 다른 상대의 패킷 도착을 기다리지 않는다.

기존 RAW 요청·저지연 요청·장치 호환 경로·출력 안전 복귀는 `WindowsAudioDevice`와 `SharedRenderPlayer`를 재사용한다. 출력의 초기 준비는 준비된 상대가 하나라도 있으면 진행한다. 통화 도중 참가한 상대 때문에 이미 진행 중인 출력의 초기 준비를 다시 기다리지 않는다.

입퇴장은 소스 배열을 교체해 알리고, 렌더는 구성원 목록 잠금을 잡지 않는다. 상대 제거는 진행 중인 읽기의 종료를 기다린 뒤 해당 버퍼를 해제한다. 정상 수신에서는 기존 상대별 버퍼의 짧은 잠금·디코딩 비용은 여전히 존재한다. 느린 디코더/스케줄링이 공통 렌더 마감을 넘기는 경우까지 없어진 것은 아니다.

합산은 넓은 정수 범위에서 수행하고 마지막 PCM16 변환에서 포화시켜 정수 wrap을 막는다. 상대 수에 따라 자동으로 전체 볼륨을 낮추지 않는다. 여러 큰 신호가 겹치면 포화 왜곡이 생길 수 있으며 진단의 `ClippedSamples`에 기록한다. 고급 리미터·공간 음향·스테레오 전송 구현은 아니다.

한 상대의 예상치 못한 PCM 읽기 오류는 그 상대를 무음 처리하고 진단에 남긴다. 출력 재시작은 공통 장치를 한 번 다시 열고 각 상대의 기존 버퍼를 재개한다. 실제 출력 장치 오류는 모든 상대에 영향을 주며 기존의 한 번 자동 복구 정책을 사용한다. 마지막 상대가 나가면 출력 스트림을 닫고, 다음 상대 참가 시 새로 만든다.

## 진단과 검증

진단 JSON의 `SharedOutput`에는 등록 상대 수·활성 상대 수·소유한 출력 스트림 수·포화 샘플 수가 들어간다. 기존 경로에서는 이 필드가 null이다. 통화 상대가 있으면 후보의 출력 스트림 수는1, 혼자 남거나 통화에서 나가면0이어야 한다. 이 값은 앱이 소유한 출력 객체 수이며 Windows 전체 오디오 세션을 조사한 값은 아니다.

상대별 RTP 큐·PLC·부족·디코딩 지표는 독립 값이다. 후보의 상대별 장치/렌더 지표는 **같은 공통 출력의 관측을 반복해서 보여주는 것**이므로 상대별 장치 소진 횟수 등을 합산하면 안 된다. RTP 큐와 출력 장치 대기도 구분한다. RTCP RTT나 스트림 감소를 입→귀 지연 감소로 표현하지 않는다.

```powershell
./native/verify.ps1 -NoRestore -Integration
./native/TransportProbe/bin/Release/net10.0-windows10.0.19041.0/TransportProbe.exe --shared-output-checks
./native/TransportProbe/bin/Release/net10.0-windows10.0.19041.0/TransportProbe.exe --audio-devices
```

`--shared-output-checks`는 합산·볼륨·시간축 유지·포화·소스 오류/부족 격리·분리 수명·믹서 읽기 할당을 검사한다. 서로 다른 프레임/송신 시계와 한쪽 입력 공백을 넣어, 각 RTP 버퍼를 따로 읽은 결과의 합과 공통 출력 결과도 비교한다. 물리 장치가 필요하지 않다.

실제 장치와 로컬 서버를 사용하는 그룹 검사는 다음 형식이다.

```text
TransportProbe.exe --local-group-output SERVER_URL REPORT.json SPEECH.wav true opus-adaptive
TransportProbe.exe --local-output-soak SERVER_URL REPORT.json SPEECH.wav true opus-adaptive 60
```

`true`를 `false`로 바꾸면 기존 출력이며 나머지 조건은 유지한다. 이 도구는 **동일 PC에2·3·6개 엔진**을 실행하고, 조용한 합성 음성·상대별 볼륨0.01로 연결·재시작·입퇴장·재참가·혼자 남기·새 통화를 확인한다. 별도 시험용 서버/방을 사용한다. 추가 마지막 인수 `true`는 입력 장치 대신 타이머로 공급한 PCM을 쓰는 명시적 진단 모드다. 일반 앱에는 합성 입력을 자동 적용하지 않는다.

현재 결과와 제한은 [107 보고서](reports/EXTREME-107.md)에 기록한다. 두 PC 이상의 독립 장치 시계·외부 회선/TURN·실제 게임 부하·물리 입→귀 지연은 별도 검증이며 이 후보의 기본값 승격 조건으로 남긴다. 기존 집 네트워크 공백은 해결된 것으로 취급하지 않는다.
