# 양쪽 사건 연결과 기록 재준비

자동 기록의 배경/워밍업/처리 경계는 [자동 문제 기록](INCIDENT-RECORDING.md)을 따른다. 상대와 같은 자료를 찾기 쉽게 사건 ID를 교환하지만 물리 원인이 같다는 판정이나 시계 동기화는 아니다.

## 사용

1. 양쪽에 이 기능이 있는 최신 소스를 실행한다. 기존 공개0.6.1-beta.1 ZIP은 지원하지 않는다.
2. 상세 진단에서 상대 지원/확인 상태를 확인한다. `지원`은 프로토콜 응답을 받았다는 뜻이다. 응답 없음은 구버전·연결 상태 등 여러 원인이 가능하다.
3. 한쪽의 자동 사건을 상대에게 알리고 같은 ID를 상대 기록에 포함하도록 요청한다. 이미 비슷한 구간을 수집 중이면 서로의 ID를 연결한다. 오래된 사건을 보존 중이면 덮어쓰지 않고 busy를 응답한다.
4. 후속 문제를 기다리려면 **양쪽에서** `기록 다시 준비 (이 PC)`를 누른다. 통화·마이크·송신 큐·RTP 시간축은 재시작하지 않는다. 첫 상대 음성부터2초간 트리거를 유예한다.
5. 문제 뒤2초 이상 기다리고 양쪽 진단을 저장한다. 복사/저장 시 송신·수신·재생 경계, 사건 전후, 누락, 상대 확인을 로그에 표시한다.

재준비는 해당 PC에만 적용한다. 상대가 보낸 알림으로 사용자의 이전 자료를 지우지 않는다. 재준비 전 자료와 당시 상대 상태는 최근2개까지 `incidentDetails.History`에 보관한다. 세 번째 이전 자료부터 빠지며 `HistoryEvicted`에 수를 남긴다. 수집 도중 다시 준비했다면 그 자료는 부분 기록(Archived/manual-rearm)이다. 이미 동결됐던 자료는 원래 EndReason을 유지하고 OriginalState에 보관 전 상태를 남긴다. 앱 강제 종료 시 메모리 자료는 사라진다.

## 보고서

- `incident.EventId`가 주 사건 ID다. `LinkedEventIds`는 겹치는 수집 구간에서 받은 연관 요청 ID다. 양쪽 주/연관 ID 집합의 교집합을 먼저 찾고 SSRC/RTP 타임스탬프로 실제 패킷을 대응한다.
- `incidentDetails.Peers`: 연결 지원 여부, 보낸 사건 ID·수락 응답·시도 횟수, 받은 사건 ID·이 PC의 처리 결과다. 종료한 상대 상태도 제한적으로 남기며 Connected=false다.
- `incidentDetails.Review`: 송신/수신/재생 경계·사전/사후 기록 여부, 상대 확인 수, 기록 충돌/덮어쓰기 수와 판정 한계다.
- `incidentDetails.History`: 이전 Capture와 당시 Peers. 현재 기록과 과거 기록을 섞어 손실 수를 계산하지 않는다.

**상대 확인은 메타데이터 수집 요청에 대한 수락 응답이다. 상대 JSON 파일의 확보·완전성·저장을 보장하지 않는다.** 양쪽 파일을 별도로 모아야 한다. 상태/경계가 모두 있어도 기록 충돌·상한·미계측 경계가 남는다.

## 비용과 보호

기존 암호화 데이터 채널과 진단 갱신 경로를 재사용한다. 캡처·렌더 콜백은 JSON 직렬화·상대 알림·파일 쓰기를 하지 않는다. 새 타이머나 프레임별 Task를 만들지 않는다.

연결당 지원 질의는 최대3회, 각 사건 알림은 최대3회이며1초 간격을 둔다. 보낸 ID와 맞지 않는 늦은 응답은 무시한다. 수신 메시지는384바이트 이하의 알려진 형식·GUID만 받고, 상대별1초 제한을 둔다. 최근 보관한 라운드의 알림이 늦게 와도 새 기록을 덮어쓰지 않는다. 요청/응답에는 사건 ID와 상태만 넣고 음성·IP·닉네임·토큰을 추가 전송하지 않는다.

알림은 진단 갱신이 돌 때 전송된다. 최소화·부하·채널 지연 등으로 늦을 수 있으며2초 창 안 전달을 보장하지 않는다. 양쪽 시각을 직접 차감하지 않는다. 지원하지 않는 상대의 음성 통화는 유지되며 사건 연결 상태만 미확인으로 남는다.

## 개발 검증

`./native/verify.ps1 -NoRestore -Integration`은 프로토콜·기록·기존 통화 회귀를 포함한다. 자동 두 참가자 도구에 한해 프로세스 환경 변수 `MYEONGDONG_TEST_INCIDENT_MODE`를 auto/off/exercise로 지정할 수 있다. 기본은 auto이며 일반 앱 설정/시스템 환경 변수는 바꾸지 않는다.

exercise는 기준선 뒤 양쪽 기록을 다시 준비하고 한쪽의 명시적 시험 사건으로 ID·수락·동결·이전 기록·같은 피어 유지 여부를 검사한다. off는 기록과 사건 알림을 끈 비교용이며 체크포인트 호출식 자체를 제거한 과거 바이너리와 같은 것은 아니다. 모드는 암호화 검사 단계 핸드셰이크에 포함돼 양쪽이 다르면 실패한다. 실제 결과와 미실시 범위는 [130 보고서](reports/EXTREME-130.md)를 따른다.
