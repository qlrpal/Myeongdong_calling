# 0.3.3 개발 기준점 · 2026-10-07

현재 버전을 다음 개발의 기준으로 보존합니다. 잔여 버퍼·지연 미세 튜닝은 앱 완성 후 유지보수로 진행합니다.

이후 사용자 우선순위는 **지연 1순위, 음질 2순위**로 확정했습니다.
0.4.0은 양쪽 지연 구성 교환과 테스트음을 이용한 캡처→상대 스피커 재캡처 측정을 추가합니다.
단계별 합산 모델과 실제 음향 경로 검출을 구분하며 물리 두 PC 시험은 사용자 환경에서 추가 확인해야 합니다.
다음 순서는 측정으로 대기 구간을 파악하고 지연을 줄인 뒤, 그 수준을 유지하면서 음질을 개선하는 것입니다.

## 완료

- 기존 웹 프로젝트와 네이티브 앱/서버 분리
- C#/.NET Windows 앱과 Node.js 연결 관리 서버
- 네이티브 WebRTC ICE·DTLS/SRTP·Opus 통화, 향후 엔진 교체를 위한 ICallEngine 분리
- Opus 48kHz 모노/20ms 프레임, WASAPI 공유 모드의 입력·출력
- 마이크 콜백과 네트워크 송신 분리, 제한된 송신 큐와 명시적인 RTP 시간축
- 장치 오류 표시, 한 번의 자동 출력 복구, 통화를 유지하는 수동 출력 재시작
- 실시간 RTT·양방향 보고 손실·지터·패킷 간격·코덱/콜백 처리 시간·장치 상태
- 큐 누적·버퍼 부족·부족 길이·송신 대기/버림 진단
- LAN UDP/경로/ping 검사, 읽을 수 있는 UTF-8 한글 JSON 저장·복사
- 빌드 스크립트와 전송·RTCP·재생·입력 검증 도구

## 검증한 범위

- 동일 공유기의 Windows PC 두 대에서 실제 음성 통화
- Tailscale 내부망 우회 문제를 식별하고 해제 후 직접 연결 확인
- 기존 WaveOut의 느린 소비를 재현하고 WASAPI 전환 후 큐 누적과 심한 끊김 개선
- 물리 이어폰 분리 중 캡처 공백과 출력 오류/자동 복구 확인
- 마지막 양쪽 비교 보고서는 0.3.2: 약 4분 통화, 큐 정리/송신 큐 버림/양방향 보고 손실 0
- 해당 보고서의 마지막 큐는 약 60~62ms, 버퍼 부족은 노트북 0회/PC 6회
- PC 부족 구간의 요청·소비량 차이 합계는 약 48ms로 추정
- 0.3.3은 코덱 사전 준비와 부족 길이 계측을 보완했으며 실제 입력·버퍼 테스트/빌드 통과

0.3.3의 새 양쪽 장시간 보고서는 아직 확보하지 않았습니다. 전체 음성 지연과 주관적 음질은 아직 정밀 측정하지 않았습니다.

## 유지보수로 이관

- 잔여 순간 버퍼 부족과 시작 시점의 오디오 처리 지연
- 장치 전환/분리 중 캡처 중단 시간 최소화
- 더 낮은 입출력 버퍼, 클록 차이 보정과 세밀한 지터 튜닝
- 재현 가능한 양쪽 음질/종단 간 지연 측정과 환경별 회귀 검증

기능 개발 중 심한 끊김이나 연결 실패가 재발하면 해당 회귀는 즉시 수정합니다.

## 다음 기능 개발 순서

1. **장치와 음질 설정:** 마이크/출력 장치 선택, 음소거/볼륨, Opus 품질 프로필과 적용 상태 표시. 기존 안정 프로필을 유지하며 새 설정을 추가합니다.
2. **외부망 연결:** Ubuntu TURN, 만료되는 중계 자격 증명, 서로 다른 회선에서 직접/중계 연결 검증. 기존 HTTPS 프록시를 활용하고 서버 자동 시작/재시작을 구성합니다.
3. **앱 사용 흐름:** 참가자/통화 상태 화면, 방 입장/초대, 이해하기 쉬운 실패 안내와 재접속. 정밀 진단은 별도 화면으로 분리합니다.
4. **배포:** 런타임을 포함한 Windows 패키지, 버전 표시, 설정 저장, 라이선스 고지와 설치/업데이트 방식 정리.
5. **완성 검증:** 다른 장치·회선, 장시간·그룹 통화, 권한/장치 변경/네트워크 단절 검증. 실제 결과로 지원 범위 확정.

현재 최대 6명 메시 구현은 그룹 실통화 미검증입니다. OCI UDP TURN과 만료 자격 증명 발급은 배포 및 중계 전용 검증을 완료했습니다. 다른 회선의 실제 통화는 추가 검증 대상이며 현재 배포는 .NET Desktop Runtime이 필요합니다.
커스텀 전송 엔진, 계정/채팅/화면 공유 등 추가 기능은 기본 통화 앱 완성 후 별도로 판단합니다.

0.4.1: 로컬 WASAPI 출력 제출→자기 마이크 QPC 재캡처 기준 5회 검사를 추가했습니다. 실제 입력/출력 장치명과 API 지연, 성공 결과를 JSON에 보관합니다. 로컬/통화의 기준점 차이와 송신 ADC 미측정 한계를 명시하고, DSP·장치 교체 시 한 조건씩 반복하도록 안내합니다. 버퍼 설정은 유지합니다.

0.4.2: 출력 대기 비교 40→30→20→40ms 각 5회를 추가했습니다. 요청값/실제 API 지연/회차/검사 ID를 저장하고 중앙값과 성공 횟수를 로그에 표시합니다. 기본 통화 설정은 유지하며 실제 두 PC와 장치 검사는 별도 확인이 필요합니다.

0.4.3: 통화 출력 40/20ms 선택과 통화 중 출력 재시작 적용을 추가했습니다. 기본 40ms를 유지하고 요청 설정을 피어 진단에 저장합니다. 지속 통화 비교는 사용자 환경에서 진행합니다.

0.4.4: 실제 출력 장치 WASAPI 루프백 측정과 자동 SSH 통화 검사를 추가했습니다. 두 PC 노트북→컴퓨터 40/20ms 각 5회 검출 성공. 이번 루프백 대표값은 약155ms로 차이가 확인되지 않았으며 실제 입→귀 지연과 구분합니다. 자세한 제한과 재현 방법은 README에 기록했습니다.

0.4.5: 동일 Opus 패킷의 단계별 시각 추적과 출력-검출 일관성 검증을 추가했습니다. 실제 SSH 재검사에서 유효9회 결과를 확보했고, 소프트웨어로 분리되지 않는 물리 장치 구간과 계측 부하 한계를 명시했습니다. 입력/Opus/기본 출력/큐 정책은 유지합니다.

0.4.6: 개인 장치 설정을 제외하고 앱 입력 요청 버퍼10ms, 고정 입력 버퍼/Span 복사, PCM 링 버퍼와80ms 초과 대기 정리(40~60ms 유지),5ms 전환 처리를 추가했습니다. Opus20ms 프레임/음질 및 초기40ms reserve는 유지합니다. 실제 두 PC 자동 통화와 관련 검증을 통과했으며 첫 콜드 진단의 일회성 지연은 별도 기록했습니다.

0.4.7: IAudioClient3 공유 저지연 모드, 실제 활성/주기/복귀 사유, 네이티브 입력 형식 변환과 출력 mix-rate 리샘플링을 추가했습니다. 1.33ms 노트북 입력의 실측 송신 정지를 발견해5ms 미만은 표준10ms 입력으로 복귀합니다. 수정 후 양방향 송수신/루프백10회 성공. 지연의 큰 개선은 입증되지 않았으며 단시간 검사에서 출력 버퍼 부족이 남아 표준 모드 선택을 제공합니다. Opus20ms/초기40ms reserve는 유지합니다.

0.4.8: Opus 송신을10ms/480 samples로 단축하고 RTP 시간축/상대 프레임 진단/검출 프레임 조립을 맞췄습니다.20ms 시작 reserve/60ms 큐 상한은 실제 통화에서 부족이 늘어 철회하고40ms reserve/80ms 상한을 유지합니다. 양쪽 실제 통화, WebRTC/RTCP, 서버5개, 실제 입력과 저지연/표준 출력 재시작 검증 결과는 [VERIFICATION.md](reports/VERIFICATION.md)에 기록합니다. 순간 부족과 물리 종단 간 지연은 완료로 선언하지 않습니다.

0.4.9:0.4.8 실행 파일/소스 기준을 보존하고 Opus VOIP와Restricted Low Delay의64/96kbps 비교를 추가했습니다. 기존 비트스트림 동일성, 합성 신호2회, 실제 WebRTC 비교4모드와 마이크 검사가 통과했습니다. 보고된 코덱 선행 대기는6.5→2.5ms입니다. 기본값과 수신 버퍼 정책은 유지하며 실제 발화·두 PC 총 지연 비교는 남았습니다. 상세: [OPUS-COMPARISON.md](reports/OPUS-COMPARISON.md).
