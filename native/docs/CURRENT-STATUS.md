# 현재 구현·검증 상태

2026-10-22 / `codex/extreme-latency`. 제품 기반 버전은0.6.0이며 이 브랜치는 극저지연 실험과 앱 최적화를 포함한다. 안정판 전체 대체나 새 릴리스 태그 확정 상태는 아니다.

## 목적과 실행

Windows에서 게임과 함께 사용하는 음성 통화 앱이다. 우선순위는 **지연 → 음질 → 부가 기능**, 오디오는 WASAPI 저지연 공유 모드를 사용한다. WebRTC 직접 연결을 우선하고 필요한 환경에서는 TURN을 사용한다.

저장소 루트에서:

```powershell
./native/run.ps1                            # 기존 기본 구성
./native/run.ps1 -Experiment opus-adaptive  # 극저지연 실험 구성
./native/verify.ps1
./native/verify.ps1 -NoRestore -Integration
```

.NET10 SDK·Node.js22 이상과 Windows10 2004 이상이 필요하다. 양쪽 통화 앱에 같은 브랜치의 최신 빌드를 사용한다. 자세한 선택 조건은 [실험 가이드](EXTREME-LATENCY.md), 소스 업로드 범위는 [Git 가이드](GIT-RELEASE.md)를 참고한다.

## 구현된 내용

- 방 참가/나가기, 장치 선택, 마이크 음소거, 상대 볼륨, 연결 복구, 진단 내보내기.
- 기존10ms Opus 경로와 선택적2.5/5ms Opus, 짧은 적응 수신 여유, 공유 입출력과 지원 범위 내 장치 주기 선택.
- 장치 버퍼 조기 반환·초기 소프트웨어 준비·출력 공급 계측 및 앱별 JIT 정책 대조.
- 송신의 전역 피어 잠금 제거와 피어 종료 시 진행 중 송신의 수명 보호.
- 수신 패킷 풀·제한된 정렬 저장소·값 형식 송신 메타데이터·선택적 진단 closure 분리로 반복 할당 감소.
- 직접/전용 송신 비교 옵션과 재현 도구. 기본 실험 구성은 직접 송신을 유지한다.

주요 근거: [067 장치 경로](reports/EXTREME-067.md), [068 JIT·공급](reports/EXTREME-068.md), [077 송신 수명](reports/EXTREME-077.md), [078 할당·송신 대조](reports/EXTREME-078.md).

## 검증 결과와 한계

최종 Release 빌드 경고/오류0, 관리형 회귀·서버8개·로컬 ICE/DTLS/SRTP/RTCP/재생 통합을 통과했다. 패킷 저장소 변경의 스트레스 검사도 통과했다. 실제 같은 PC의 두 앱 엔진·공유 장치 대조는 기능 시험이며 서로 다른 두 PC나 장시간 품질 검증을 대신하지 않는다.

워밍업 국소 시험에서 송신 메타데이터136→0 B/packet, Opus2.5ms 수신+재생4,464→3,944 B/packet을 확인했다. 이는 전체 앱 무할당이나 입→귀 지연 개선량이 아니다. 전용 송신은 추가 큐 대기·시작 손실·연속성의 교환이 있어 기본값으로 승격하지 않았다.

집 네트워크 조사에서는 앱 상위 처리보다 아래의 대기, 별도 AP 및 다른 NIC에서도 지연을 확인했다. 최종 물리 원인은 미확정이며 이 조사는 보류한다. [071](reports/EXTREME-071.md)~[076](reports/EXTREME-076.md)의 환경별 관측을 모든 사용자에게 일반화하지 않는다. 과거 장시간TURN 연속성 실패도 이후 국소 시험 통과만으로 해소됐다고 판정하지 않는다.
