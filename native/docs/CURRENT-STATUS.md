# 현재 구현·검증 상태

2026-10-27 / `codex/extreme-latency`. 제품 기반0.6.0이며 새 안정판 태그나 기존 버전 전체 대체를 확정하지 않았다.

## 목표와 실행

게임과 함께 사용하는 Windows 통화 앱이다. 우선순위는 **실제 지연 → 게임 중 연속성 → CPU·GC·스케줄링 부담 → 음질 → 부가 기능**이며 WASAPI 저지연 공유 모드, WebRTC 직접 연결 우선·TURN 대체 경로를 사용한다.

```powershell
./native/run.ps1                            # 기존 기본 구성
./native/run.ps1 -Experiment opus-adaptive  # 선택적 지연 우선 비교 후보
./native/verify.ps1 -NoRestore -Integration
```

.NET10 SDK·Node.js22 이상, Windows10 2004 이상이 필요하다. 양쪽에 같은 소스의 최신 빌드를 사용한다. [실행/모드 가이드](EXTREME-LATENCY.md), [Git 소스 배포](GIT-RELEASE.md), [두 호스트 그룹 시험](TWO-HOST-GROUP-TEST.md)을 참고한다. 로컬 변경은 커밋·푸시 전까지 원격에 반영되지 않는다.

## 구현된 내용

- 방 참가/나가기, 최대6명 메시, 장치 선택, 마이크/상대 음소거·볼륨, 연결 복구, UTF-8 진단 내보내기.
- 기본10ms Opus와 선택적2.5/5ms·PCM 시험, 수신 시간축/PLC·큐 상한·장치 시계 보정, 지원 범위 내 공유 장치 주기 선택.
- 전역 피어 잠금 없는 송신과 종료 수명 보호, 패킷 풀/제한 정렬 저장소, 캡처·렌더 경로 계측.
- 선택적 양쪽 패킷/마감 기록 분석과 실제 두 호스트 다중 엔진·입퇴장·재접속·10분 유지 시험 도구.
- 1:1 수신 피드백 기반 프레임 비교/복귀. 다인 통화는 현재 송신 길이를 유지한다.

|모드|현재 판단|

|기본 실행 / baseline|기존 기본값 유지|

## 최신 검증 결과와 미해결 항목

[097 네이티브 Opus·두 호스트 회귀](reports/EXTREME-097.md): 관리형 CELT 배열 할당을 계측하고 네이티브 Opus 우선·관리형 대체를 연결했다. 같은 빌드의6인90초 A/B/A에서 관리형 할당 약49~50%, GC 정지 합계 약49%, 프로세스 CPU 약19~22% 감소를 확인했다. 프레임·재생 여유는 유지했다. 관리형 전체 입퇴장/재접속+6인10분, 네이티브6인10분, 기본10ms 네이티브 TURN 제품 흐름3회가 양쪽 모두 완료됐다. PLC는 모든 방향에서 줄지 않아 연속성·물리 지연 합격으로 일반화하지 않는다. 잘못된 패킷의 네이티브 음수 반환 처리와 R2R SDK 해시 검증도 보완했다. [백엔드 식별·배포](NATIVE-OPUS.md).

일반 빌드/실행/publish의 수정 SDK 자동 연결을 추가했다. 원본 NuGet DLL 대신 고정 소스를 빌드하며 수신 시작 보호·UDP TURN 종료 삭제가 환경 변수 없이 적용된다. 현재 실제 로딩 식별자는 `10.0.17+myeongdong.2 / udp1-turn1-rtp0`이며, 초기 SRTP 인증 상태 수정은 [098](reports/EXTREME-098.md)에 기록했다. [SDK 빌드·검증](SDK-BUILD.md), [096 기본 연결 검증](reports/EXTREME-096.md). 아래094/095의 별도 빌드 지위는 당시 기록이며 이후 기본 연결로 바뀌었다. 기존 dist는 별도로 다시 빌드해야 한다.

[095 TURN 재연결 수정](reports/EXTREME-095.md): 실패한 재연결에서 Allocate437을 확보했다. OS 자동 UDP 포트가 닫힌 포트를 재선택해 남은 TURN 할당과 충돌하는 것을 통제 재현했다. **일반 앱 소스**는 최근 포트 보존과 명시적 난수 포트 선택으로 재사용을 피한다. 별도 SDK 후보는 정상 UDP 종료 시 인증된 Refresh(0)를 추가했다. 결합 후보는 두 PC의 제품 흐름3회 연속, 송수신/디코딩48개 구간, 실제6인90초, 정상/수정 SDK 로컬 통합 검사를 통과했다. 당시 기본 NuGet·기존 dist는 유지했으며 외부 사용자·장기 신뢰도·입→귀 지연 합격을 선언하지 않는다.

[094 SDK 수신 시작 보호](reports/EXTREME-094.md): 정확한 상류 소스의 수신 상태 확인·설정을 짧은 잠금으로 보호한 별도 시험 빌드를 추가했다. 실제6인 A/B/A에서 원본은 중첩·정체성 중복/미관측을 재현했고 수정 구간의30개 수신기는 모두 중첩0이었다. 노트북 내부 방향 미관측은447→0→620개, PLC 비율은2.283%→0.153%→4.975%였다. 이는 관측 구간의 합산 값이며 입→귀 지연이나 장기 발생률이 아니다. 호스트 간 미관측·PLC는 남았고, 제품 재연결 시험은 원본과 수정 모두 실패 사례가 있어 **기본 배포본 승격은 보류**한다. [시험 빌드 준비·실행](../sdk-experiment/README.md)은 원본/수정 대조용으로 남겨 두었다. 현재 정상 실행은096의 수정 SDK를 사용한다.

[093 수신 경계·SDK 경쟁 보고서](reports/EXTREME-093.md): 실제6인90초 시험에서 노트북 내부 일부 방향의 SDK 채널 이벤트에서도 중복·미관측을 확인했다. 이어 오디오·RTP 없는 순수 UDP 원본/수신 시작 직렬화/원본 대조에서 SDK 동시 수신 시작 문제를 양쪽 호스트에서 재현했다. 직렬화 구간은 중복·미관측0이었다. **시험 전용 수정이며 실제 통화의 동일 원인 확정이나 제품 해결 완료는 아니다.** 최신 Release 빌드는 경고/오류0이다. 통합 검사의 IPv6 RTCP는 최초 시간 초과 후 해당 검사 재실행이 통과했다.

[092 두 호스트 그룹 보고서](reports/EXTREME-092.md): 실제 공유 오디오를 사용하는 엔진을 PC/노트북에 각각3개 실행했다.3명/6명 성립, 입퇴장·재참가·명시적 Leave/Join 재접속·전체 종료/재입장을 확인했다. OS 자동 경로의6명 장시간 시험은 약93초에 연결이 끊겨 **실패**했다. 앱에 LAN 인터페이스를 명시한 조건에서는3명/6명 대조와6명10분 연결·디코딩·종료 정리 검사가 양쪽 모두 완료됐다. 새 세션/순서도 달라 경로의 단일 원인을 확정하지 않는다.

**통화 연속성 합격은 아니다.** PLC·부족이 남았고, 특히 노트북 같은 호스트 방향에서도 송신 API 기록과 복호화된 RTP 콜백 사이의 미관측 프레임이 확인됐다. 재생 버퍼 이전의 SDK/전송·검증·로컬 OS 경계가 미분리다. 이 문제를 집 무선망이나 물리 손실만으로 설명하지 않는다.6대 독립PC·다른 사용자 회선·게임 부하·물리 입→귀 지연 시험을 대신하지 않는다.

최종 원본 소스 Release 빌드 경고/오류0, 관리형 회귀·서버8개·로컬 IPv4/IPv6 WebRTC/SRTP/RTCP 통합을 통과했다. 그룹 시험의 기능 완료와 품질/지연 합격을 구분한다. 메모리에는 보존 중인 진단 자료가 포함돼 전후 값만으로 누수를 판정하지 않는다.

## 다음 우선순위

2026-10-27 사용자 지시로 우선순위를 변경했다. 현재 장비로 더 나누기 어려운 집 네트워크 물리 원인 조사는 미해결 항목으로 보존하고, 노트북 없이 가능한 앱 구현·내부 검증을 진행한다. 실제 지연 우선·게임과 WASAPI 공유 출력·직접 우선/TURN 대체 원칙은 유지한다.

1. 107의 단일 PC 내부 검증은 완료했다. 공통 출력은 독립 두 PC·외부/TURN·실제 게임 부하와 PLC/마감 회귀를 후속 검증하기 전까지 선택 후보로 유지한다. 기존 출력이 기본값이며 전체 안정화나 물리 지연 우위를 선언하지 않는다.
2. 남은 통화/장치 오류 처리와 사용성·빌드/소스 배포 절차를 정리한다. 기존 미커밋 변경·사용자 진단·배포본은 보존하고 요청 없는 커밋·푸시는 하지 않는다.
3. 네트워크 조사는 독립 AP/NIC 관측·신뢰할 수 있는 AP 전달 통계·별도 무선 캡처 등 새 증거가 확보됐을 때 재개한다.106의 PC 경로 대조와072/075/076의 기존 검사를 무작정 반복하지 않는다. 앱 수정만으로 NIC 하위/무선/AP 문제를 해결했다고 표시하지 않는다.

노트북이 없는 동안 동일 PC의 여러 엔진과 합성 검사를 사용하며 독립된 여러 기기의 검사로 표현하지 않는다. RDP 세션은 오디오 장치를 바꿀 수 있으므로 실제 선택 장치를 확인하고, 입력 없는 세션의 합성 입력 검증과 물리 장치 검증을 구분한다. 기본 OS/VPN 경로·공유기·개인 장치 설정은 임의 변경하지 않는다.
