# 구조적 지연 개선 실행 계획

2026-11-03 / `codex/extreme-latency` / 기준 커밋 `460e8ab`.

이 문서는 Gemini 제안 검토 후 수립한 **새 실행 순서**다. 기존 [평상시 개선 계획과145~151 결과](STEADY-LATENCY-PLAN.md)는 이력으로 보존한다. [지연·원인·시험 종합](reports/LATENCY-CAUSES-AND-TESTS-2026-11-03.md)의 기존 결과를 지우거나 기각 후보를 성공으로 바꾸지 않는다. 아래 작업은 계획이며 새 구현/검증 완료가 아니다.

## 1. 목표와 변경 범위

우선순위는 실제 평상시 입→귀 지연, 게임 중 연속성, CPU/GC/스케줄링, 음질, 부가 기능 순이다. WASAPI 공유 모드와 게임 소리 공존, WebRTC 직접/TURN, 인증 후 상태 반영과 기존 SDK 수명 수정을 유지한다. 독점 모드/ASIO·개인 장치/드라이버/전원·라우팅/VPN/AP 설정 변경은 해결책으로 전제하지 않는다.

출발점은 기본10ms/native Opus LowDelay64/수신20ms/스레드풀 송신/상대별 공유 출력이다. 기각한 전용 송신·단일GCM 키 재사용·지속 PI·정착 예산을 재도입하는 계획이 아니다. 더 줄일 수 있는 지연이0이라고 단정하지도 않는다. 목표 감소량과 무손실·PLC0·완벽한 위상 고정을 사전에 보장하지 않는다.

처음에는 기존 프레임·여유·큐·출력 구조를 고정하고 후보 하나씩 평가한다. 공통 출력,5ms 프레임, 낮은 수신 목표를 한 번에 켜지 않는다. UI·베타 기본값은 후보 검증 후 판단한다.

## 2. 순서와 단계별 출구

| 순서 | 작업 | 기대를 검증할 대상 | 다음 단계/중단 조건 |
|---|---|---|---|
| P0 | 초기 적체의 실제 생성 경위와 시험 입력 정리 | 실제 재고와 필터값, 첫 읽기/출력 시작/2초 전환을 구분 | 기존 기록으로 판단 가능하면 새 계측 생략. 불명확하면 필요한 시작 경계만 제한 기록 |
| P1 | 출력 선행 준비를 한 변수로 비교 | 초기 적체/첫 음성/초기 고지연 지속시간 감소 | P0에서 출력 시작 관련 추가 재고가 확인될 때 구현. 재현 안 되면 보류/종료 |
| P2 | 무음 구간의 제한적 PCM 시간 조정 | 무음 뒤 다음 발화의 정상 대기 감소 | 원본 발화 훼손·안전 여유 소진·반복 진동이 있으면 기각 |
| P3 | hold 후 도착한 원본의 부분 재생/병합 비교 | 사건 후 지연 잔류와 PLC/원본 생략의 교환 관계 | RTP/디코더/재생 샘플 시간축 검증부터 통과. 단순 무손실 복원으로 취급하지 않음 |
| P4 | 장치별5ms 송신과 묶음 인식 정합 | 동일 원본 내용의 송신/수신 전체 대기 | 실제 생성 묶음·큐 예산·수신 제어를 맞춘 새 가설이 있을 때만 착수 |
| P5 | 낮은 수신 여유의 재검증 | 새 구조의 이득 위에서 안전하게 더 줄일 수 있는 범위 | 앞 단계의 유효한 새 근거가 있을 때만. 중복 전송과 묶어10~12ms 성공을 전제하지 않음 |

P1~P4는 서로 독립적인 후보다. 앞 후보가 실패했다고 효과 없는 제어기를 다음 후보의 전제로 남기지 않는다. P0의 입력/경계/판정 기준은 공통으로 재사용한다. 현재의 PC 수신20→15→20ms 단독 비교는 P5의 보조 대조로 내리고 첫 작업으로 반복하지 않는다.

## 3. P0 — 가장 먼저 할 일

### 초기 큐 생성 경위

[146](reports/EXTREME-146.md)·[147](reports/EXTREME-147.md) 원본을 먼저 재사용한다. 약52~56ms는 관측된 시작 **필터 큐**이며, 그 전부가 출력 시작 지연 탓이라고 확정하지 않는다.27.111초는 특정 후보의 활성화 시점이지 모든 통화에서 그 시간 내내 같은 큐가 유지된다는 뜻이 아니다.

다음을 같은 호스트의 경계로 연결한다.

1. 피어 생성·장치 열기/초기화·connected·렌더 스레드 시작·실제 장치 Start.
2. 첫 인증된 RTP 입장·첫 정상 Read·첫 실제 PCM 공급·실제 출력 패딩.
3. 원시 패킷/남은 PCM 재고·필터 큐·목표·누적 도착/소비량.
4. 2초 정착 전후와 첫 유효 음성 시점. 미디어가 정착 전/후에 들어오는 조건을 분리한다.

기존 코드가 연결 전에 이미 준비하는 부분과 연결 후 시작하는 부분을 구분한다. 기존 기록이 부족할 때만 시작 구간의 bounded 메타데이터를 추가하며 기본 실행에 고빈도 로그를 넣지 않는다. 소프트웨어 경계와 장치 시계를 물리 음향 시각으로 바꾸지 않는다.

### 대화형 시험 입력

현재 `SpeechFixture`는 WAV 반복 공급기이므로 모든 입력이 연속 발화라고 가정하지 않는다. 사용한 WAV의 구간을 먼저 확인하고 필요하면 기존 공급기에 결정적 대화형 입력과 정답 메타데이터를 추가한다. 기존 도구를 복제하는 것부터 시작하지 않는다.

- 연속 신호, 발화/무음 교대, 문장 첫 약한 소리, 작은 목소리/자음, 배경 잡음/음악, 긴 침묵과 재발화.
- 각 구간의 원본 샘플 범위·발화/무음 정답·동일 내용 마커를 명시한다.
- 128/256/480샘플 읽기, 도착/렌더 위상, 실제 캡처 묶음,±200/500ppm, 지터/지연 묶음·손실·재정렬·중복·RTP 랩·SSRC 초기화를 결정적으로 재현한다.
- 지연이 줄었는지와 실제로 건너뛴 원본 구간을 별도로 판정한다. 합성 PCM 교체는 실제 마이크 음향이나 청감 검증을 대신하지 않는다.

산출물은 초기 재고 경계표, 가설별 관측/반증, 재사용 가능한 입력/정답, 같은 내용 마커의 비교다. 큰 시작 큐의 직접 원인이 관측되지 않으면 이를 확정 원인으로 보고 P1을 강행하지 않는다.

## 4. P1 — 출력 선행 준비

기존 상대별 출력 구조에서 한 피어의 준비 시점만 먼저 비교한다. 단일 믹서로 바꾸는 작업을 섞지 않는다. 장치 열기·렌더 시작·무음 공급·정착이 서로 다른 단계라는 점을 반영한다.

- 연결 준비와 출력 준비를 겹칠 수 있는지 검사한다. 연결이2초보다 빨라도 사용자 음성을 억지로2초 더 기다리게 하지 않는다.
- 원래 음성을 모두 유지하는 후보와 초기 적체를 의도적으로 정리하는 후보는 별개다. 선행 준비와 원본 폐기를 동시에 켜지 않는다.
- 첫 유효 음성 도착→첫 실제 공급, 첫30초의 재고/대기 변화,60초 이후 정상 구간을 따로 본다.
- 상대가 오지 않는 방·음소거·입퇴장·장치 변경·취소에서 불필요한 장치 점유/CPU·스트림 누수가 없는지 확인한다.
- 디코더 더미 예열은 냉간 호출 비용이 실제로 클 때만 별도 비교한다. 예열 뒤 상태 초기화·음원 없는 상태의 안전 동작을 검증한다.

선행 준비가 첫 음성이나 정상 대기를 반복해서 줄이지 못하면 종료한다. 첫 시작만 개선되면 ‘시작 경험 개선’으로 기록하고 평상시 입→귀 개선으로 이름을 바꾸지 않는다. 원본을 버리는 후보는 폐기량/첫 음절 보존을 별도로 통과해야 한다.

## 5. P2 — 무음 구간의 제한적 PCM 조정

첫 실제 재생 제어 후보는 일정 dBFS 이하라는 이유만으로 큐를 자르지 않는다. 무음 판정 신뢰도·지속 구간·안전 여유를 확인하고, 확신할 수 없으면 기존 재생을 유지하는 보수적 동작으로 시작한다.

- 이미 디코딩된 후보 구간의 내용이 확인됐을 때만 조정한다. 과거150ms가 조용했다는 사실로 앞으로 큐에 있는 음성이 무음이라고 단정하지 않는다.
- 판정을 위해 새150~200ms 대기나 큰 PCM 큐를 만들지 않는다. 기존 과거 이력과 현재 확인 가능한 작은 PCM 구간만 사용한다.
- 압축 Opus 패킷을 임의 폐기해 디코더 상태를 건너뛰지 않는다. 디코딩 진행·RTP 위치·소비 위치·시계 보정 상태의 일관성을 유지한다.
- 생략한 PCM 샘플 수/시간, 무음 판정 근거, 전후 재고, 다음 발화 마커의 공급 시각을 남긴다. 무음 생략도 ‘샘플 손실0’이라고 부르지 않는다.
- 첫 후보는 한 번의 작은 조정만 허용한다. 상한·재시도 유예·실패 시 취소를 두고, 기존 수신 안전 여유와 다음 장치 읽기에 필요한 재고를 침범하지 않는다.
- 발화 중/연속 입력에서는 조정하지 않는지 확인한다. 낮은 에너지의 발화·전환 경계가 잘리거나 보정과 역보정이 반복되면 기각한다.

측정은 무음 뒤 다음 발화의 정상 대기, 내용 마커 보존, 경계 불연속, PLC/늦음/소진/생략량이다. 장치가 깨어나는 시각을 강제로 바꿨거나 앞으로의 도착 위상을 고정했다고 주장하지 않는다. 침묵이 없는 장시간 발화에도 이득이 있는 것으로 일반화하지 않는다.

## 6. P3 — hold 복구의 지연/음성 보존 대조

현재 일반 LowLatency 경로의 hold를 재현한 뒤 비교한다. 극저지연 프리셋에서는 다른 hold/제어 분기가 적용되므로 혼동하지 않는다. 과거 누적 `HeldMs`를 현재 잔류 지연으로 사용하지 않는다.

- 해당 RTP 위치별로 PLC를 생성한 양, 실제 공급한 양, 아직 남은 PLC를 구분한다.128샘플 요청을2.5ms 단위로 올림하면240샘플 PLC가 만들어질 수 있어 ‘항상120샘플’로 가정하지 않는다.
- Opus PLC가 이미 진행시킨 디코더 상태, 실제 패킷 디코딩, 남은 PCM, 선형 보간 이력, 예상 RTP 위치와 실제 공급 위치를 함께 검증한다.
- 기준선은 지연 도착한 원본을 보존하는 기존 동작이다. 후보는 일부 원본을 의도적으로 생략해 시간축을 따라잡는 별도 선택이다. 생략량과 PLC·경계 병합을 모두 계측한다.
- 짧게 늦은 패킷, 다음 패킷이 먼저 도착한 경우, 진짜 손실, 반복 hold, 가변 길이, 랩·소스 변경·재버퍼·장치 재시작을 확인한다.
- 이미 재생한 소리를 나중에 복구한 것으로 표시하지 않는다. 원본의 나머지 구간을 실제로 공급했는지와 이후 디코더 진행을 검사한다.

사건 후 큐/마커 지연이 빨리 회복돼도 원본 생략이나 청감 악화를 숨기지 않는다. 발화 훼손이 커지거나 기존 안전 동작을 깨면 종료한다. 평상시 지연과 사건 후 복구 지연을 따로 보고한다. 이것만으로15ms 수신 여유가 안전해졌다고 선언하지 않는다.

## 7. P4 — 조건부5ms와 묶음 정합

P0에서 실제 캡처 묶음과 동일 원본 내용의 조립 대기가 확인되면, 송신과 수신의 정합을 설계한 뒤 비교한다.134의 프레임 길이 단독 축소를 반복하지 않는다.

- 256샘플 콜백/240샘플 프레임은15콜백에16프레임이다. 간헐적2프레임 묶음까지 포함하고, 장치 주기 `<8ms`라는 조건 하나로 균등 송신을 보장하지 않는다.
- 먼저 한 방향만5ms로 바꾸는 비대칭 비교를 한다. 노트북 송신의 효과는 노트북→PC 방향에서 검증한다.
- 수신 묶음 인식/시계 제어와 프레임 길이는2×2 비교로 효과를 분리한다. 이전 실패 제어기를 전제로 남기지 않는다.
- 송신 큐는 프레임 개수만 같다고 같은 정책이 아니다. 기존30ms 분량 용량을 비교 기준으로 한다면10ms3개/5ms6개를 명시하고 나이/폐기 정책은 고정한다. 정상 묶음의 형제 프레임을 버리지 않는지 확인한다.
- 동일 원본 샘플/내용 마커로 비교한다. 프레임을 나눠 첫 샘플 기준점이 바뀐 것을 모든 음성의5ms 단축으로 해석하지 않는다.
- RTP 타임스탬프 연속성·디코딩/PLC 길이·통계 단위, 패킷 빈도·SRTP/할당/CPU, 입퇴장/다인 호환을 검증한다. 페이싱을 넣는다면 추가 송신 대기 자체를 별도 변수로 본다.

전체 정상 대기가 줄고 연속성이 유지된 방향/조건에서만 채택을 검토한다. 송신 조립 감소가 수신 대기 증가로 상쇄되면 종료한다. 기본10ms와 호환 경로는 유지한다.

## 8. P5·후순위

새 구조의 유효성이 먼저 확인된 경우에만 낮은 수신 여유를 비교한다. 첫 후보는 PC 수신만20→15→20ms이며 노트북20ms를 유지한다. 이전 기각한10~14ms 하한을 그대로 다시 시험하지 않는다. 새 복구 방식의 위험과 수신 여유 축소의 위험을 분리한다.

중복 전송/RED는 후순위 독립 후보다. 다음 패킷에 담은 복사본은 다음 프레임 생성 이후 도착하며, 함께 늦어지는 지연 묶음을 해결하지 못한다. 협상/포맷·인증·타임스탬프·중복 제거·추가 트래픽의 비용을 검증해야 한다. 이를 근거로10~12ms나12~15ms 단축을 미리 약속하지 않는다.

단일 공유 출력의 기본값 승격과 암호화 할당 감소도 별도 과제다. 출력 준비 시점·무음 조정과 동시에 바꾸지 않는다. 실제 다인 부담에 근거가 생길 때 재평가하며 평상시 입→귀 단축이 보장된 항목으로 취급하지 않는다.

## 9. 공통 검증과 작업 제한

각 후보는 **사실/정답 확인 → 결정적 재현 → 짧은 실제 비교 → 저계측 유지 → 적용 범위 확대** 순서다.

- 최초 기준은 실제1:1·한PC당 엔진1개다. 한PC6엔진/30출력은 집중 부하 회귀로 따로 분류한다.
- 정상 입력·±시계 편차·재정렬/손실/긴 도착 묶음·음성 경계에서 먼저 시간축/내용/큐 상한을 확인한다. 여기서 실패하면 실장치 장시간 시험으로 넘기지 않는다.
- 실제 비교는 같은 장치/경로/내용의 A/B/A로 시작한다. 초기 사건은 여러 번 새 통화로 반복하고, 회차 편차가 효과와 비슷하면 역순 대조 한 묶음으로 확인한다. 계속 뒤집히면 미입증으로 종료한다.
- 초기 첫 음성, 통화 정착 후 발화, 침묵 뒤 재발화, 지연 사건 뒤 복구를 별도로 보고한다. 불리한 방향/회차를 빼지 않는다.
- 엔지니어링 선별 목표는 원래 내용의 전달에서 재현되는 **ms 단위** 개선이다. 수십 μs 계산 이득을 위해 구조를 복잡하게 만들지 않는다. 구체적 통과 폭은 후보 착수 전에 A/A 변동과 측정 해상도로 정한다.
- PLC/hold/advance·늦음/재버퍼·출력 소진·캡처 불연속·원본 생략·무음 생략·실제 공급 마커를 함께 본다. 정상 기준선의 무사건 조건을 깨면 중단한다. 기준선에도 사건이 있으면 감소를 증명하기 전 안정화로 부르지 않는다.
- 고빈도 기록은 필요한 짧은 구간만, 기본값은 끔. 장치 observer가 없는 대조도 수행한다. 기록의 최대 경과를 순수 CPU 비용으로 취급하지 않는다.
- 짧은 비교를 통과한 후보만 저계측 각180초, 이후 같은 길이의 기준선/후보30분 이상과 준비 가능한 실제 게임·TURN·재참가/장치 변경·다인으로 확대한다. CPU 합성 부하와 실제 게임은 별도다.
- 실제 음향이 준비되지 않으면 물리 입→귀는 미실시로 남긴다. 서로 다른PC 시각을 빼거나19.2/30/58.2ms의 서로 다른 시험 합을 전체 지연으로 사용하지 않는다.

한 후보는 채택/기각/자료 부족 중 하나로 끝낸다. 같은 실패를 반복하거나 효과가 없는 실험 스위치를 제품에 남기지 않는다. 자료/권한/장치가 부족하면 가능한 모형/회귀를 끝내고 해당 실기만 미실시로 남긴다. 원인 규명을 기다린다는 이유로 환경 검사만 무한 반복하지 않는다.

## 10. 산출물·복구

후보마다 변경 한 변수, 적용 전후 해시/설정, 가설/반증, 결과/표본 수, 내용/시간축 회귀, 채택 범위·기각 이유, 미실시와 복구 결과를 남긴다. 기존 도구를 재사용하고 필요한 모형/입력만 추가한다. 개인정보/음성/패킷 원문/비밀값은 Git 제외 경로에 보존한다.

고정된 검사 실행 경로와 [앱 한정 방화벽 준비](TEST-FIREWALL.md)를 사용한다. 노트북에는 교체 전 실제 bin/Runner를 새로 백업하고 해시 복구한다. 기존 베타/dist/운영 서버는 유지하고 원래 기준선으로 즉시 돌아갈 수 있게 한다. 커밋/푸시·릴리즈는 별도 요청 범위에서 수행한다.

이 계획 수립 시점에는 구현·새 실기·기본값 변경·커밋/푸시를 수행하지 않았다. 다음 실제 작업은 **P0의 기존 초기 기록 검토와 대화형 입력/정답 구성**이다.
