# 평상시 지연 감소 실행 계획

2026-11-03 · `codex/extreme-latency` · 비교 기반 `e8a140b` / EXTREME-144

## 목표와 원칙

최우선은 평상시 실제 입→귀 지연 감소다. 게임 중 연속성, CPU·GC·스케줄링 부담, 음질 순으로 함께 평가한다. WASAPI 공유 모드·WebRTC 직접 연결 우선/TURN 대체·기존 보안과 SDK 수정을 유지한다.

현재 물리 입→귀 전체 지연과 구조적 하한은 미확정이다. ‘기본 사양이80%를 차지한다’, ‘최소50~75ms’, ‘후보로5~10ms가 줄어든다’는 전제를 사용하지 않는다. 각 후보의 실제 감소량은 비교 시험 후 기록한다.

현재 기본 구성은10ms 프레임/native Opus LowDelay64/고정 수신 여유20ms다. bounded 공유 출력의 추가 여유는 실제 출력 주기5ms 이상에서3ms, 그 미만에서5ms이며 장치 용량을 넘지 않는다. 초기 전체 패딩·정착·소진 시 안전 복귀는 보존한다. 기존144의 결과는 [진행 정리](PROGRESS-2026-11-03.md)를 참고한다.

## 1단계 — 기존 자료 정리와 짧은 가설 검증

목적은 새로운 실시간 변경 전에 중복 계산과 잘못된 인과 가정을 제거하는 것이다. 기존140~144 원본/도구를 먼저 사용하고, 부족한 경계만 제한적으로 추가한다.

- 캡처 전달, 프레임 조립, 인코딩/송신, 수신 대기, PCM 공급, 장치 시계를 구분한다. 겹치는 기간을 합산하지 않는다.
- 워밍업 전후 수신 큐·출력 패딩·누적 소스 소비량을 대응해 패딩 축소분의 상위 큐 전이 여부를 확인한다. 초기 미디어가 워밍업 전/후에 도착하는 경우를 분리한다.
- 첫 읽기의 패킷 양자화와 평상시 필터링된 큐 평균을 구분한다. 첫 읽기의 과잉량을 그대로 평상시 지연으로 표현하지 않는다.
- 128/256/480샘플 읽기, 도착·렌더 위상, 시계 편차의 결정적 재현을 우선 사용한다. 기존 기록으로 전환 순간이 보이지 않으면 그 전후만 상한 있는 메타데이터로 관측한다.

완료 조건: 경계표와 가설별 관측/반증 조건을 작성한다. 반복 가능한 추가 대기가 관측되면 단일 후보로 분리한다. 관측되지 않으면 미확정으로 남기고2단계로 이동한다. 원인 확인 없이 deadband를 줄이거나 음성을 버리는 수정은 하지 않는다.

## 2단계 — 같은 주기의 캡처 경로 비교: 첫 구현 우선순위

가설: 장치 주기를 줄이지 않아도 호환 레코더와 자체 캡처 루프의 전달·리스 보유 방식 차이에서 제거 가능한 대기가 있을 수 있다.

1. 같은 장치·포맷·실제10ms 주기에서 기존 호환 캡처와 자체 공유 캡처를 비교한다. 프레임10ms·수신20ms·출력·코덱은 고정한다. 이 비교는 경로 전체 대조이며 효과를 MMCSS나 리스 한 요소의 효과로 단정하지 않는다.
2. 자체 캡처 경로를 고정한 뒤 staging 끔/켬/끔을 별도로 비교한다. 현재 staging 설정이10ms 자체 경로 허용까지 바꾸는 결합을 검사 전용 구성에서 분리한다.
3. 렌더 staging은 캡처 결과와 섞지 않고 필요할 때 별도 비교한다. 기존 전체 실험 프리셋을 켜서 여러 정책을 함께 바꾸지 않는다.

측정: 장치 보고 첫 샘플→콜백, 콜백→프레임 완성, 인코딩/송신 대기, 리스 보유, 캡처 불연속/부분 폐기, 대응한 수신 구간과 연속성. 콜백이 빨라진 것만으로 입→귀 개선을 선언하지 않는다.

채택 조건: 변경 대상 방향의 실제 대기 감소가 반복되고 반대 방향이 악화되지 않으며 연속성 기준을 통과할 것. 효과가 없으면 후보를 제거하고 기존 경로를 유지한다. 성공 시 장치 능력에 따른 선택과 기존 호환 fallback을 유지한다.

## 3단계 — 장치·도착 묶음을 고려하는 수신 목표 설계

가설: 고정 여유 또는 현재 적응 제어가 장치 읽기·패킷 도착 묶음·시계 편차를 충분히 구분하지 못해 불필요한 정상 대기를 남길 수 있다.

- 현재 제어기를 기준선으로 유지하고 먼저 shadow 계산으로 후보 목표와 예상 마감 위험만 기록한다. 이 단계는 재생을 바꾸지 않는다.
- 직접/TURN 명칭이나 최근 지터 수치 하나만으로 목표를 낮추지 않는다. 도착 상대 지연의 분포와 묶음, 실제 읽기 단위, 늦은 도착/PLC, 관측량·경과 시간과 시계 편차를 함께 본다.
- 검증된 허용 범위 안에서 감소·실패 시 증가·감소 유예를 설계한다. 목표 변경과 목표까지 소비율을 수렴시키는 방법은 분리해서 검증한다.
- 12/15ms 등의 값을 성공으로 미리 정하지 않는다. 수신 여유와 출력 여유가 같은 실패에 중복 반응하지 않게 한다.
- 기존 기록 재현·위상/묶음/손실/시계 편차에서 후보를 선별한 뒤 실제 A/B/A로 진행한다. 재현 합격은 실제 장치 합격과 구분한다.

시작 큐/워밍업 개선은1단계에서 근거가 확인된 경우에만 별도 변수로 시험한다. 유효 음성을 읽고 버린다면 폐기 시간·내용 변형을 별도로 집계하며 PLC0을 무손실로 표현하지 않는다. 미디어 시작을 늦추는 방식은 첫 음성 전달 지연도 평가한다.

## 4단계 — 5ms 프레임과 수신 제어의 정합 재설계

목적은134에서 기각한 프레임 축소를 반복하는 것이 아니라, 앞 단계에서 검증한 제어와 장치 주기에서 더 짧은 패킷이 실제 이득을 내는지 확인하는 것이다.

1. 프레임 길이와 수신 제어의2×2 비교를 구성한다:10ms/5ms × 기존/후보 제어. 출력·코덱·장치 주기는 고정한다. 앞 단계 후보가 기각됐으면 이 단계 착수 근거를 다시 판단한다.
2. 송신 조립 대기 감소가 수신 대기 증가로 상쇄되는지 같은 내용/샘플 기준으로 확인한다. 프레임 첫 샘플 기준만 작아지는 측정 착시를 배제한다.
3. 실제 Opus 가변 길이, RTP 샘플 시간축·랩·전환/재참가 호환, 패킷 빈도·SRTP 비용·CPU/할당을 검증한다.
4. 먼저1:1 직접 연결에서 비교하고, 직접/중계·다인으로 확대한다. 검증 전 전역 기본값이나 통화 중 자동 프레임 전환으로 승격하지 않는다.

완료 조건: 프레임 감소와 제어 변화의 효과를 분리해 보고하고, 이득이 입증된 장치/경로 범위에서만 선택한다. 연속성이나 비용이 악화되면10ms를 유지한다.

## 공통 시험 및 채택 기준

| 단계 | 시험 | 판정 범위 |
|---|---|---|
| 사전 검사 | 실제 코덱/RTP·PCM 시간축·순서/손실·정지/종료·위상/시계 편차 | 알고리즘·회귀만 평가 |
| 상세 비교 | 두 PC A/B/A 각45초, 같은 장치/경로/부하, 필요한 경계만 관측 | 대기 감소와 방향별 효과 |
| 저계측 비교 | 두 PC A/B/A 각180초, 고빈도 기록 끔 | PLC·출력/입력 실패·적용 설정 확인 |
| 승격 검증 | 후보 최소30분, 같은 시간의 기준선, 준비 가능한 실제 게임 부하 | 장기/부하 회귀, 수시간 전체 보장 아님 |
| 확장 검증 | 강제 TURN, 재참가/재연결/장치 변경,3/6엔진 | 해당 경로·생명주기·부하만 평가 |

- 계측을 켠 상세 시험과 일반 실행의 CPU/GC 수치를 동일하게 취급하지 않는다. 실제 장치 시계 검사는 기존 위상 정렬 도구를 재사용한다.
- 지연은 중앙값·P95와 표본 수/관측 범위를 보고한다. P99는 표본 수가 충분할 때만 평가하며14개 마커로 안정적인 꼬리 분포를 주장하지 않는다.
- PLC·늦은 폐기·재버퍼·출력 소진·안전 전환·송신/입력 부분 폐기를 함께 평가한다. PLC는 프레임 수 외에 오디오 시간·비율도 비교한다.
- 장치별 변경은 변경 대상 방향의 감소와 다른 방향의 비악화를 평가한다. 적용 범위·허용 변동·연속성 통과 기준은 결과를 보기 전에 정한다. 희귀 사건은 반복 대조 없이 인과를 단정하지 않는다.
- 물리 입→귀 검증이 준비되지 않으면 미실시로 표시한다. RTT/2, 큐 길이, 내부 기간 합, 장치 시계를 물리 입→귀로 바꾸지 않는다.
- 두 PC의 다중 엔진 시험은 독립된3명/6명의 장치·회선 검증이 아니다. 외부 친구·독립 PC·게임이 준비되지 않으면 가능한 내부 시험을 진행하되 해당 합격을 대신 선언하지 않는다.

효과가 확인된 후보만 최종 `./native/verify.ps1 -NoRestore -Integration` 및 Python 분석 회귀를 수행하고 개발 기본값 승격 여부를 판단한다. 같은 후보가 근거 없이 실패를 반복하면 비교용 원본/보고서만 남기고 제품 코드는 원복한다.

## 보조 과제와 변경 범위

입력 불연속 시 부분 PCM 보존, 간헐적 네트워크/렌더 스파이크, 다인 공통 출력의 기본값 승격은 평상시 지연 개선에 직접 필요한 경우 외에는 뒤로 둔다. 부분 PCM 보존은 짧은 콜백 간격만으로 결정하지 않고 실제 샘플 신선도·시간축·누락/중복을 검증해야 한다.

48kHz 출력은 선택적 비교/가이드 후보이며 사용자 환경의 필수 조건으로 삼지 않는다. 장치 설정·드라이버·공유기·시스템 라우팅·VPN을 임의 변경하지 않는다. 독점 모드·ASIO·새 하드웨어 구입을 해결책으로 전제하지 않는다.

각 실험은 가설, 변경 함수/한 변수, 예상 관측과 반증, 비교 조건/해시, 결과·한계, 채택/기각, 실제 복구 결과를 MD에 남긴다. 노트북 시험 파일은 백업·해시 복구하고 기존 dist/공개 베타와 운영 서버는 유지한다. 진단 원본·개인 네트워크 정보·비밀값은 Git 제외 경로에 보존한다. 커밋·푸시·릴리즈는 별도 요청 범위에서 수행한다.
