# 명동 콜링 0.6.0 사용법

Windows 10 2004 이상에서 사용합니다. 현재 배포는 폴더형이며 .NET 10 Desktop Runtime이 필요합니다. ZIP을 풀고 폴더 안의 `VoiceNative.exe`를 실행하세요. DLL·runtimes 폴더도 함께 있어야 합니다.

## 통화 시작

1. 기본 서버 주소를 유지하거나 운영 중인 서버 주소를 입력합니다.
2. 닉네임을 입력합니다. `새 방 만들기`를 누르면 임의의 방 이름으로 참가합니다.
3. `방 이름 복사`로 이름을 전달합니다. 상대는 같은 서버·같은 방 이름을 입력하고 `방 참가`를 누릅니다. 지정한 이름의 방은 첫 참가 시 자동으로 만들어집니다.
4. 참가자 상태가 연결되면 통화합니다. 직접 연결이 어려우면 설정된 TURN으로 자동 우회합니다. 공유기 포트포워딩은 필요하지 않습니다.
5. `나가기`를 누르면 마이크와 통화 연결을 해제하고 자동 재접속도 중지합니다.

방 이름은 문자·숫자·밑줄·하이픈 1~40자, 닉네임은 1~24자입니다. 최대 6명 메시 구조이며 실제 그룹 환경의 품질은 장치·망·인원에 따라 달라집니다. 방 이름은 초대 코드 역할이며 로그인·방 비밀번호·참가 승인 기능은 없습니다.

## 통화 조작

- `마이크 음소거`는 인코딩 직전 PCM을 무음으로 바꿉니다. 해제하면 입력을 다시 보냅니다. 소켓·장치의 짧은 처리 중 버퍼까지 즉시 소거하는 기능은 아닙니다.
- 참가자마다 볼륨 0~200%와 `상대 음소거`를 사용할 수 있습니다. 100% 초과는 큰 음성에서 포화될 수 있습니다. 음소거 중에도 재생 타임라인을 소비하므로 해제할 때 이전 음성이 쌓여 나오지 않습니다.
- 마이크·출력 목록에서 장치를 고릅니다. `Windows 기본 장치`는 시스템 기본 멀티미디어 장치를 따릅니다. 통화 중 선택을 바꾸면 같은 방에 잠시 재접속합니다. 게임·다른 앱의 장치나 음량 설정은 바꾸지 않습니다.
- `장치 새로고침`으로 새 장치를 불러옵니다. 저장한 장치가 없으면 기본 장치가 선택됩니다. 선택한 고정 장치가 빠진 경우 다시 연결하거나 목록을 새로고침하고 사용할 장치를 선택하세요.

기본은 저지연 공유 모드이므로 게임 소리와 함께 재생할 수 있습니다. 독점 모드·ASIO·자체 에코 제거는 제공하지 않습니다. 스피커 사용 시 소리가 마이크로 다시 들어갈 수 있습니다.

## 연결·장치 복구

서버 연결이 종료되거나 ICE 실패가 지속되면 같은 방·닉네임으로 최대 5회 재접속합니다. 대기 간격은 1·2·4·8·15초이며 실제 연결 시도 시간은 별도입니다. 입력이 멈추거나 기본 장치가 바뀐 경우도 복구를 시도합니다. 상대가 정상적으로 나간 경우에는 방에서 기다립니다.

`나가기`·창 닫기는 대기 중 재시도를 취소합니다. 이미 진행 중인 연결 정리를 기다려 종료가 잠시 걸릴 수 있습니다. 재접속 실패 후에는 장치·서버 주소·네트워크를 확인하고 다시 참가하세요. Windows 앱 방화벽 허용은 필요할 수 있습니다.

최신 소스의 오류 안내는 다음처럼 구분합니다. 예전 배포 폴더에는 다시 빌드하기 전까지 반영되지 않습니다.

- **서버 연결 실패:** 서버 주소·네트워크를 확인하세요. 서버가 방 인원 제한 등으로 참가를 거절한 경우 거절 이유를 함께 확인하세요.
- **마이크 준비 실패:** 마이크 연결과 Windows 입력 장치·앱에서 선택한 장치를 확인하세요. RDP 연결/해제 때 사용할 수 있는 장치가 달라질 수 있습니다.
- **출력 장치 오류:** 장치를 확인하고 출력 재시작을 사용하세요. 통화 중 기존 출력 자동 복구는 한 번 시도합니다.
- **통화 정리 오류:** 나머지 자원도 정리를 시도한 뒤 실패를 알립니다. 자동 재연결은 중단하므로 진단을 저장하고 앱을 다시 시작하세요. 장치 선택 변경에 따른 자동 재참가도 정리가 성공했을 때만 이어집니다.
- **서버 퇴장 알림 미전달:** 로컬 통화 자원 정리를 먼저 진행하고 서버 알림은 짧은 제한 시간 안에서 시도합니다. 알림 실패만으로 통화를 다시 연결하지 않습니다.

정리 오류는 상세 진단의 `CleanupError`에도 남습니다. 사용자가 새 참가를 명시적으로 시작하면 이전 경고를 초기화합니다. 이미 진행 중인 장치/API 처리까지 강제 종료하는 기능은 아니므로 전체 종료 시간이 항상3초 이내라는 뜻은 아닙니다.

## 설정·진단

서버·방·닉네임·장치·마이크 음소거는 다음 실행에도 유지합니다. 코덱·시험용 재생 정책은 검증된 기본값으로 시작합니다. 상대별 볼륨은 통화 세션 안에서 유지합니다.

`상세 진단·고급 설정` 탭에서 연결 경로·RTT·손실·큐·출력 상태와 기존 측정 도구를 확인하고 JSON을 복사·저장할 수 있습니다. 기본 고정 20ms 정책을 유지하며 자동 저지연은 시험 선택입니다. 표시되는 수신→출력·RTT·API 지연을 실제 입→귀 지연으로 해석하지 마세요.

설정은 `%LOCALAPPDATA%/MyeongdongCalling/settings.json`, 이벤트 로그는 `logs/app.log`와 `app.log.previous`입니다. IP·닉네임이 포함될 수 있습니다. 음성·세션 토큰은 저장하지 않습니다. 문제가 있으면 JSON과 발생 시각을 함께 전달하세요.
